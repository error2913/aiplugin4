# 全局记忆、三层自动抽取/更新与命名规范方案

> ⚠️ **实现以 `05-最终实施方案.md` 为准**。本文的 bank/标签/可见性/命名仍可参考，但以下已被 05 裁决取代：
> - 可见性最终为 `public/origin/owner` 三值，**私聊归档默认 `owner`、群来源默认 `origin`**，`public` 才是显式跨群；旧文档“public 默认”作废。
> - `群聊→个人自动抽取`、`全局自动抽取` 默认改为 **关**（隐私/污染风险），由骰主显式开启。
> - 巩固后 MM 刷新默认 **关**；模板播种会额外触发一次 `seed` 生成（见 05 §7）。
> - 抽取 schema 最终复用 `prompt/templates.ts` 的既有字段（`memory_type/target_id/related_*`），仅扩 `memory_type=global`、加 `confidence`、删 `summary`；本文 §3.2 的 `owner/target_user_ids` 只作概念映射，不再作为第二套 schema（见 05 §5.2）。
> - 上下文解耦不新增端口，直接删除 archiver 的 3 处记忆调用（见 05 §11）。

> 配套文档：`00-记忆模块检查报告.md`、`01-认知层重写方案.md`、`02-实验验证结果.md`
> 已确认决策（按建议执行）：
> 1. 私聊 `private` 记忆**不允许**在该用户触发群聊时进入群 prompt；
> 2. `长期记忆条数上限` 默认值 100 → **300**；
> 3. `.ai memo clear` / `.ai memo obs clr` **强制 `--yes`**。

## 0. 直接回答

| 问题 | 结论 |
|---|---|
| 有没有全局记忆（主智能体自己的个人记忆）？ | **名义上有，功能上没有。** 代码里存在 `BankKind='global'`、`resolveGlobalBank()`、`global_<agent>` 命名与 `MemoryBankMeta.kind`，但：`resolveGlobalBank` **全仓 0 调用**；没有任何写入/注入/命令/工具入口；`SessionService.memory` 只是 `{}` 占位；主智能体人设实际来自配置「角色设定」，不是记忆。 |
| 个人/群聊记忆的自动抽取做好了吗？ | **部分做了。** 归档结算时 `MemoryManager.summarizeChunk` 用 `summarize_agent` 抽 facts，自动写入**当前会话所属 bank**（私聊→个人，群聊→群聊）。但：只处理 `add`（`delete` 被跳过，`update/noop` 当新增）；prompt 里声明的 `memory_type/target_id/related_user_ids/related_group_ids/visibility/related_memory_ids` **全部被忽略**；群聊里关于某个用户的稳定事实**不会**进入该用户的个人 bank。 |
| 自动更新做好了吗？ | **没有。** `MemoryUnit.state='invalidated'` 定义了但全仓**从未赋值**；`op=update/delete` 不生效；观察只有在归档 consolidate 时才更新；心智模型刷新只发生在命令/工具 consolidate 后，归档路径不刷新；`心智模型定时刷新间隔` 是死配置。 |
| 三层打通了吗？ | **没有。** 没有跨层路由（群↔个人↔全局）、没有晋升/降级、没有全局注入、没有跨 bank 去重与统一 revision。 |
| 命名规范吗？ | **部分规范。** 分层与文件名清晰（engine/repository/storage/consolidation/mental_models/reflection），但业务词汇存在多套同义词、默认值 bug、死命名和命令/工具/文档三套叫法。第 7 节给出规范与重命名表。 |

**一句话**：现在只有“私聊和群聊各自的 add-only 事实记账”，没有“三层记忆 + 自动更新 + 跨层打通 + 全局本体记忆”；本方案在 v3 认知层重写的基础上补齐。

## 1. 现状证据

### 1.1 自动抽取链路（存在，但只做了一半）

```
context_bridge / archiver（上下文结算）
  → MemoryManager.summarizeChunk(session, messages)          manager.ts:327-400
  → summarize_agent + SUMMARY_PROMPT_TEMPLATE                 templates.ts:116-228
  → parseLooseJson(reply).facts
  → engine.addMemory(bankForSession(session), {verbatim:!MEMORY_LLM_EXTRACT})
  → engine.consolidate(bank)                                  manager.ts:389-394
```

可运行事实：
- 触发：上下文结算水位/空闲/转冷，不是每条消息；`context_bridge.ts:175-187`、`archiver.ts:95/377/414`。
- 归属：`bankForSession(session)` 只按当前会话类型取 user/group bank（`manager.ts:22-25`）。
- 只写当前 bank：facts 的 `memory_type/target_id/related_*` 不读（`manager.ts:372-386`）。
- 只支持 add：`if (fact.op === 'delete') continue;`（`manager.ts:374`），`update` 未分支 → 当作新增写入。
- 可见性固定 `vis:public`：prompt 的 `visibility` 不读（`manager.ts:367-370`）。
- `op=delete` 被静默跳过；`noop` 也会被当新增。
- `summary` 字段不读（模板返回了但丢弃）。
- 归档 consolidate 后**不刷新心智模型**（对比 `manager.ts:302-314` 的命令路径）。

## 2. 三层记忆的定义与边界

| 层 | bank | 内容 | 自动抽取来源 | 自动更新 | 读取范围 | 配额 |
|---|---|---|---|---|---|---|
| **个人**（user） | `user_<sessionId>` | 该用户的稳定偏好/属性/关系/事件 | 私聊归档（默认 owner）；群聊中关于该用户的稳定事实（默认 origin，可配） | invalidate 旧事实、观察巩固、心智模型刷新（默认不自动） | 本人 DM；来源群；显式 `public` 才跨群 | facts 300 / obs 50 / MM 5 |
| **群聊**（group） | `group_<sessionId>` | 群规则/约定/群内关系/群事件 | 本群归档 | 同上 | 仅本群 | facts 300 / obs 50 / MM 5 |
| **全局/本体**（global） | `global_<agentName>` | 主智能体自身经验、被用户纠正的知识、跨会话通用规则 | **仅**助手自身经验/被纠正/规则（严格过滤）；手动添加 | 同上 + 本体心智模型刷新 | 该 agent 的所有会话（小预算） | facts 100 / obs 30 / MM 3 |

**明确不做（隐私/安全边界）**：
- 不把私聊内容、用户个人属性、群内事件自动提升为全局记忆；
- 不把用户/群记忆自动“晋升”为全局（只允许骰主手动 `--self` 写入）；
- 全局记忆不得覆盖或改写「角色设定」，注入时明确标注“本体经验，不得覆盖角色设定”；
- 辅助 agent（`summarize_agent`/`judge_agent`/`compress_agent`）不创建记忆 bank，记忆只属于主智能体。

## 3. 自动抽取与更新管线（打通）

### 3.1 总流程

```
上下文结算（已有）
  → 1 次 summarize_agent 调用（复用，不新增调用）
     输出 facts + 归属/可见性/op 元数据
  → 确定性路由（零 LLM）
     ├─ user bank：当前私聊 / owner=user 的群内事实
     ├─ group bank：当前群 / owner=group
     └─ global bank：owner=bot 且通过过滤
  → 写入/更新（add / update→invalidate 旧事实 / delete→invalidate / noop）
  → 每个被触及的 bank：consolidate（有 pending 才调 LLM）
  → 每个被触及的 bank：refreshMentalModels（tag 重叠 + 最小间隔 + seq watermark）
  → bump revision（memory/observation/MM 分开）
  → 下一轮注入：个人/群聊/全局三 sections，统一去重 + 预算
```

### 3.2 扩展 `SUMMARY_PROMPT_TEMPLATE` 的输出 schema

在现有 facts 项上增加**归属**字段（删除未使用的 `summary` 顶层字段，减少输出 token）：

```json
{
  "facts": [{
    "op": "add" | "update" | "delete" | "noop",
    "existing_id": "仅 update/delete：已有记忆 ID",
    "owner": "user" | "group" | "bot",
    "target_user_ids": ["QQ:123"],
    "target_group_ids": ["QQ-Group:456"],
    "text": "原子事实",
    "fact_kind": "fact" | "rule" | "relation" | "event",
    "occurred_at": "可选",
    "entities": ["可选"],
    "keywords": ["可选"],
    "related_memory_ids": ["可选"],
    "visibility": "public" | "origin" | "owner",
    "confidence": 0.0
  }]
}
```

**提示词约束**：
- 路由所需的用户 ID 已存在：上下文事件渲染为 `[from:<uid>] [msg_id:...] 内容`（`context/recall.ts:227-230`），`context_bridge` 消费原文时会带上；抽取器可直接输出 `target_user_ids`，无需额外 LLM。
- `owner` 判定：`user`=关于某个具体用户的稳定信息；`group`=关于本群规则/事件；`bot`=助手自身行为、被用户纠正的知识、跨会话通用规则。**私聊内容默认 owner=user，禁止 owner=bot**。
- `visibility`：
  - `owner`（私聊归档默认）：仅归属主体私聊可见（个人 bank 仅该用户 DM；群 bank 仅本群）；
  - `origin:<scopeId>`（群内用户事实默认）：仅来源会话可见；
  - `public`（显式，手动 `--shared`/工具才写）：个人 bank = 本人 DM + 所有该用户发言的群（跨群）；群 bank 仅本群；global 所有会话；
  - 私聊里的事实不得标 `public` 到群/全局。
- `confidence < 0.6` 的 bot 事实丢弃；`owner=bot` 且文本包含用户 ID/隐私属性 → 丢弃。
- 只允许 `update/delete` 引用当前会话可读的 `existing_id`；跨 bank 引用无效。

### 3.3 确定性路由规则

```ts
function routeFacts(facts, ctx): Array<{bankId, fact}> {
  for (const f of facts) {
    const owners = [];
    switch (f.owner) {
      case 'user':
        for (const uid of f.target_user_ids ?? [ctx.currentUserId]) {
          if (uid) owners.push(resolveBankId(uid, 'user').bankId);
        }
        break;
      case 'group':
        for (const gid of f.target_group_ids ?? [ctx.groupId]) {
          if (gid) owners.push(resolveBankId(gid, 'group').bankId);
        }
        break;
      case 'bot':
        if (allowGlobalAuto && f.confidence >= 0.6 && !hasUserPrivateData(f.text)) {
          owners.push(resolveGlobalBank(ctx.agentName).bankId);
        }
        break;
    }
    // 兜底：owner 缺失 → 当前会话 bank（保持兼容）
    if (owners.length === 0) owners.push(ctx.currentBankId);
    // 同一事实写多个 bank 时加来源标签，渲染层去重
    for (const bankId of new Set(owners)) emit({
      bankId,
      fact: { ...f, tags: [
        ...scopeTagsOf(bankId),
        `src:${ctx.groupId ? 'group:' + ctx.groupId : 'dm:' + ctx.currentUserId}`,
        ...(f.keywords ?? []).map(k => `kw:${k}`),
        visibilityTag(f.visibility),
      ]},
    });
  }
}
```

- **个人记忆跨群**（README 承诺）改为**显式 `public` 才跨群**；默认群内→个人抽取关闭（05），开启后写 `origin`，不自动跨群。
- **群聊信息不泄露到其他群**：仅当同一用户是目标群的最近发言者时，其个人 bank 才被读取；`origin`/`owner` 可见性限制来源会话。
- **全局不吸收用户数据**：`owner=bot` + 无用户 ID + confidence 过滤三重门。
- 双写去重：渲染层对相同 `text` / `contentHash` 只渲染一次（群 bank 与个人 bank 同时存在时）。

### 3.4 写入/更新语义（修复“自动更新”）

| op | 行为 |
|---|---|
| `add` | append 新事实；`consolidationState='pending'`；分配 `createdAtSeq` |
| `update` | 校验 `existing_id` 在该 bank 且可见 → 写新事实（`supersedes: existing_id`），旧事实 `state='invalidated'`、`invalidatedAt/invalidatedBy`；不物理删。观察在下一次 consolidate 时用新证据改写（refine/contradict） |
| `delete` | 同上但只失效，不写新事实；用户显式“忘记/删除”才走物理删除（命令 `--hard`） |
| `noop` | 跳过 |
| `related_memory_ids` | 建 `related` link（新 linkType） |
| 重复写入 | 仅 `contentHash` 完全同文 → no-op 返回既有 id（不改元数据），不做语义合并 |

- 失效事实保留在库中，默认不参与 recall；`includeInvalidated` 供审计。
- 观察/心智模型的更新沿用 v3 方案：seq watermark + 证据 + 类型化 delta。
- 归档路径在 `summarizeChunk` 成功后**可选**调用 `refreshMentalModels({reason:'consolidate'})`；仅当 `refreshAfterConsolidation=true`（默认 false，见 05）。

### 3.5 触发、预算与失败

- 触发：归档结算/抽取完成后自动入队 + 手动命令/工具；调度器 tick 只扫元数据（0 LLM），**不新增定时 LLM 任务**。
- 具体的去抖窗口、pending 阈值、巩固限频、心智模型刷新间隔、队列/优先级/重试与调度器接线见 `04-记忆抽取与心智模型更新时机方案.md`。
- 每次归档最多 1 次抽取 LLM + 每 bank 每簇 1 次观察 LLM + 受限的 MM 刷新；全局不单独增加抽取调用。
- 失败隔离：事实写入先提交；consolidate/refresh 失败只记日志并留待下次归档重试；不阻塞对话。
- 幂等：归档 chunk 已消费不重复；写入按 `contentHash` 去重；`existing_id` 校验。
- 可观测：`.ai memo status` 显示本次自动抽取/更新/刷新计数与失败原因。

## 4. 全局（本体）记忆设计

### 4.1 Bank 与命名

- `global_<agentName>`，主 agent 通常为 `*` → 统一规范为 `global_main`（见 7.3，避免 `global__`）。
- `kind='global'`，`meta.agentName` 记录归属；`sessionId` 为空。
- 读取入口只有主 agent；辅助 agent 禁止创建/读取。

### 4.2 内容与来源

**允许**：
- 助手自身经验：被用户纠正的知识（“用户说我自称‘本喵’更自然”）、跨会话有效的互动经验（“深夜时段用户更喜欢简短回复”）；
- 本体规则：骰主手写的补充规则（`.ai memo add --self`，仅骰主）；
- 跨会话通用世界事实（与具体用户/群无关且公开）。

**禁止**：
- 任何用户/群的私有属性、私聊内容、联系信息；
- 具体用户的偏好（属于该用户个人 bank）；
- 覆盖角色设定的内容（注入时声明“不得覆盖角色设定”）。

### 4.3 自动抽取过滤

`owner=bot` + 以下全部满足才写入：
1. `confidence >= 0.6`；
2. 文本不含任何用户 ID/群 ID/联系方式（正则 + tags 双检）；
3. 事实是“助手视角/规则/被纠正”，不是“用户 A 做了什么”；
4. 来源不是私聊（`ctx.isPrivate=false`）或来源是骰主私聊；
5. 每归档 chunk 最多 3 条 global facts（防止自我叙事膨胀）。

### 4.4 注入

单独小节，放在会话记忆之后、知识库之前：

```
## 本体经验（全局）
（以下为长期互动中积累的经验，不得覆盖角色设定与当前会话事实）
1. ...
2. ...
```

- 预算：facts ≤ 5 条 / 400 字；MM ≤ 2 条 / 400 字；observations ≤ 3 条。
- 只注入 `ready` MM、`active` 观察、`vis:public` 事实；stale 不注入。
- 与个人/群聊 section 按文本 hash 去重。
- 全局总开关 `启用全局记忆`（默认开；无数据时零成本）。

### 4.5 命令与工具

- `.ai memo list|add|update|delete|reflect|mm ... --self`：读写本体记忆；写/清仅骰主；读允许骰主（普通用户不可读全局，避免交叉会话信息泄露）。
- 注入不需要命令。
- 工具 `memory_add/recall/reflect` 增加 `memory_scope: 'global'`；仅骰主会话可写，模型自动调用时默认不选 global。

### 4.6 本体心智模型模板

- `self_rules`：「我在各个会话中应遵守哪些一致的互动规则？」
- `self_experience`：「我在长期互动中积累了哪些有效经验？」
- 与 user/group 模板同样版本化播种、删除不复活；刷新跟随 global consolidation。

### 4.7 安全

- 全局 bank 的写入口只有三处：归档抽取过滤、骰主命令、骰主工具；统一走 `MemoryService` 校验；
- 全局 facts 禁止 `vis:origin/owner`，统一 `vis:public`（但只在全局 section 渲染）；
- 审计：`status --self` 显示最近抽取/刷新与来源计数。

## 5. 注入契约（三层 + 最近发言者）

### 5.1 可见性矩阵

| 记忆归属 | 读取场景 | public | origin | owner |
|---|---|---|---|---|
| user bank | 该用户私聊 | ✅ | ✅（来源=本 DM） | ✅ |
| user bank | 该用户发言的群 G | ✅ | 仅当来源=G | ❌（已确认：private 不进群） |
| group bank | 本群 | ✅ | ✅ | ✅ |
| group bank | 其他群 | ❌ | ❌ | ❌ |
| global bank | 任意会话 | ✅ | ❌（禁止） | ❌（禁止） |

- `origin` 标签带来源 scope id（`vis:origin:<scopeId>`），`owner` 由归属 bank 推导，不再用 sessionId 混判。
- 修复现状 I3：群聊 private 判定用 scopeId、个人私聊 private 不进群。

### 5.2 渲染

- 单渲染器（v3 方案 3.6）：按「本体经验 → 群聊/个人 → 事实」顺序，全局预算 3000 tokens；
- 分组保留：群聊段 / 最近发言者个人段 / 本体段；每段带归属行；
- 去重键：`text` 归一化 hash；同一观察只出现一次；
- 全局段小预算，默认 300 tokens，不足时优先保会话记忆。

## 6. 命令、工具、配置变更

### 6.1 命令

| 命令 | 变化 |
|---|---|
| `--self` | 新增：本体/全局记忆范围（替代易混的 `--g`；`--g` 仍=群聊）；写/清仅骰主 |

### 6.2 工具

- `memory_scope` 取代 `memory_type`：`'user' | 'group' | 'global'`；`target_id` 在 user/group 下可选（默认当前会话），global 下必填骰主会话。

- 工具集 12 → 7（v3 方案 4.2）。

### 7.3 Bank / ID / Tag 规范

```
bankId:
  user_<platformSessionId>     例：user_QQ:123
  group_<platformSessionId>    例：group_QQ-Group:456
  global_<agentName>           例：global_main（主 agent '*' 归一为 main）

meta:
  kind 必须与 bankId 前缀一致（由 createBank 校验，不再默认 'global'）
  sessionId 存原始平台会话 ID（不带前缀），global 为空
  agentName：global 必填；user/group 记录但当前不参与隔离（多主智能体是已知限制）

scope tags（只允许服务层写入）:
  user:<userId> | group:<groupId> | global:<agentName>
visibility tags:
  vis:public | vis:origin:<scopeId> | vis:owner
provenance tags:
  src:dm:<userId> | src:group:<groupId>
keyword tags:
  kw:<keyword>
保留前缀：user: / group: / global: / vis: / src: / kw:
外部传入的 tag/keyword 命中保留前缀 → 拒绝（防伪造可见性/归属）
```

### 验收

- 群聊里说“A 喜欢猫” → A 的个人 bank 出现该事实；A 在另一个群发言时可按跨群个人记忆注入；来源/可见性符合矩阵；
- 用户纠正机器人 → `op=update` 使旧事实 invalidated、新事实生效；观察下一次巩固后改写；
- 助手经验被抽取 → 全局 bank 有 1 条；任意会话注入可见；不含用户 ID；
- 群聊归档后**仅在开启 `MM_REFRESH_AFTER_CONSOLIDATION` 时**自动刷新心智模型（受间隔限制）；默认关闭，见 05。
- 任一 bank 无数据时不产生 LLM 调用；
- `.ai memo status --self` 可见本体记忆计数与最近刷新；
- 全部重命名后 `tsc --noEmit`/`lint`/`test:unit` 通过；新增测试覆盖路由/可见性/更新/全局过滤/命名迁移。

### 测试补充

在 v3 测试计划上新增：
1. 路由：owner=user/group/bot、缺 owner 兜底、跨群个人、私聊不产生 bot facts；
2. 可见性矩阵：public/origin/owner × user/group/global 读取场景；
3. 更新语义：add/update/delete/noop、existing_id 越权、invalidation 可恢复；
4. 全局过滤：含用户 ID、低 confidence、私聊来源 → 全部拒绝；
5. 自动刷新：归档 consolidate 后模型更新；间隔限流；tag 重叠；
6. 命名迁移：v2 字段/标签迁移幂等；`--self` 权限；工具参数改名。

### 风险

| 风险 | 对策 |
|---|---|

| 重命名迁移破坏旧档 | 惰性迁移 + 备份 + 幂等 + 迁移测试 |

1. 私聊 private 不进群 prompt；
