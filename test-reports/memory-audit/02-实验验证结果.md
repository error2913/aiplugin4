# 记忆模块实验验证结果

- 运行环境：Node v24.19.0，仓库提交 `f633e98`，SealDice 最小桩（`scripts/harness/seal-env.cjs`）
- 实验文件：`test-reports/memory-audit/experiments.ts`（全部使用 `MemoryEngine` 依赖注入：`InMemoryMemoryStorage`、桩 embedding/extractor/reranker/observation/reflectSynthesizer、可注入 `now`）
- 运行器：`test-reports/memory-audit/run.cjs`
- 原始输出：`test-reports/memory-audit/raw-results.txt`
- 结果：**15/15 用例通过（无异常）**，`SUMMARY {"total":15,"failed":[]}`

复现：

```bash
# 仓库根目录
npx esbuild test-reports/memory-audit/experiments.ts --bundle --platform=node --format=cjs --outfile=test-reports/memory-audit/experiments.cjs
node test-reports/memory-audit/run.cjs
```

> 说明：实验不调用真实 LLM/网络，全部使用桩；`now` 注入仅心智模型服务使用，retain 仍用真实时钟（见 O 项）。

## 1. 逐项结论

| 用例 | 候选问题 | 实测关键输出 | 结论 |
|---|---|---|---|
| **A** retain 精确查重 | 原文按 `trim+小写+去空白` 命中即合并 | 3 次写入 → 2 条 unit；第 2 次 `action:"merged"`；合并后 tags 变 `user:QQ1,vis:public,user:QQ2,kw:drink`、metadata 被后写改 `type:event`、importance 0.9、factType 仍 world、accessCount=1 | **证实**：原始事实被合并且元数据/统计被后写污染 |
| **B** tagsMatch 默认 any | 群聊召回带出仅 `user:` 标签的单元 | `ids_any` 含 `用户1的私人备注`（仅 user:QQ1 标签）；`ids_all` 只 1 条；非参与方 QQ9 的单元未进入 | **部分证实**：无越权到非参与方，但“仅个人标签”的单元会进入群聊召回（归属过滤放宽） |
| **C** 语义无阈值 / backfill | 无相似度下限；无策略命中时按插入序 | C1：3 条完全无关记忆全部带 `semantic` 策略返回（cosine=0，score≈0.416）；C2：`maxTokens:20` 时返回最早 4 条（写入序）；C3：embedding 抛错被静默吞掉，语义通路关闭 | **证实**：语义无下限；backfill 最旧优先；embedding 故障无告警 |
| **D** reflect 范围与必调 LLM | 全部 ready 模型 + 全部观察无条件注入；空库也调 LLM | 3 条 scopeTags 全部不匹配 `user:QQ1` 的模型仍全部注入；只给 `factTypes:['world']` 仍注入 3 条观察；同一 query 调两次 = 2 次 LLM；空库调用 1 次；payload 1212 字符 | **证实** |
| **E** delta 是整段重写 | 无 `structured_content` AST、无类型化操作、无逐字节保证 | 模型字段列表无 `structuredContent`；`content` 从“旧答案：A段-B段-C段”整体替换为“新答案：A段 - B段 - C段”；history 只存旧 answer；`mode:'delta'` 时仅把旧答案+新记忆喂给返回单字符串的 synthesizer | **证实**：改动虽可能语义相同，但没有“未命中段落不变”的机制保证 |
| **Q** 同秒 watermark | 秒级水位导致同秒新记忆进不了 delta | 同秒场景：watermark == newestUpdatedAt → 非 force 刷新 `not_stale` 跳过；force 刷新 delta 窗口为空（0 条记忆） | **证实**：同一秒写入的记忆会漏出 delta，直到后续新记忆出现 |
| **F** 观察趋势 / 过期删除 | 无 STABLE… 趋势；过期物理删除 | `Observation` 字段无 trend/status；history 只有 `created`；把观察压到 91 天前再 consolidate → observations 0，同步 unit 被删；源事实仍在且 `consolidationState="done"` | **证实**：无趋势枚举；过期删除；源事实标记不重置，观察无法重建 |
| **G** 巩固后刷新范围 | 是否按 tag 重叠筛选 | 5 个模型（A/B/C/D/全局），1 次 `refreshMentalModels(reason:'consolidate')` → LLM 调用 2 次（A、全局），skip 3（not_stale 1、no_source 2） | **部分证实**：触发层遍历全部模型、没有 tag 重叠筛选；但 per-model watermark/scope 让实际 LLM 调用被限制。差异是语义与全局模型行为，不是“每次都烧 5 次” |
| **H** 图检索越界 / 观察向量 | 图扩散返回 scope 外；观察 unit 无向量 | `graphSearch` 返回 3 条（含 tags/类型外单元）；`recall` 结果只 2 条（越界被 `unitById` 过滤）；观察 unit 创建时 `embedding:[]`，首次召回回填 `[8,1]`，首轮仅 `keyword`，次轮才 `semantic+keyword` | **证实**：不会越权注入，但计算浪费；观察首轮不进语义 |
| **I** 群聊注入预算/重复 | 分组注入无全局预算；跨 bank 重复 | 群段 20 条 1600 字；每位发言者 13 条 1040 字；观察 20 条 6188 字；组合 prompt 14292 字 ≈ **13311 tokens**，而各调用 maxTokens 合计 5120；同一事实在 prompt 出现 3 次 | **证实**：预算严重超发 + 跨 bank 重复文本 |
| **J** cap 淘汰 | 是否淘汰刚写入/破坏证据 | J1：cap=2，两条 importance 0.95 旧记忆 → 刚写入的 0.1 记忆立即被删（`retainResult` 返回 id 但库中不存在）；J2：cap=3 时 3 条源事实 + 1 条 observation unit → 覆盖组先被删，观察 proofCount 3→2，evidence 减为 2 条 | **证实**：写入即可能被淘汰；观察证据链被静默削减 |
| **K** 命令/工具写入标签缺失 | 默认参数写入后注入不可见 | 仅 `vis:public` 的 user 记忆 + 注入式 `recall(tags:['user:QQ1'])` → 返回 0；group 同理返回 0；不带 tags 的 recall 返回 3；带 baseTags 的归档记忆可见 | **证实**：写入-注入契约断裂（P0） |
| **N** 观察双重注入 | 观察 unit 进入长期记忆 + 观察段再注入 | `recallCount=4`，`obsUnit` 在召回中且出现两次；拼接 prompt 中同一观察文本出现 **3 次** | **证实**：双重注入 + recall 重复结果 |
| **O** retain 时钟 | `now` 注入不覆盖写入路径 | 注入 now=1700000000；unit.createdAt/updatedAt=1792946861（真实时钟） | **证实**：时钟注入仅心智模型生效 |
| **R** 空策略兜底顺序 | backfill 按插入序、无视新近度 | 把“最新记忆”的 lastAccessedAt 设为当前，recall 仍返回写入顺序（最早→最新），matchedStrategies 全空 | **证实**：兜底不看新近度/重要性 |

## 3. 实验未能覆盖、需人工/静态确认的项

以下问题依赖命令层/私有可见性/配置链路，已在检查报告中以静态证据标注，未在实验中构造完整 Session/Prompt（避免引入 SealDice 全环境）：

- `.ai memo obs off` 装饰性（`summaryOverride` 无消费者）；
- `memory_update` 越权保护条件写反；
- 群聊 private 记忆写入/注入判定使用不同 id（群 id vs 玩家 id）；
- `MEMORY_MM_TICK_INTERVAL` 死配置；
- README 记忆命令表与实现不一致；
- `obs clr` 不清 `consolidationState`、不失效 prompt 缓存 revision；
- storage `saveBank` 总是写 5 个分片（与注释不符）。

这些项在实现重写时按方案第 6 节一并删除/修复。
