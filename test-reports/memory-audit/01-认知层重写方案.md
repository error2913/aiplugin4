# 记忆模块改进方案：认知层重写（v3）

> ⚠️ **实现以 `05-最终实施方案.md` 为准**。本文保留数据模型/算法推导与背景；其中默认值、可见性词表、预算、调度器/端口方案、测试文件方案已被 05 及三份 review 裁决取代（尤其：不再新增 memory_work 端口，改为删除 archiver 记忆调用；MM 默认 full/不自动刷新/0 间隔/2048；可见性统一 public/origin/owner；测试续写现有 entry）。

> 配套检查报告：`00-记忆模块检查报告.md`
> 结论先行：**不在现有字符串/同步 unit 结构上打补丁，重写“观察层 + 心智模型层 + reflect + 注入层”，保留 bank/存储/召回原语。** 这不是全模块从零重写，也不是修修补补，而是把与 Hindsight 语义冲突的三个子系统整体替换，并删除旧路径。

## 0. 方案定位

| 选项 | 结论 | 理由 |
|---|---|---|
| A. 在现结构上逐点修 | ❌ 否决 | 需要在 `answer: string` 上另挂 AST、在 observation 表外再留同步 unit、在一次性 reflect 里加优先级分支 → 三套并存路径，正是冗余来源 |
| B. 全模块从零重写 | ❌ 否决 | bank 隔离、JSON 分片存储、四路召回 + RRF + rerank 回退 + token 预算、注入缓存与 revision 均已可用且与 Hindsight 思想一致；重写只会制造回归 |
| **C. 认知层重写 + 读写契约修复（本方案）** | ✅ 采用 | 替换 `observations` / `mental_models` / `reflection` / 注入渲染四处；保留 `repository`/`storage`/`scoring`/`prompt_cache`/`revision`；迁移旧数据；删除旧代码路径 |

**目标**（对齐 Hindsight 可迁移部分）：
1. 原始事实 append-only，不因文本相似而合并；相似关系以 link 表达。
2. 观察是独立网络：evidence + proofCount + 保守合并 + 矛盾改写 + 不物理删除；过期只降级“不再默认信任”，供 reflect 核对。
3. 心智模型 = 可增量维护的**结构化文档**：`sourceQuery/content/trigger/tags/maxTokens/structuredContent/reflectResponse/lastRefreshedSourceQuery`；delta 用类型化操作，未命中段落逐字节不变；有 baseline / sourceQuery 漂移 / 空内容保护。
4. reflect = 有预算的 agentic 三层检索：心智模型 → 观察 → 原始事实；有 staleness 信号与新鲜模型快路径。
5. tags 双层门控：refresh 读取过滤（默认 all_strict）与读取可见性过滤分离。
6. 读写契约：scope 标签在**写入时统一注入**（修复 R1/I3），注入侧只做读取过滤；所有 tier 只渲染一次。
7. 三层 bank（个人/群聊/全局本体）与自动抽取/更新管线：见 `03-全局记忆与三层自动链路方案.md`；抽取/巩固/心智模型刷新的具体时机与调度器见 `04-记忆抽取与心智模型更新时机方案.md`（本文件不重复细节）。

**非目标**（明确不做，避免冗余）：
- PostgreSQL/pgvector/Oracle 后端、异步 worker/分布式锁、REST/MCP server/webhook、bank 模板、CARA opinion 网络与 disposition 参数、384 维固定 embedding、多租户 `tag_groups`。
- 不引入新依赖；不新增“v3 目录”（沿用 `src/memory/v2/`，bank meta 内升 `schemaVersion:3`）。
- 不保留旧行为兼容层：旧数据迁移后删除旧字段/旧分支，不做双读双写。

## 1. 目标架构

```
写 ── retain(scopeTags 必须由服务层注入)
      ├─ 原始事实 RawFact (append-only) ── semantic/entity links
      ├─ 文档(可选，保留字段不新增逻辑)
      └─ consolidation（归档后/手动）
           └─ 观察 Observation { evidence[], proofCount, lastSupportedAt, status }
                └─ 手动 obs clear 重置源事实 consolidation 标记 → 可重建

读 ── buildMemoryPrompt  (单渲染器，全局预算)
      ├─ 心智模型（ready；固定模板优先 + 语义召回；读库零 LLM）
      ├─ 观察（active；stale 不注入；去重后与事实互斥）
      └─ 原始事实 recall（四路 RRF + rerank 回退 + 预算）

reflect（用户/工具/模型刷新）
      step1 searchMentalModels(query) ── 新鲜且高相关 → 直接返回 content（零合成 LLM）
      step2 searchObservations(query) ── 附 is_stale 分级
      step3 recall(query) ── 原始事实 ground truth
      └─ LLM 合成（引用证据 id）→ basedOn；刷新调用落库 reflect_response
```

**单一事实源**：观察只存在 `observations[]`；心智模型只存在 `mentalModels[]`；两个 tier 都不再复制为 `MemoryUnit`。

## 3. 操作管线

### 3.1 retain（写入契约）

```ts
// src/memory/manager.ts 统一入口（command/tool/媒体/归档共用）
async function retain(session, text, input) {
  const bank = resolveBank(session);
  const tags = uniq([
    scopeTagOf(bank),                    // 必须：user:<id> 或 group:<id>（修复 R1）
    ...input.relatedUserIds.map(id => `user:${id}`),
    ...input.relatedGroupIds.map(id => `group:${id}`),
    ...input.keywords,
    input.visibility === 'private' ? visibilityTag('owner', scopeOf(bank)) : visibilityTag('public'),

  ]);
  return engine.retain(bank.id, { ...input, tags });  // 不允许调用方绕过
}
```

`engine.retain`：
1. `text = trim`；空 → noop。
2. 解析实体（`resolveEntityIds`），time 字段归一。
3. embedding（可选；失败降级）。
4. **不做**精确文本合并。保留一个“完全同文去重”：`contentHash` 命中时返回既有 id（`action:'duplicate'`，不改 tags/metadata/importance/accessCount）——这是为 QQ 场景低价值重复写入做的物理去重，**不是语义合并**；在文档中注明与 Hindsight append-only 的差异。
5. 建立 semantic link（cosine ≥ `SEMANTIC_LINK_MIN=0.7`）与 entity link；不做全库 O(n²) 扫描 → 用 entityIds 桶 + 最近 N 条候选（N=200）。
6. `createdAtSeq = ++bank.meta.settings.nextFactSeq`。
7. **不在每次 retain 做 cap 淘汰**；淘汰只在 maintenance（consolidate 后/命令）执行。

### 3.2 recall（检索）

签名：
```ts
recall(bankId, query, {
  tags?, tagsMatch?: TagsMatch, types?,
  maxTokens?, budget?, collapseObservations?: boolean,
  includeInvalidated?: false,
}): Promise<RecallHit[]>   // RecallHit = { kind:'fact'|'observation'; unit?: MemoryUnit; observation?: Observation; score; matchedStrategies }
```

流程：
1. 取 `state='valid'`、`types` 命中的事实；按 `tagsMatch` 过滤（默认 **any**，调用方可传 all_strict）。
2. 语义：只保留 `sim >= SEMANTIC_MIN_SIM`（默认 0.35，配置项）；无向量则跳过。
3. 关键词：保留 char n-gram，但只取 top `keywordLimit`；空 query 时改用 `importance + recency` 排序。
4. 图：先按 query 命中实体，再从**已过滤的 scope 内**做扩散（≤2 跳），不返回 scope 外 id。
5. 时间：保留中文相对窗口（今年/去年/上个月/…），补 `YYYY-MM-DD` 与 `MM-DD`。
6. RRF 融合；LLM rerank 仅在前 20 候选、配置开启时；失败回退 RRF。
7. 新近度加分只作用于 RRF 结果；`accessCount/lastAccessedAt` 只在真正返回时更新，末尾保存一次。
8. 去重（id Set），按 token 预算裁剪；**不做插入序 backfill**。结果不足时：
   - 空 query：按 `importance × recency` 补足；
   - 非空 query：返回空，由调用方决定。
9. `collapseObservations`：若事实被某条 active observation 的 evidence 覆盖，用该观察替换事实（每条观察只出现一次）；渲染层不再额外注入重复观察。

### 3.3 consolidate（观察生成）

```ts
async function consolidate(bankId, opts?: { touchedTags?: string[] }) {
  resetStaleStatus(bankId);                       // 状态惰性计算
  const pending = facts.filter(consolidationState === 'pending');
  const clusters = cluster(pending);              // 实体/相似度 0.97；不跨 scopeTags 混簇
  for (const cluster of clusters) {
    const evidence = cluster.map(f => ({ memoryId: f.id, quote: f.text }));
    const decision = await llm.observationDecision({ evidence, existing: candidates });
    // decision: create | reinforce | refine | contradict | merge | split | none
    applyObservationDecision(decision);           // evidence 并集、proofCount 重算、history reason
  }
  markConsolidated(pending);
  await retention(bankId);                        // cap 保护（见 3.6）
  return { created, updated, merged, touchedTags };
}
```

LLM 提示词要求（替换 `OBSERVATION_PROMPT`）：
- 一个 canonical observation 携带多个源事实，**禁止**生成近重复 sibling；
- 数字/实体/否定/条件不同时保持独立（保守合并）；
- 新证据与现有观察矛盾时用 `contradicted` 记录变化，不覆盖旧历史；
- 输出严格 JSON schema：`{action, targetId?, text, evidenceMemoryIds[]}`；解析失败 → 简单拼接并标记 `failed`，不阻塞归档。

过期语义：
- `Observation.status` 由读取时计算：`active` 若 `lastSupportedAt` 在 `OBSERVATION_STALE_DAYS(90)` 内，否则 `stale`。
- **不删除** stale 观察；注入默认跳过，reflect 可带入并标记“待核对”，由 raw facts 核对。
- `.ai memo obs clr`：清空 observations，并**把源事实 `consolidationState` 重置为 pending**（可重建）；不删事实。

### 3.4 mental_models

创建：
```ts
createMentalModel(bankId, { sourceQuery, content?, tags, trigger }) {
  // 有 content → ready；无 content → pending 后立即 refresh(full)
  // structuredContent = parseMarkdown(content || '')
  // reflectResponse = 本次 reflect 的 basedOn
}
```

刷新（`refreshMentalModels(bankId, ids?, {reason})`）：
1. 限流：per-bank 最小间隔 + failed 冷却（保留现有逻辑，改 seq）。
2. 每模型：
   - scope：`factTypes + tagsMatch`（有 tags 时默认 `all_strict`；无 tags 不筛）。
   - `newestSeq = max(in-scope fact seq, in-scope observation updatedSeq)`；`newestSeq <= lastMemorySeenSeq` → `skipped:not_stale`。
   - **delta 前置条件**：`trigger.mode==='delta'` && `structuredContent` 非空 && `sourceQuery === lastRefreshedSourceQuery`；否则 `full`。
   - delta：`recall(createdAfterSeq=lastMemorySeenSeq)` 只取新证据 + 现有 AST；LLM 输出**类型化操作**：
     ```json
     {"operations":[
       {"op":"add_section","heading":"...","blocks":[...]},
       {"op":"append_bullet","sectionId":"...","text":"..."},
       {"op":"replace_block","blockId":"...","text":"..."},
       {"op":"remove_stale_paragraph","blockId":"..."},
       {"op":"replace_section_blocks","sectionId":"...","blocks":[...]}
     ]}
     ```
     `applyDeltaOps` 只改命中块；未命中块的 `text` 原样复制（测试断言字节相等）。
   - full：`reflect(sourceQuery, {scope, strict:true, fastPath:false})` → 新 content → `parseMarkdown`。
   - 输出空/LLM 失败：保留旧 content + AST；`reflectResponse.skipped='empty_candidate'|'llm_error'`；不推进 watermark。
   - 成功：写 history（旧 content/structured）、version++、`lastMemorySeenSeq=newestSeq`、`lastRefreshedAt=now`、`lastRefreshedSourceQuery=sourceQuery`、`reflectResponse.basedOn`、重算 embedding。
3. 自动刷新触发（**仅在配置开启时；默认关，见 05 §7**）：`consolidate` 返回 `touchedTags`；只刷新 `tags.length===0 || intersect(tags,touchedTags)` 的模型（无 tags 的全局模型按“有任意新证据即刷新”处理，避免永不刷新；在文档中注明这是对 Hindsight “仅重叠”的 QQ 场景放宽）。
4. 读取：`searchMentalModels(query, tags, {freshOnly?})`；`isStale(model) = newestInScopeSeq > lastMemorySeenSeq`，零 LLM。

### 3.5 reflect（agentic 三层）

```ts
async function reflect(bankId, query, opts: {
  tags?; factTypes?; scopeNote?;
  fastPath?: boolean;        // 用户/工具 reflect 默认 true；模型刷新 false
  strict?: boolean;          // 无答案时是否允许 dump（刷新/工具 false）
  maxTokens?: number;        // 默认 2048
}) {
  const models = await searchMentalModels(query, tags, { limit: 3 });
  const fresh = models.find(m => score(m) >= 0.5 && !isStale(m));
  if (opts.fastPath && fresh) {
    return { text: fresh.content, basedOn: { models:[fresh], observations:[], facts:[] }, answeredBy:'model' };
  }

  const observations = await searchObservations(query, tags, { limit: 5 });
  const staleGrade = gradeStaleness(bankId);      // up_to_date/slightly_stale/stale
  const facts = await recall(bankId, query, { tags, maxTokens: maxTokens/2 });

  if (facts.length === 0 && observations.length === 0 && models.length === 0) {
    return { text: opts.strict ? '' : NO_MEMORY, basedOn: empty, skipped:'no_memory' };
  }
  const text = await llm.synthesize({
    query, scopeNote: opts.scopeNote ?? scopeNoteForBank(bankId),
    models, observations, facts, staleGrade,
    rules: '优先引用新鲜心智模型；stale 时以原始事实核对；每条结论标 [证据 id]；无证据时明确说不知道',
  });
  if (!text.trim()) return { text:'', basedOn, skipped:'llm_error' };
  return { text, basedOn, answeredBy:'synthesis' };
}
```

- 用户 `.ai memo reflect` / `memory_reflect`：`fastPath:true`，命中新鲜模型时零 LLM、毫秒返回。
- 模型刷新：`fastPath:false`，必须重新合成；`strict` 保证不回退 dump 记忆原文。
- `basedOn` 统一字段名（`models/observations/facts`），由刷新方写入 `reflectResponse`。

### 3.6 注入与渲染（`manager.buildLongTermPrompt` + `prompt.ts`）

单入口：
```ts
async function buildMemoryPrompt(ctx, session, text, uis, gi) {
  const bank = resolveBank(session);
  const sessionTags = scopeTagsFor(session, uis, gi);   // 含本会话 scopeTag + 最近发言者
  // 1) 心智模型：固定模板优先 + 语义召回；按会话 tags any 过滤；只 ready
  // 2) 观察：active + scope 命中；按 updatedAt 倒序、≤20；stale 不注入
  // 3) 事实：recall(collapseObservations:true)；个人/群按分组渲染
  // 3.5) 本体（全局）经验：独立小预算 section（见 03 方案）
  // 4) 全局预算：默认 3000 tokens（配置），先模型/观察、后事实；超预算按分数截断
  // 5) 去重：文本 hash 去重；观察覆盖的事实不再渲染
  // 6) 群聊保留“群聊 / 最近发言者个人”分组与归属行；私聊单段
  return renderMemory(sections, { maxTokens });
}
```
- 删除 `buildObservationPrompt`（观察并入单入口）或保留为同一渲染器的薄包装（除知识库外不再双入口）。
- 会话级 `obs off`：`buildMemoryPrompt` 检查 `session.memory.summaryOverride !== false`，**真正生效**（保留命令）。
- 群聊 private：`canSee` 使用 `vis:origin:<scopeId>` / `vis:owner` 判定（见 03 命名规范）；个人 bank 注入时按被注入者本人 scope（不再用触发者 user id 判定他人私聊私有记忆）→ 修复 I3。
- `status` 注入估算改为调用同一个选择函数（不再手写标签估算）。

### 3.7 保留/淘汰策略

- 默认仍不做单条 eviction（Hindsight 取向）；`MEMORY_MAX_FACTS` 继续作为存储安全阀，但：
  1. 只在 maintenance 执行，不在 retain 路径；
  2. 永不淘汰本回合刚写入；
  3. 有 active observation evidence 引用的事实**跳过**（宁可持续超过 cap，也不破坏证据链）；
  4. 先淘汰 `state='invalidated'`，再最低 `decayScore`；
  5. 默认值从 100 调至 300（可配置），文档说明“安全阀，不是记忆策略”。
- 纠错使用 `state='invalidated'`（保留可恢复），命令提供 `.ai memo update`（改文本）与 `.ai memo delete`（物理删，危险操作）。

| `reflect` | 增加“命中心智模型（零 LLM）/ 合成（证据数）”标识；可选 `--deep` 强制下探原始事实 |
| `mm` | 列表显示状态/是否 stale/自动刷新开关；`refresh` 原因中文化；`add` 保留 `--tag/--mode/--auto/--no-auto`；新增 `mm clear <ID>`（清空 content 强制下次 full）——对齐 Hindsight clear_mental_model |

## 5. 迁移（v2 → v3）

`migrate.ts` 在 `repository.getBank` 时按 `schemaVersion` 惰性执行，幂等：

1. `schemaVersion=2` → 3。
2. 删除 `units[].factType==='observation'` 的同步 unit（观察数据以 `observations[]` 为准；若该 unit 有独立 status 差异，保留 observation 表版本）。
3. `observations[]`：补 `status='active'`、`lastSupportedAt=lastVerifiedAt`、evidence 去重；history reason 归一；`lastVerifiedAt` 移除。
4. `mentalModels[]`：
   - `sourceQuery = question`，`content = answer`，`structuredContent = parseMarkdown(answer)`；
   - `trigger = triggerConfig`（补 `tagsMatch = tags.length ? 'all_strict' : 'any'`）；
   - `lastRefreshedSourceQuery = question`，`lastMemorySeenSeq = 当前 bank 最大 fact seq`（或 0 强制首次 full）；
   - `reflectResponse` 缺失 → 首次刷新写入；
   - `history` 旧 answer 字符串映射为 `{content, at, trigger}`；
   - 删除旧字段。
5. 为所有旧 facts 分配 `createdAtSeq`（按 createdAt 排序），设置 `nextFactSeq`。
6. 清理 dangling links；清理 `documents/chunks` 未使用数据（保留字段，不新增）。
7. 迁移后 `repository.save(bankId)` 一次；失败保留 v2 数据并记日志，下一次重试。

迁移测试：构造 v2 样本（含 observation unit、delta 模型、stale 观察），断言迁移后 tier 数量、序列化体积下降、注入不再重复。

## 9. 验收标准

| 指标 | 目标 |
|---|---|
| 标签契约 | 任意写入路径（命令/工具/媒体/归档）写完后，下一次同会话注入必能召回；单测覆盖 |
