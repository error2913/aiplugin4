## 一、结论摘要

1. **参考架构基本可信，但有一处关键错误**：`mental_models` 表结构、full/delta 刷新、类型化编辑 + AST 逐字节保证、tags 双重门控（默认 `all_strict`）、consolidation 后按 tag 重叠刷新、三层 reflect 优先级、TEMPR 四路检索 + RRF + rerank + token 预算、原始事实 append-only 不再合并——这些都能在官方 Blog/论文/提交记录中找到证据。**但“观察记忆有 STABLE/STRENGTHENING/WEAKENING/NEW/STALE 新鲜度趋势枚举”不成立**：Hindsight 官方提交 `495e957` 的标题就是「stop claiming a per-observation freshness trend」，现行机制是 `is_stale` 分级信号（按未巩固积压量 `up_to_date / slightly_stale / stale`），不是观察级趋势枚举。

2. **当前插件是“形似而神不似”的 Hindsight 简化版**：bank 隔离、原始事实/观察/心智模型三层、evidence/proofCount、watermark、trigger 配置、四路召回 + RRF 等骨架都在；但决定“认知积累”的三件事没有做到：
   - 观察层只是“聚类后让 LLM 写一句总结”，没有证据生命周期（增强/削弱/矛盾/失效）、过期观察被物理删除、无法重建；
   - delta 刷新只是把旧答案 + 新记忆交给 LLM **整体重写**，没有 `structured_content` AST 与类型化编辑，无法保证未变更段落不变；
   - reflect 是**一次性 LLM 合成**：无条件注入全 bank 心智模型 + 全部观察，没有三层优先级、没有 staleness 路由、没有“心智模型命中即免合成”的快路径，空库也照样调 LLM。

3. **三个主函数的使用存在明确的契约错误，不是“参数调优”问题**：
   - `retain` 的写入路径没有把目标会话的 `user:/group:` 标签写入 unit，而注入侧 `recall` 先按标签硬过滤 → **`.ai memo add`/`memory_add` 默认参数写进去的记忆，列表能看见、注入永远看不见**（实验 K）；
   - `recall` 默认 `tagsMatch='any'`、语义通路无相似度下限、backfill 按写入顺序（最旧优先）兜底、结果可重复 ID（同一观察最多出现 3 次）；
   - `reflect` 的心智模型不按 `scopeTags/factTypes/createdAfter` 过滤，`reflect` 返回不持久化 provenance。

4. **命令层能用，但离“易于用户使用”有距离**：`.ai memo` 共 12 个二级动作、3 层帮助、范围参数 `--u/--g` 语义重载；ID 是 6 位随机串且列表没有序号；`clear`/`obs clr` 不可恢复却无确认；`obs on/off` 是装饰性开关；README 命令表仍是已废弃的 `[p/g] st` 语法。详细见第五节。

5. **架构差距判定：不做全模块重写，做“认知层重写（v3）”**。理由：bank/storage/retain 原语/四路召回/RRF/注入缓存这些下层骨架与 Hindsight 对齐且可用；差距集中在观察层、心智模型层、reflect 三块，恰好是三个可独立替换的模块。继续在现有字符串答案 + 同步 unit 上打补丁，会同时留下“observation unit 双份”“delta 软重写”“reflect 一次性合成”三条并存路径，必然冗余。方案见 `01-认知层重写方案.md`：**保留 bank/存储/召回原语，重写观察/心智模型/reflect 与读写契约，净代码量目标为负**。

### 2.2 可作为重写依据 / 不应照搬

**可作为依据**：三层分离（原始事实 / 观察 / 心智模型）、原始事实 append-only、观察的 evidence + proofCount + 保守合并、心智模型 `sourceQuery/content/trigger/tags/maxTokens/structuredContent/reflect_response/history`、delta 类型化编辑 + AST 逐字节保证 + 回退条件 + 空内容保护、tags 双重门控（默认 all_strict）、consolidation 后按 tag 重叠刷新、reflect 三层优先级与 staleness 路由、四路召回 + RRF + rerank 失败回退 + token 预算。

**不应照搬**：PostgreSQL/pgvector/Oracle、异步后台 worker 与分布式锁、CARA 的 opinion 网络与 disposition 参数、webhook/MCP server/bank 模板、384 维固定 embedding、按 bank 的完整 REST API。这些是服务端产品能力，与 SealDice 单进程 JSON 存储场景不匹配；插件应保留“可注入 embedding、同步/准异步巩固、单 JSON bank”的裁剪。

## 三、当前实现与 Hindsight 对照

| 层 | Hindsight | 当前插件 | 判定 |
|---|---|---|---|
| Bank 隔离 | 每 Agent/用户一个 bank | `user_<session>` / `group_<session>` / `global_*`（`bank_resolver.ts:14`），agentName 不参与 bankId | ✅ 基本对齐；多角色共享记忆（设计待确认） |
| 原始事实 | append-only，不合并，无文本相等检查 | `retain` 精确文本（trim/lower/去空白）命中即合并：并 tag、覆盖 metadata/importance、`accessCount++`（`engine.ts:181-193`） | ❌ 违反 append-only；实验 A |
| 事实抽取 | LLM 抽原子事实 + 时间/实体/关系 | 默认 `verbatim=true`；`MEMORY_LLM_EXTRACT` 只在归档路径二次抽取，工具/命令/媒体路径永远 verbatim | ❌ 配置语义与实现不符 |
| 多索引 | 向量 + BM25 + 实体图 + 时间区间 | 向量（cosine 内存扫）、关键词（子串 + char n-gram，非 BM25）、实体图（entityIds + links 1-3 跳）、时间（中文相对词） | ◐ 四路形态在，索引是朴素实现；无阈值/无全局预算 |
| 融合 | RRF → cross-encoder/LLM rerank → budget | RRF → 可选 aux LLM rerank（失败回退）→ token 预算 | ✅ 形态对齐；细节缺陷见 4.3 |
| 观察 | 独立 network；evidence + proof_count（去重源事实数）；保守 merge；不删除；矛盾改写 | 独立 `observations[]`，但**同时**同步一条 `factType=observation` 的 MemoryUnit 参与召回；evidence/proofCount/history 有；90 天未验证直接物理删除；相似度 0.8 char-gram 合并；无矛盾/增强语义 | ❌ 双份存储 + 不可逆删除 + 过度合并 |
| 心智模型 | `source_query` + content + trigger + structured AST + `reflect_response` provenance + `last_refreshed_source_query` | `question` + `answer` 字符串 + `triggerConfig` + watermark + history；无 AST/provenance/source query 漂移检测；delta=整段重写 | ❌ 缺 delta 的核心保证 |
| reflect | agentic 循环、三层优先级、staleness 信号、按预算下探 | 一次函数调用：全 bank ready 模型 + 全部观察 + recall 事实 → 一次 LLM；无条件 | ❌ 不是 agentic，也不是“优先心智模型” |
| tags | 双重门控，默认 all_strict；`tags_match`/`tag_groups` | `scopeTags` 单层；refresh/inject/recall 全部 `some`（any）；无 `tags_match` | ❌ 安全/召回边界与默认值不同 |
| 巩固触发 | 后台 consolidation；前后按 tag 重叠刷新模型 | 归档时同步 consolidate；仅命令/工具 consolidate 后才刷新模型 | ◐ 归档路径的“巩固后自动刷新”实际不触发 |
| 遗忘 | 不做单条 eviction，合规才删；invalidation 可恢复 | 默认 cap=100，超限按覆盖/衰减物理删除；stale 观察物理删除 | ❌ 方向相反；实验 F/J |
| 读取 | 心智模型 boot 时直接加载 content（零 LLM） | 注入路径直接读模型文本（零 LLM） | ✅ 对齐（但 reflect 路径不利用这一点） |
| reflect 结果 | `reflect_response` 持久化，驱动心智模型刷新 | `basedOn` 只在返回值里，不落库 | ❌ 无 provenance/审计 |

### 5.2 典型任务旅程

1. **“记住一件事”**：`.ai memo add 西瓜` → 回复“已添加<id>” → 但注入侧看不到（R1）。用户会认为“AI 没记住”，无从排查。
2. **“看看记住了什么”**：`.ai memo list` → 输出 `1. [a1b2c3] 文本`。没有时间、没有标签、没有“这条会不会被注入”，且观察同步 unit 混在长期记忆里；翻页只能 `--page` 或页码参数。
3. **“删掉记错的”**：`list` 复制 6 位随机 ID → `delete <ID>` → 直接物理删除，无确认；如果误删的是 observation 同步 unit，观察表里仍留一条幽灵观察。
4. **“让 AI 总结对某人的印象”**：`.ai memo mm add 这个用户的偏好是什么？` → 同步 LLM 生成，等待数秒无“处理中”反馈；生成失败时返回“暂为占位：生成中…”并提示“积累记忆后自动生成”，但归档路径不会自动刷新（O5），用户等不到。
5. **“关掉观察记忆”**：`.ai memo obs off` 回复“已关闭”，实际注入照旧（I5），用户以为隐私/成本已关闭。
6. **“清空重来”**：`.ai memo clear` 直接清空，无 `--yes`，与 `.ai ctx purge --yes` 的安全习惯不一致。

## 六、架构差距判定：是否需要重写

**判定：不做“全模块从零重写”，做“认知层重写 + 读写契约修复”（v3），保留 bank/存储/召回原语。**

依据：

1. **对齐的部分不要动**：bank 隔离（`bank_resolver`）、JSON 分片存储（`storage`）、四路召回形态 + RRF + rerank 回退 + token 预算（`engine.recall`/`scoring`）、注入缓存与 revision（`prompt_cache`/`revision`）、固定模板播种（`templates`）。这些与 Hindsight 思想一致，重写只会引入回归。
2. **偏离的部分不是“参数问题”，而是数据模型问题**：
   - observation 被复制成 MemoryUnit 参与召回（双份数据 + 双份注入 + 删除不同步）；
   - mental model 的 `answer` 是纯字符串，没有 AST，因此 delta 只能整段重写；
   - reflect 没有工具循环与 staleness 信号，无法“先读心智模型，必要时下探原始事实”；
   - tags 是单层 any 过滤，无法表达 Hindsight 的 all_strict 读取边界；
   - 物理删除 + 无 invalidation，使“证据链”与“可恢复性”不成立。
   在这些前提上打补丁（比如给 answer 加一个可选 AST 字段、在 reflect 里加几个 if 分支、给 observation 单元加删除同步），会形成**字符串路径与 AST 路径并存、observation 单元与观察表并存、旧 reflect 与新 reflect 并存**的三重冗余，正是用户要求避免的“过多冗余代码”。
3. **重写范围可控**：需要替换的是 `reflection.ts`（约 100 行）、`mental_models.ts`（约 430 行）、`consolidation.ts`（约 180 行）与 `engine.ts` 的 recall/retain 段落，以及 4 个门面/命令/工具文件；`repository`/`storage`/`scoring`/`prompt` 保留并按新类型小改。预计净减代码。
4. **迁移可行**：现有 bank 的 `observations[]`/`mentalModels[]` 可直接映射到 v3；observation 同步 unit 丢弃；心智模型 answer 包成单 section AST；旧 `question/answer` 字段保留只读别名。

详细方案见 **`01-认知层重写方案.md`**。核心承诺：
- 原始事实 append-only；观察仅有 evidence 与 proofCount，不复制为 unit；
- 心智模型 = `sourceQuery + content + structuredContent AST + trigger + provenance`，delta 用类型化操作 + 未命中段落逐字节复用；
- reflect = 有预算的 agentic 三层循环，staleness 路由，新鲜心智模型快路径；
- tags 双层门控（refresh 默认 all_strict，读取独立可见性）；
- 删除而非新增路径：删掉 observation 单元、精确合并、preferObservations hack、死配置/死参数与重复门面。
