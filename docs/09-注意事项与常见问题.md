## 运行与部署注意事项

- SealDice v1.4.6 分离部署(napcat/llonebot)下图片相关功能存在问题,建议 v1.5.0+。
- `run_core_command` 需要启动 `ob11-core-bridge` 并在「后端」配置「核心桥WS地址」直连其 `/plugin` WebSocket（SealDice 正向连接 `/core`）；`run_ext_command` 在插件内**本地直调扩展 `solve`**，无需中间件/MCP。核心指令白名单使用 `core|指令名`，但 `core|ext` 无需加入白名单即可查看扩展。两条路径都复用多消息收集器（空闲窗口 + 最大消息数 + 超时）。
- ob11 相关工具(发消息、取用户/群信息、禁言、打卡等)需要安装 ob11 网络连接依赖或 HTTP 依赖;未安装时相关工具返回"未找到ob11网络连接依赖"。
- **⚠️ 5.0 破坏性升级注意(模型配置 v4 → v5)**:「模型」页的「api连接」「模型规则」**两个 TOML 框已废弃**——两个配置项已注销、UI 上不再出现,插件**不再读取**它们,也**不做自动迁移**。原因是海豹的 `seal.ext` 没有配置写入 API,"读旧→转换→**写新**"的第三步永远做不到,兼容垫片只能退化成每次启动跑一遍、旧配置删不掉、用户也看不到转换结果。**升级后请用[配置生成器](https://error2913.github.io/aiplugin4-config/)重新生成一份 JSON 粘进「模型配置」**(或按 README「模型」章手写);不重建的话插件会载入出厂 DeepSeek 示例并打 WARN 提示,原有模型全部不可用。字段对照:`api_key`→`providers[].apiKey`、`base_url`→`providers[].baseURL`(必填、不再兜默认值)、`provider`→通常不用填(由 `baseURL` 的 host 自动识别)、`models`→`providers[].models[]`(`{id, name, kind}`)、`[types]`→`models[].kind`、`ignore = 1`→`providers[].enabled = false`、`[request]`→`providers[].request`(连接级)或 `models[].request.request`(模型级)、规则的 `use` 组→顶层 `purposes` + `groups`、规则的 `[body]/[params]/[prompt]/[response]` 与 `models` 定向→ `models[].request.{body,params,prompt,response}`
- **⚠️ 5.0 另一处行为变更(视觉不再按命名猜测)**:模型类型里**只有视觉不再自动推断**——`gpt-4o`、`gemini`、`qwen-vl`、`*vision` 这类名字**不会**被认成视觉模型,一律归 `text`。原因是一批正则最容易过期(新模型名永远追不上),且猜错会让用户误以为模型已具备视觉能力。要识图必须在「模型配置」里显式写 `"kind": "vision"`(配置生成器会自动预填);接口自报的能力位(`vision`)仍作正向证据。嵌入/生图/语音/reranker 仍按命名白名单推断。
- **4.24.0 升级注意(语音/生图依赖移除)**:生成音频(tts)与生成图片(tti)依赖插件已废弃,完整包不再附带(只留 ob11 网络连接)。请**卸载旧的 tts/tti 依赖插件**——插件不再读取 `globalThis.tts` / `globalThis.tti` / `globalThis.aiDrawing`。语音合成与文生图改由「模型」页**模型配置**声明(给模型写 `kind: "tts"` / `"gen"` 即进入 `tts` / `image-generation` 用途候选):**请求结构由插件内置的供应商预设提供**(逐条迁移自旧依赖插件的 MODELS.md,覆盖 OpenAI/硅基流动/智谱/百炼/Google Cloud/Gemini/MiniMax/FishAudio/ElevenLabs/火山方舟/腾讯 TokenHub/Stability/百度/本地自建等),所以**一般什么都不用写**——只在接口与预设不一致时才写该模型的 `request.body`(默认逐键合并,`bodyMode: "replace"` 改回整体替换)或 `request.request`/`request.response`(逐键覆盖);命令入口由旧的 `.tts` / `.tti` 改为 `.ai tts` / `.ai tti`,并有 `.ai media` 查看/取消任务队列。注意 `baseURL` 推荐填**根地址**(如 `https://api.siliconflow.cn/v1`),完整接口地址也能用(已以预设路径结尾时不再重复拼接)。
- **「ai语音使用的音色」下拉的归属(易误解)**:该下拉服务的是**协议端自带的 AI 语音**(NapCat/Lagrange 的 AI 语音 API,角色名如小新/猴哥/妲己),**与插件 TTS 无关**;这条链路本就无需配置模型,现在 AI 直接用 `call_ob11_api` 调 `get_ai_characters`(查角色,取 `character_id`)/`send_group_ai_record`、`send_private_ai_record`(发送)/`get_ai_record`(只取语音 URL),用法与常见角色名见默认知识库 ob11-api。下拉里的「自定义」选项对应的才是插件 TTS 链路(当年需额外的 tts 依赖 + ffmpeg),现已内置:内置预设里已经带 `{voice}` 占位符,改该模型 `request.params.voice` 的 `default` 或按次传 `--voice`(命令)/`voice`(工具参数)即可。两者互不影响,协议端不支持这些 action 时改走 `generate_audio`。
- 中间件捕获消息默认转发到协议端；若希望 AI 内部执行且不打扰真实 QQ，需在工具参数中设置 `capture.forward=false`。海豹核心连接 `/core`，协议端由中间件出站主动连接（WebUI「⚙ 配置」填地址，重启生效），插件通过 `/plugin` WebSocket 调用。纯 OB11 没有 trace_id，同一群并发动作可能返回 `ambiguous=true`；中间件已按群/私聊 lane 串行化，并以空闲窗口、最大消息数和超时结束收集。
- 简单配置(开关/数值/单行字符串/纯字符串数组)修改后自动生效(缓存最多 1 分钟,无需重载 JS);复杂配置(模型「模型配置」、触发/忽略正则、评分触发、角色扮演设定、MCP 总开关与服务器、技能、知识库、本地资源路径、音乐服务)启动时解析一次、常驻内存,修改后需重载 JS 才生效(其中「MCP服务器配置」「技能配置」「知识库」三类也可用 `.ai mcp refresh` / `.ai skill refresh` / `.ai kb refresh` 立即生效)。
- 嵌入输出维度取自该模型 `request.body` 的 `dimensions`(默认 1024,须与后端一致,如 text-embedding-v4 为 1024);未配置维度时记忆检索自动降级为关键词/分数检索、知识库检索自动降级为关键词匹配(嵌入仅作候选重排,加载知识库本身不请求嵌入)。
- 流式输出需要自建或使用公共后端,并在"后端 → 流式输出"配置 URL;在 chat 用途组 `groups[].body` 里设 `stream = true` 的模型才会走流式(`anthropic-messages` 协议不支持,会自动回退非流式)。
- 模型类型判定顺序:**`models[].kind` 显式声明** → 命名终值(reranker/生图/语音/嵌入白名单) → 接口自报能力位(vision/embed) → 兜底纯文本。⚠️ **视觉不在自动推断之列**:网关自命名模型(如 `my-embed-1`)与视觉模型(如 `inhouse-vl`、`gpt-4o`、`gemini`)都要在「模型配置」里显式写 `kind`(取 `text`/`vision`/`embed`/`gen`/`tts`),否则会被当纯文本模型、甚至被选为默认对话模型。非 OpenAI 兼容的语音/生图服务(如 Google Cloud TTS)没有 `/models` 列表,需把模型写死在 `models` 里声明 `kind` 才能接入。
- `请求超时时限` 同时约束模型请求与工具调用,过小会导致长回复/慢工具超时。**语音/图片生成不受此限**:它们是异步任务,提交后立即返回,HTTP 超时由该模型 `request.request.timeout`(或连接级 `request.timeout`)控制,因此慢出图(SD 等)不会被工具层 180s 截断。
- **4.25.0**:AI 调 `generate_audio` / `text_to_image` 时**先等一段同步窗口**（「工具 → 媒体生成同步等待秒数」,默认 5 秒,0=关闭）——窗口内出结果就把结果**当场返回给 AI**（图片给 `[img:图片ID]`、语音给 record 段发送指引）,不再走异步通知;超时才返回任务号,生成完由通知链路唤醒投递。命令 `.ai tts` / `.ai tti` **不走**该窗口（始终由插件直接投递）。若把该值调大,AI 的这轮响应会相应变慢,但省掉一次唤醒与模型调用;调成 0 则一律走异步。
- **4.25.0 媒体送达的三段式（改动该链路时必须保持）**:工具来源的媒体结果必须满足"要么已呈现给 AI、要么仍在 `noticeQueue` 待呈现",不得两头落空。三段缺一不可:① 入队（带 `taskId`,`notified` 只在真正被消费时回置）;② 会话忙则 defer,不假定"本轮 flushNotices 一定会注入";③ `Agent.run()`/`runStream()` 的 `finally` 里 `resumePending()` 之后调用 `MediaTaskManager.wakePendingNotices()` 补触发。详见 [03-核心模块详解](03-核心模块详解.md) 的硬约束说明。
- **4.26.0 上下文成本治理的配置与行为变化**:待机群（会话待机或全局待机）的普通消息入库改为**冷态零 LLM**（只追加 + 纯代码截断，不再每条消息压一次）；归档 / 窗口移出改为**只写一次的分片**（`read_raw kind=user id=arc:序号` / `id=raw:序号` 回查），`.ai forget --all` 可清空；记忆结算改为按「结算水位 + 空闲 / 转冷」触发。新增 `.ai ctx` / `.ai ctxset` / `.ai tk use`，以及「上下文」页的冷态窗口字数、冷态单条截断字数、归档保留原文、窗口上限字数、结算水位 / 最小门槛 / 空闲门槛 / 单次结算调用上限、原文分片保留天数 / 上限、待机入库配额等配置。注意：**「单次结算调用上限」限制的是分片数，不是 LLM 调用数**；冷态阈值改为**连续 10 分钟**无相关活动才转冷（详见 [14](14-会话冷热态与上下文成本治理方案.md)）。
- **4.26.0 联网搜索**:新增「联网 → 联网配置」（v1 JSON，可接 10 家 provider + generic，**留空 = 内置 SearXNG**，开箱可用）；旧「后端 → 联网搜索」配置项已删除、不再读取；`web_search` 参数与新增的 `web_fetch`（正文 Markdown、`start_index` 续读）见 README「联网」章。坏 JSON / 校验失败只记日志、本次不生效（不抛异常、也不回退默认）；修改后需重载 JS 生效（详见 [18](18-联网搜索与抓取接入方案.md)）。

## 常见问题排查

### 不回复 / 触发不生效

按以下顺序检查:

1. 日志级别设为"调试",观察触发日志(`trigger reply: ...`)与请求日志。
2. 检查"触发正则表达式"与"触发需要满足的条件"(豹语表达式)是否命中;触发条件命中为 1 才触发。
3. 检查"触发次数上限/补充间隔"(令牌桶),桶为空会跳过回复(`bucket empty, skip reply`)。
4. 检查消息是否被"忽略正则"或"忽略消息豹语条件"拦下(日志有 `忽略` 字样)。
5. 检查消息是否含白名单之外的 CQ 码类型(`CQ_TYPES_ALLOW` 之外的 type 不处理)。
6. 确认模型配置可访问:url/API Key/模型名正确、余额充足、支持工具调用。

### 回复中的字面量 \n 没有换行

AI 回复中的字面量 `\n` 或 `\r\n` 会在发送前转换为真实换行；如果需要发送多条独立消息，使用 `\f` 作为分隔符。代码块或示例中的 `\n` 也按此规则转换。

### 工具调用失败

- 查看日志中的 `调用函数失败:` 原因:未注册/未经许可/参数缺失/类型不符/会话类型不符/超时等。
- 用 `.ai tool` 查看开关状态,`.ai tool help <函数名>` 查看参数,`.ai tool call <函数名> --参数=值` 手动试用。
- 工具在"禁止调用的函数"列表中时无法开启;新会话中"默认关闭的函数"需要 `.ai tool on <函数名>` 手动开启。

### 记忆/知识库检索不到

- 记忆检索:确认已有嵌入模型可用(「模型配置」里有 `kind: "embed"` 的模型,且 `.ai model text-embedding` 已绑定或存在可用默认),该模型 `request.body.dimensions` 与后端输出一致(默认 1024),且"启用长期记忆"开关打开;检索有内置相似度下限(0.8)过滤,条目太旧(衰减)或相似度过低不会展示。模型名无法被自动识别为嵌入时(网关自命名),在「模型配置」里显式写 `"kind": "embed"`。
- 知识库:"启用知识库记忆"开关打开后,内容来自"知识库"配置(Markdown 模板,每条一份完整文档,`#` 条目标题、`##`/`###` 小节,超长自动分块);不按角色加载,修改配置后需重载 JS 生效,可让 AI 通过 knowledge_search / knowledge_read 工具检索验证;嵌入未配置时自动降级为关键词匹配,不影响基本检索。

### 语音/图片生成不生效

按以下顺序检查(4.24.0 起为内置能力,与对话模型同一套连接):

1. `.ai model tts` / `.ai model image-generation` 查看该用途候选与当前模型:为空说明「模型配置」里没有 `kind` 为 `tts` / `gen` 的模型(命名白名单未命中时显式写 `kind`)。
2. 先看 vendor(由 `baseURL` 的 host 自动识别)是否在**内置预设**覆盖范围内(README「媒体用途」表):在范围内就不用写任何请求覆盖,只填连接 + `kind` 即可;不在范围内(例如文心一格生图、自建服务)才需要在 `request.body` 里自行描述结构。预设里没有的 vendor 一律按 OpenAI 兼容处理。
   - 百度短文本语音合成已内置(`baseURL` 为 `tsn.baidu.com` 时识别为 `baidu`):它是 `access_token` 鉴权,而连接只有 `apiKey` 一个密钥字段,故约定 `apiKey` 填 `"APIKey:SecretKey"`(冒号分隔,密钥含冒号用 `\:` 转义),插件按连接换取并缓存 `access_token`(30 天、带 5 分钟提前量、同一连接不重复换);直接填 `access_token` 也支持。该服务无 `/models` 列表,`models` 里要写死一个模型并声明 `kind: "tts"`。
   - 百度返回**失败时仍是 HTTP 200**,靠 `Content-Type`(成功以 `audio` 开头、失败为 `application/json`)区分,业务错误在 `err_msg`(`err_no` 取值不固定,故只取 `err_msg`),预设已配 `error_message_path = "err_msg"`,故失败会显示百度的原始原因而不是"未找到音频数据"。
3. **语音报"当前运行时无法读取二进制响应体"**:该接口是「整个响应体即音频流」(OpenAI 兼容 `/audio/speech`、百度、阿里 CosyVoice 等),而海豹的 JS 引擎(goja)的 fetch 只有 `text()`/`json()`,没有 `arrayBuffer()`,且 `text()` 会按 UTF-8 解码把音频字节替换成 U+FFFD 永久损坏——所以必须由后端代读。启动 aiplugin4-backends 的 **`media-fetch`** 后端(默认端口 46679),并在「后端 → 媒体转base64」确认地址即可。**返回 JSON 的接口不受影响**(MiniMax 走 `data_path=hex`、Google Cloud 走 `audioContent`、绝大多数生图接口),不需要该后端。
4. 检查 `request.body` 的占位符是否写全:`{text}`/`{prompt}` 是正文,`{model}` 是模型名;`request.response.data_path` 指错会报"响应中未找到音频/图片数据",整响应即音频时留空 `data_path` 并设 `data_type = "base64"`。
5. 用 `.ai media` 看队列状态与失败原因;`.ai tts 测试` / `.ai tti 测试` 可绕过 AI 直接验证。
6. 参数不生效时检查该参数是否真的出现在**最终模板**(预设或你的 `request.body`)的 `{占位符}` 里——**只有模板里出现的键才接受覆写**,其余一律忽略(这是刻意的:让模型不支持的参数不会污染请求)。
7. 地址不对时优先不用改请求覆盖:`baseURL` 填根地址即可(如 `https://api.siliconflow.cn/v1`);确实要换地址再写 `request.request.url`(绝对地址)或 `request.request.urlSuffix`(`urlSuffix = ""` 表示 `baseURL` 原样即接口地址)。

### AI 调工具生成的语音/图片"没动静"(没有自动发出来)

AI 侧(`generate_audio` / `text_to_image`)完成后的行为是**确定的**:① 把完成通知写入会话队列(这步先做且不会因后续失败而丢);② **直接触发一轮对话**投递(不判断忙/待机/全局待机——这是用户请求的结果送达,不是主动搭话)。命令侧(`.ai tts` / `.ai tti`)由插件**直接投递**,不经过 AI。日志按模块标签 `[media]` 过滤即可看到每一步:

- `媒体任务 #N 完成，触发会话 <sid> 起一轮对话` → 已起新对话,AI 该在下一轮发出;
- `媒体任务 #N 直接投递失败:...` → 协议端离线/端点异常,结果仍在任务队列(可用 `.ai media` 看),下一轮对话会呈现;
- `媒体任务 #N 通知/触发对话失败(结果仍在任务队列,可用 media_tasks 查看):...` → 同上,`run` 侧出错也不丢结果。
- 该触发**免触发令牌桶**(桶空也送达),所以"触发次数上限"导致的不发言已排除;若仍不发,查 `chat` 是否被 `.ai stop` 中止或模型侧报错。
- 若 AI 收到了通知却发不出去:`[audio:xxx]` 只认「资源」页配置的本地语音资源名,**生成结果的路径/URL 要用 `call_ob11_api` 的 record 段**;图片用 `[img:图片ID]`,且该图片必须已注册进 `Image.imageMap`(任务落地时会自动 `Image.save`)。

### 图片识别异常

- 确认图片 URL 可在浏览器访问(过期或 QQ 图床 bug 时更换协议端版本)。
- 模型不支持 QQ 图床时,把"识别图片时将url转换为base64"设为"总是"或"自动"。
- 图片转文字依赖视觉模型:先在「模型配置」里给视觉模型显式写 `"kind": "vision"`(⚠️ 视觉**不再**按模型名自动识别,`glm-4v`/`gemini`/`pixtral` 这类名字也不会被自动认成视觉模型),再用 `.ai model image-understanding <模型>` 绑定。
- **图片直链失效不会再卡死会话**:QQ 直链的 rkey 过期(图床返回 `download url has expired`,后端与模型都拿不到图)时,插件会把这些图片降级为 `[img:ID]` 文本标签,不再产生 image_url,模型也就不会因"下载图片失败"整轮 400;日志里出现 `图片xxx的URL已确认不可用` 或 `[model-error] 模型无法下载上下文图片` 即为此场景,属于正常兜底。
- 若**历史上下文**里已留下坏图片(如旧版本遗留)导致该会话一直不回复,执行 `.ai forget` 清上下文后即可恢复(新版会自动把这类图片降级,不再需要手工清理)。

### HTTP 请求出错

- 日志中的 `请求失败! 状态码: xxx` 对照 HTTP 错误码与大模型文档排查;常见原因:url 填错、API Key 错、模型名错、不支持工具调用、余额不足、请求频繁。

### 待机群相关(上下文成本治理)

背景:待机群里所有群聊消息会累积进**同一条** user 消息块;旧版本每来一条消息都会重判"整块是否超过「消息压缩阈值」",超过就调一次压缩智能体——群里越热闹花钱越多,哪怕机器人一句话都没说。现在改为**冷态入库零 LLM**。

- **为什么待机群不再"每条消息都压缩"?**
  待机(会话待机或全局待机)且无在途对话时,消息只追加 + 纯代码中段截断,`compression` 调用为 **0**(用 `.ai ctx` 的"本会话调用:压缩"确认)。压缩只发生在热态,且遵守三条规则:同一批只尝试一次(含失败)、只压尾部连续未压缩段、结果必须比原文更短才采纳。若你确实想要压缩,用 `@` 让会话转热即可。

- **怎么看花了多少钱?**
  `.ai ctx`(权限 U)显示:当前冷/热状态、预算与冷态窗口、上下文条数与估算 token、归档分片数、本会话 `compression`/`summarization`/`judge` 调用次数、全局用途用量与缓存命中。全局分模型用量仍看 `.ai tk`。

- **归档分片怎么清?**
  归档出来的原文写进 `session_<会话ID>:arc:<三位序号>` 分片(只写一次、永不重写)。`.ai forget` **只清上下文,不碰分片**(分片是留档,供 `read_raw` 回查)。分片数量上限默认 200,超出时最旧的分片会被置空。按会话清理分片用 **`.ai forget --all`**(清空本会话 arc/raw 分片并重置结算水位,不影响已沉淀的长期记忆);分片 TTL 见「原文分片保留天数」。

- **「归档保留原文」开关怎么用?**
  开(默认):归档时把原文写进分片(`read_raw kind=user id=arc:序号` 可回查)**并**调总结智能体沉淀记忆。关:归档**不留原文、不写分片**(省存储),**但仍然会调总结智能体沉淀记忆**——历史照样进长期记忆,只是之后无法回查原文。注意:关掉它**不会**省钱(总结调用照旧),只省存储。

- **待机群"记不住"更早的内容怎么调?**
  冷态下模型默认只看到最近「冷态窗口字数」(默认 5000 字)的内容,更早内容折叠成纯代码摘要(零 LLM)。调大该值可让模型默认看到更多;设 0 = 不折叠(注意会直接抬高每轮 token)。消息里出现"它/这个/刚才/继续"这类指代词时会自动升档多装一段,"总结/回顾"这类明确要求回顾的则不折叠。更早的原文可让 AI 用 `read_raw` / `grep_raw` 回查。
