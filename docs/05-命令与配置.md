# 05 - 命令与配置

> 本章命令语法均来自 `src/cmd/sub_cmd/` 当前源码;README 命令手册会随发版同步,如与 README 不一致以本章为准。

## `.ai` 命令体系

根命令 `.ai`(`AI` 大写同样注册),子命令别名经 `ALIAS_MAP` 归一(常用:`priv→privilege`、`ses→session`、`st→set`、`ck→check`、`clr→clear`、`sb→standby`、`memo→memory`、`p→private`、`g→group`、`tk→token`、`y→year`、`m→month`、`lcl→local`、`ran→random`、`lst→list`、`rm→remove`)。支持 `--page=<数字>`(别名 `--p`)翻页;`.ai help <一级子指令>` 或 `.ai <一级子指令> help` 可查看对应子命令帮助(后者带更多参数时交由子命令自身处理,如 `.ai tool help <函数名>`)。

### memory 子命令

> 行为、数据模型与排障见 [13-记忆系统](13-记忆系统.md)；本节只列命令语法与范围/权限。完整命令/配置表以本节为准，工具表见 [04-工具系统](04-工具系统.md)，记忆实现细节以 13 为准。

```text
.ai memo status                         # 状态(事实/观察/模型/backlog/后台队列)
.ai memo add <内容>                     # 添加事实;--shared 跨群,--private 仅本人
.ai memo list [页码]                    # 事实列表(#N 可代替 ID)
.ai memo update <ID|#N> <新内容>        # 更新事实
.ai memo delete <ID|#N> ... [--关键词] [--hard]  # 默认软失效;--hard 物理删除仅骰主
.ai memo clear --yes                    # 清除(必须 --yes)
.ai memo obs on/off                     # 会话级观察开关
.ai memo obs list                       # 观察列表
.ai memo obs view <ID>                  # 观察详情(证据/证据数/历史)
.ai memo obs clr --yes                  # 清除观察并把源事实重置为待巩固
.ai memo obs refresh                    # 立即抽取当前上下文并巩固(手动;裸 obs 等价)
.ai memo consolidate                    # 立即巩固
.ai memo reflect <问题> [--deep]        # 心智模型优先推理
.ai memo mm list                        # 心智模型列表
.ai memo mm view <ID>                   # 模型内容/状态/触发方式
.ai memo mm add <问题> [答案] [--tag=xx] [--mode=full|delta] [--auto|--no-auto]  # 无答案则排队生成
.ai memo mm refresh [ID]                # 手动刷新(绕过自动门控)
.ai memo mm clear <ID>                  # 清空并排队 full 重建
.ai memo mm del <ID|问题关键词>          # 删除模型
```

范围: 默认当前会话(私聊=个人,群聊=当前群); `--u` 本人、`--g` 当前群、`--self` 本体(仅骰主); `--u=<ID>`/`--g=<ID>` 跨目标(仅骰主),三者不能同用。可见性: 个人事实默认 `owner`(仅本人私聊),群聊默认 `public`(仅本群); 跨群必须显式 `--shared`; 迁移的旧个人事实统一收紧为 `owner`。权限: memo 普通用户可用(`U`),`obs on/off` 需会话权限 1(`S`),`--self`/跨目标/`--hard` 仅骰主。

### tool 子命令

```text
.ai tool                            # 工具组概览(组名 + 工具数 + 开/关统计)
.ai tool <组名>                      # 查看组内工具与开关状态(等价 --group=<组名>)
.ai tool <函数名>                    # 查看工具详情与参数(等价 help <函数名>)
.ai tool all                        # 扁平列出全部工具(含技能/知识库)
.ai tool on|off [<组名|函数名>]      # 开关整组或单个工具;无参=全部工具(on/off 需邀请者以上)
.ai tool help <函数名>               # 查看工具详情与参数
.ai tool call <函数名> --参数=值     # 试用工具(call 需骰主),参数可尝试 JSON 解析
```

工具组 = 内置工具的 16 个能力分类（基础调度/指令/定时/触发/记忆/图片/多媒体/OB11/资源/属性/原文检索/上下文编辑/黑名单/网页/公开会话/子代理，外部插件注册的工具归「外部插件」）+ 每台 MCP 服务器各一组；组内计数只统计当前平台可用工具，`禁止调用的函数` 中的工具不参与统计与开关。

解析优先级：`--group=<组名>` 显式指定 > 函数名（精确命中即单工具，行为不变）> 组名精确命中（分类名或 MCP 服务器名）> 唯一包含匹配；`on/off/help/call/list/all` 为保留字，组名与它们撞名时用 `--group=`。

`on/off` 不带参数=全部工具；**关闭时默认跳过核心常驻工具**（`list_tools`/`search_tools`/`list_mcps`/`call_tool`/`use_skill`/`call_ob11_api`/`run_ext_command`/`run_core_command`），避免一键关掉 AI 的工具发现与执行入口，确需一并关闭加 `--force`；开启时跳过 `禁止调用的函数`。`.ai mcp on/off <服务器>` 与 `.ai tool on/off <服务器>` 等价（同一批量开关实现）。技能与知识库不参与工具组维度，其会话开关用 `.ai skill on/off`、`.ai kb on/off`，但单工具开关照旧可用（如 `.ai tool off use_skill`）。

## 权限体系

### 用户权限等级(PRIVILEGE_LEVEL_MAP)

| 等级 | 数值 | 说明 |
| --- | ---: | --- |
| blacklist | -30 | 黑名单用户 |
| user | 0 | 普通用户 |
| inviter | 40 | 邀请者 |
| admin | 50 | 群管理员 |
| owner | 60 | 群主 |
| whitelist | 70 | 白名单用户 |
| master | 100 | 骰主 |

### 命令权限(CmdPrivInfo)

每个命令/子命令有一个三元组 `[会话所需权限, 会话检查通过后用户所需权限, 强触所需权限]`:

- 用户权限来自 `ctx.privilegeLevel`(SealDice),会话权限来自 `session.setting.priv`。
- 通过规则:会话权限 ≥ 第 1 项 **且** 用户权限 ≥ 第 2 项;或用户权限 ≥ 第 3 项(强触)。
- 支持 `*` 通配与多级嵌套(子命令可再挂子命令)。
- 预置常量:`U = [0,0,0]`、`M = [0,100,100]`、`I = [0,40,40]`、`S = [1,40,100]`。
- 自定义权限持久化在 `cmdPriv` 存储键,`.ai priv reset` 可恢复默认;`priv` 命令本身不可被修改权限。

## 配置分组总览

配置在 SealDice WebUI 的插件设置中按分组展示，键名与 `configs/*.ts` 注册时一致（分组顺序见 `src/config/config.ts` 的 `configMap`；解析/应用分离机制见 [03-核心模块详解](03-核心模块详解.md) 的配置系统）。常用配置的实际键名：

| 分组 | 常用键名 | 说明 |
| --- | --- | --- |
| 基础 | 日志级别、请求超时时限、请求并发上限、请求队列上限、是否开启全局待机 | 全局开关 |
| 模型 | 模型配置 | **一份 JSON（v5）**，取代旧的两个 TOML 框（「api连接」「模型规则」已注销、不再读取，也不做迁移——海豹的 `seal.ext` 没有配置写入 API，"读旧→转换→写新"的第三步做不到；详见 [09-注意事项与常见问题](09-注意事项与常见问题.md) 的升级注意）。顶层：`version`（固定 5，必填）、`providers`（至少 1 项，必填）、`purposes`（用途 → 模型 id 的**有序数组**）。`providers[]`：`api`（必填，`openai-completions`/`anthropic-messages`/`openai-responses`）、`baseURL`（必填，须 `http(s)://` 开头，**不再兜默认值**）、`apiKey`（必填，明文）、`provider`（vendor 标识，**通常不填**，由 `baseURL` 的 host 自动识别，仅当识别失败且该地址代理某家原生接口时才手工指定）、`models`（**留空/不写 = 启动时自动拉取**；无 /models 接口的语音/生图服务如 Google Cloud TTS 就把模型写死在这里）、`enabled`（默认 true；false = 忽略该连接，取代旧的 `ignore = 1`）、`displayName`、`timeout`（秒）、`request`（连接级覆盖：list_url/auth_header_name/headers/timeout 及 balance_url/balance_json_path/balance_divisor/balance_currency）。`providers[].models[]`：`id`（**全局唯一**，被 `purposes` 引用）、`name`（发给 API 的真实模型名，可含 `.` `:` `/`，**不需加引号**）、`kind`（`text`/`vision`/`embed`/`gen`/`tts`/`decision`，**取代旧的 `[types]` 表**；`decision` 只能绑 `judge`、固定走 `{baseURL}/systemone`）、`contextWindow`、`maxTokens`、`request`（**per-model** 覆盖：`body`/`request`/`response`/`params`/`prompt`；其中 `bodyByUse` 是「用途 → 请求体」逐模型覆盖，空 = 用插件默认）、`bodyMode`（`merge`/`replace`，与内置预设的合成方式）。`purposes` 是有序数组：优先用列出的、按此顺序，首选失效自动往后切；留空取该用途首个可用模型。用途取 `chat`/`summarization`/`judge`/`image-understanding`/`text-embedding`/`tts`/`image-generation`（`compression` 已移除；旧配置里残留的 `compression` 会在解析期自动忽略并打 WARN，**无需重建配置**）。媒体用途（tts/image-generation）**默认走内置供应商预设**（按 vendor + 模型名给出原生结构，只填连接 + `kind` 即可用）：不写 `request.body` 时用预设结构，写了默认**整体替换**预设结构（`bodyMode: "merge"` 改为逐键合并）并用 `{占位符}` + 嵌套表描述该供应商的请求体结构；`request.params` 声明 AI 可覆写参数（default/min/max/enum/type/desc，优先于预设自带默认），`request.prompt.extra` 写自由提示词，`request.request`/`request.response` 逐键覆盖预设的地址与取数路径/轮询。**请求体默认值**：对话/总结/评分/识图默认 `{"max_tokens": 65536, "temperature": 1}`（原样发送，超过模型上限由服务商拒绝，用户自担）；旧 `groups[]` 已在 4.30.0 移除，配置里残留会被忽略（不报错、不迁移）。**校验失败整份拒绝**（不做部分生效）并一次报出全部问题（带 `$.providers[0].models[1].name` 式路径）。`.ai model` ### 模型配置 JSON 示例

「模型」分组下只有一个 JSON 配置项：

```json
{
  "version": 5,
  "providers": [
    {
      "api": "openai-completions",
      "baseURL": "https://api.deepseek.com/v1",
      "apiKey": "sk-xxxx",
      "models": [
        { "id": "flash", "name": "deepseek-v4-flash", "kind": "vision" },
        { "id": "pro",   "name": "deepseek-v4-pro",   "kind": "text" }
      ]
    }
  ],
  "purposes": { "chat": ["flash"], "summarization": ["flash"], "judge": ["flash"] }
}
```

- `providers[].models` **留空/不写 = 启动时自动拉取**该连接的模型列表（OpenAI 兼容 `GET /models`；`anthropic-messages` 走 `/v1/models` 自动翻页），失败按连接降级展示（auth/无列表接口/超时）不影响其它连接；离线或无列表接口的服务（Google Cloud TTS 等）就把模型写死；
- `models[].kind` 取 `text`/`vision`/`embed`/`gen`/`tts`/`decision`，**取代旧的 `[types]` 表**。`decision` = System One 决策模型（阿里 `decision-model-preview` / Jev `jev-latest`），只能绑 `judge`，请求固定 `POST {baseURL}/systemone`，不参与对话/总结。⚠️ **视觉不再按模型名猜测**：`gpt-4o`/`gemini`/`qwen-vl` 这类名字不会被自动认成视觉模型，要识图必须显式写 `"kind": "vision"`；嵌入/生图/语音/reranker 仍按命名白名单推断；
- `purposes` 可填 `chat`(普通对话)/`summarization`(记忆总结)/`judge`(评分插话判断)/`image-understanding`(识图)/`text-embedding`(嵌入)/`tts`(语音合成)/`image-generation`(文生图)，值是**模型 id 的有序数组**；`compression`(消息压缩) 已随压缩智能体一起移除，旧配置里的 `compression` 会在解析期自动忽略并打 WARN；
- 逐模型「用途 → 请求体」覆盖写在 `models[].request.bodyByUse`（键 = 7 用途之一，值 = 该用途在该模型上的请求体；空 = 用插件默认；优先级高于代码默认，媒体用途继续用下面的 `request.body`/预设）；
- 媒体用途的 per-model 覆盖写在 `models[].request` 里（`body`/`request`/`response`/`params`/`prompt`）：`request` 可选 `method`/`url`/`urlSuffix`/`headers`/`content_type`/`auth_header_name`/`timeout`（`url` 为绝对地址，`urlSuffix` 拼在 `baseURL` 之后，`urlSuffix = ""` 表示 `baseURL` 原样；媒体用途的 `request`/`response` 是逐键覆盖预设，`poll_*` 写在 `request` 也接受）；
- **模型类型判定顺序**：`models[].kind` 显式声明 > 命名终值（reranker/生图/语音/嵌入白名单） > 接口自报能力位 > 兜底纯文本。`decision` 只能靠显式声明（不猜），且只进 `judge` 候选。模型按类型进各用途候选：`text`/`vision` 进对话候选（`vision` 另进识图候选）、嵌入白名单（如 `text-embedding-*`/`bge-*`）进嵌入候选、生图白名单（`dall-e`/`gpt-image`/`wanx`/`flux`/`stable-diffusion` 等）进生图候选、语音白名单（`tts-*`/`*-tts`/`cosyvoice`/`fish-speech` 等）进语音候选、reranker 不进任何候选。默认模型按「运行时覆盖 > 配置绑定（有序）> 该用途首个可用」三层解析；想换用 `.ai model <用途> <模型>`。嵌入输出维度取该模型 `request.body.dimensions`（默认 1024），配置后长期记忆与知识库启用语义检索，未配置/不匹配自动降级为关键词检索。
