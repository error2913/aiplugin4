# 07 - 开发指南

## 环境与常用命令

```bash
npm install         # 安装依赖
npm run build       # 生产构建 → dist/aiplugin4.js(头部拼接 header.txt)
npm run build-dev   # 开发构建 → dev/aiplugin4.js(带 sourcemap)
npm run smoke       # 冒烟:在 Node 中用 seal 桩加载 dist/aiplugin4.js
npm run lint        # ESLint 检查 src/**/*.ts
```

构建说明(`tools/build.js` + `tools/build-config.js`):

- 使用 esbuild,入口 `src/index.ts`,target 为 es6(生产)/es2020(dev),`external: ['csharp','puerts']`。
- 产物输出到 `dist/aiplugin4.js`,并把 `header.txt`(UserScript 注释)拼到文件头部。
- 生产构建不做压缩(minify=false),保持可读、便于用户自行查错。

冒烟测试(`scripts/smoke.js`):用 `seal` 桩(Proxy 兜底所有方法)在 Node 中 `require('../dist/aiplugin4.js')`,可在没有 SealDice 的环境下提前发现加载期 `ReferenceError`/`TypeError`。改完核心逻辑建议 `npm run build && npm run smoke`。

## 代码组织约定

- 核心逻辑放在 `src/` 对应模块目录,`src/index.ts` 只做装配,事件处理统一走 `src/pipeline.ts`。
- 持久化类需要定义 `static validKeysMap`,并用 `revive()` 恢复(见 [06-数据存储](06-数据存储.md))。
- 新增消息级能力优先考虑做成"工具"而非写死在命令里,便于 AI 通过函数调用使用。
- 模板文案(如 prompt)放配置模板,不要硬编码在业务逻辑中。

## 添加一个工具

1. 在 `src/tool/tools/` 下新建文件(或放入已有分类目录),导出一个 `registerXxx()` 函数。
2. 创建 `new Tool({ type:'function', function:{ name, description, parameters } })`,实现 `solve(ctx, msg, session, args)`,返回字符串给 AI。
3. 可选配置:`sessionType`(group/user)、`sensitive`(敏感标记)、`ExtCmdInfo`(调用海豹内置指令)。
4. 在 `src/tool/tool.ts` 的 `Tool.registerTool()` 中导入并调用注册函数。

示例:

```typescript
// src/tool/tools/tool_say.ts
import Tool from "../tool";

export function registerSay() {
    const tool = new Tool({
        type: "function",
        function: {
            name: "say_hi",
            description: "打招呼",
            parameters: {
                type: "object",
                properties: {
                    arg1: { type: "string", description: "说点什么" }
                },
                required: ["arg1"]
            }
        }
    });
    tool.solve = async (_ctx, _msg, _session, args) => {
        return `你好，${args.arg1}`;
    };
}
```

```typescript
// src/tool/tool.ts 的 registerTool() 中
import { registerSay } from "./tools/tool_say";
registerSay();
```

## 添加一个配置分组

1. 在 `src/config/configs/` 下新建文件,定义类,实现 `register()`(用 `seal.ext.registerXxxConfig` 注册)与 `get()`(读取并返回类型化对象)。
2. 在 `src/config/config.ts` 的 `configMap` 中登记该分组。
3. 使用处直接 `Config.<分组>.<字段>` 读取(带缓存)。

可用注册函数:`registerTemplateConfig`(多行文本/模板)、`registerStringConfig`、`registerIntConfig`、`registerFloatConfig`、`registerBoolConfig`、`registerOptionConfig`(下拉)。

## 添加一个子命令

1. 在 `src/cmd/sub_cmd/` 新建文件,导出 `registerCmdXxx()`,创建 `new SubCmd('name')`。
2. 设置 `desc`/`help`/`priv`,实现 `solve(scc: SubCmdContext)`,返回 `ret`。
3. 在 `src/cmd/root_cmd.ts` 的 `SubCmd.register()` 中调用注册函数。
4. 如需要子参数权限,在 `priv.args` 中按命令链嵌套声明。

`SubCmdContext` 提供:ctx、msg、cmdArgs、epId、uid、gid、sid、session、page、ret。

## 添加一个智能体

1. 在 `src/agent/agents/` 新建文件,导出 `init()`,内部用 `Agent.get(name)` 获取实例并配置 name/description/instruction/use。
2. 在 `src/agent/agents/index.ts` 的 `initAgents()` 中调用。
3. 若需要独立的模型用途(如 `compression`、`summarization`),在模型配置的 `use` 列表中登记对应模型;用途匹配失败会回退到 `chat` 模型。

## 修改 prompt 模板

- 模板在 `src/config/configs/prompt.ts` 中定义默认值(注意改动需要同时更新默认注册内容,WebUI 中"刷子"可还原默认)。
- system prompt 的分节组装逻辑在 `src/prompt/builder.ts`,新增节时需要同步修改模板骨架与构建函数。
- 记忆/知识库/工具段的开关在 `src/memory/manager.ts` 与 `src/config/configs/memory.ts`。

## 发布流程

`.github/workflows/`:

- `build-check.yml`:main 分支 push / PR 时执行 lint、tsc strict、构建并校验 sealpack(`npm run package:check`)、冒烟测试。
- `release.yml`:推送 `v*` 标签时自动发版——verify(校验标签与 `VERSION`/`update.ts` 一致)→ 打包 `.sealpack` → 用 `SEALPACK_TOKEN` 发布 SealRepo → 从 `src/update.ts` 提取版本日志作为 GitHub Release 正文,附带 `aiplugin4-v<版本>.sealpack` 与 `dist/aiplugin4.js`。

打包源 `sealpack/`:`scripts/main.js` 与 `info.toml` 版本由 `scripts/prepare-sealpack.js` 自动同步;包图标放 `sealpack/assets/icon.png`;SealRepo Token 放 GitHub Actions secrets(`SEALPACK_TOKEN`)。

发版前记得同步:`src/config/static_config.ts` 的 `VERSION`、`header.txt` 的 `@version`、`src/update.ts` 的 `updateInfo`(且需包含新版本条目)。

## 开发小贴士

- 日志统一走 `Logger`(脱敏/截断),不要直接 `console.log` 明文密钥。
- 涉及网络请求统一走 `withTimeout` + `fetchData`/`requestModel`,避免请求卡死。
- 修改会持久化的类字段后,检查其 `validKeysMap` 是否需要同步更新。
- 新增工具名不要与已有工具重复;敏感操作(发消息/禁言/改名)记得置 `sensitive = true`。
