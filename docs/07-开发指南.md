# 07 - 开发指南

## 环境与常用命令

```bash
npm install                 # 安装依赖
npm run build               # 生产构建 → dist/aiplugin4.js（头部拼接 header.txt）
npm run build-dev           # 开发构建 → dev/aiplugin4.js（带 sourcemap）
npm run smoke               # 冒烟：Node + seal 桩加载 dist/aiplugin4.js
npm run lint                # ESLint 检查 src/**/*.ts
npx tsc --noEmit            # 类型检查（直跑 tsconfig，不要加 --strict 覆盖严格选项）
npm run test:unit           # 单元测试（esbuild 打包 scripts/unit-test-entry.ts 等入口）
npm run test:ob11           # OB11 runtime 模拟（原生兜底/异常/特殊段/资源引用/发送降级）
npm run test:integration    # 跨仓库联测：配置生成器产出 → 插件 v5/domain 解析（无生成器仓库时 SKIP）
npm run sim                 # 上下文成本治理端到端模拟（代码路径级，14 项）
npm run sim:matrix          # 消息顺序/时序矩阵（90 组顺序×预算 + 时序/状态/边界，76 项）
npm run fuzz                # 随机化长跑（确定性 PRNG，可 FUZZ_SEEDS/FUZZ_ROUNDS 回放）
npm run package:check       # 构建 + 同步 sealpack 源 + 包格式与体积校验
npm run deps:check          # 依赖边界 ratchet（环/跨层/动态 import/复活删除边）
npm run deps:update         # 收紧依赖基线（恶化需 --allow-grow 并在 PR 说明）
npm run version:check       # 版本号单一事实源校验
npm run version:sync        # 按 meta.ts VERSION 回写其它版本位置
npm run changelog:check     # changelog 数据文件 ↔ 聚合索引一致
npm run changelog:gen       # 按数据文件重新生成聚合索引 src/changelog.ts
npm run domain:check        # 默认值生成物（config/domain/default_data.ts）一致
npm run domain:gen          # 从默认值源重新生成 default_data.ts
npm run docs:manifest       # 文档清单（docs-site/manifest.js ↔ docs/ccdocs/磁盘 ↔ mkdocs nav）
npm run docs:build          # 构建文档站点（需 mkdocs）
```

## 验证体系

- **单测/模拟/fuzz**：`test:unit`（真实模块 + seal 桩）、`sim`/`sim:matrix`/`fuzz`（真实 `Context`/`Session`/`handleMessages` + 假存储/假模型）都是代码路径级验证，能抓回归但不能替代真机（覆盖不到真实厂商 API 请求体校验、goja storage 行为、QQ 消息形态与多会话并发时序）。`fuzz` 曾抓到「tool 结果与发起它的 assistant 不相邻」的真实 400 bug，改上下文/工具配对后必跑。
- **测试环境单一事实源**：`scripts/harness/seal-env.cjs` 统一维护 seal 最小桩与 `__TEST_CONFIG__`，`test-unit`/`sim`/`sim:matrix`/`fuzz`/`test:ob11` 通过 `installSealEnv({preset, ...})` 复用（`preset` 决定初始配置与模板默认值，差异项用参数覆盖）。新增 seal API / 配置读取语义只改这一处，不要往各 harness 内联桩里加。
- **依赖边界**：`deps:check` 用 esbuild metafile 提取真实运行时图，Tarjan 求 SCC，按 `scripts/deps-baseline.json` ratchet（最大 SCC/环内数只能降、基线外文件入环、新增跨层依赖、新增动态 import、复活删除边、未分类文件均拒绝）。架构调整后跑 `deps:update` 收紧；新增目录必须在 `scripts/lib/deps.mjs` 的 `LAYER_RULES` 配层。
- **单一事实源校验**：版本号、changelog、默认值、文档清单、测试桩各有 `*:check` 脚本（见上），CI 中全部执行。
- **行为不变量**：配置键/存储键/`validKeysMap` 语义、模型侧工具错误文案、sim 的 LLM/存储统计与改造前一致；改动先补行为测试。

## 构建与产物

- esbuild（`tools/build.js` + `tools/build-config.js`）：入口 `src/index.ts`，target es6（生产）/es2020（dev），`external: ['csharp','puerts']`；产物 `dist/aiplugin4.js`，`header.txt` 拼到头部；生产不做压缩（minify=false），保持可读。
- 冒烟（`scripts/smoke.js`）：seal 桩（Proxy 兜底）在 Node 中 require 产物，提前发现加载期 `ReferenceError`/`TypeError`。改核心逻辑后建议 `npm run build && npm run smoke`。
- 豹包：`scripts/prepare-sealpack.js` 同步 `sealpack/scripts/main.js` 与 `info.toml` 版本；`package:check` 调 `sealpack validate/size`。

## 代码组织约定

- `src/index.ts` 只做装配，事件处理统一走 `src/pipeline.ts`；业务逻辑放对应模块目录。
- **依赖只向下**（L0 基础 → L1 纯逻辑 → L2 能力 → L3 领域 → L4 装配，见 [02-架构设计](02-架构设计.md)）；低层不得 import 高层。
- 宿主能力走 `getHost()`（storage/clock/fetch），不直接调 `seal.*` / `ext.storage*`。
- 双向协作拆到 `src/core/ports/`：双方各自注册一半，不互相 import；实现是动态委派，不要缓存函数引用。
- 配置「解析」放 `config/configs/`，「应用」放 `config/apply/` + `hooks.ts`，组合根注册；解析函数不要直接调实现。
- 大文件按「叶子模块」拆分：每个文件单一职责、显式依赖；被拆出的原 API 保留同名委派/`re-export`，外部 import 零改动。
- 持久化类必须定义 `static validKeysMap` 并用 `revive()` 恢复（见 [06-数据存储](06-数据存储.md)）。
- tsconfig 已启用 `noImplicitThis`：普通函数里不要用 `this`（需要时显式标注 `this: Host`）；`noUnusedLocals`/`noUnusedParameters`/`noImplicitReturns` 开启。
- 日志统一 `logger`（脱敏/截断），不要 `console.log` 明文密钥；网络请求走 `withTimeout` + `fetchData`/`requestModel`。

## 添加一个工具

1. 在 `src/tool/tools/<分类>/` 新建文件，导出 `registerXxx()`。
2. `new Tool({ type:'function', function:{ name, description, parameters } })`，实现 `solve(ctx, msg, session, args)`，返回字符串给 AI。
3. 可选：`sessionType`（group/user）、`sensitive`、`platforms`、`group`。调用扩展指令用 `run_ext_command`（现场构造 `CmdArgs`，不依赖历史指令或 `.r`）。
4. 在 `src/tool/tools/init.ts` 的 `registerTools()` 中调用注册函数（`src/tool/bootstrap.ts` 的 `registerAllTools()` 统一装配）。
5. 注册批次用 `Tool.withCategory('分类', () => { ... })` 包裹，保证工具组正确。

```typescript
// src/tool/tools/tool_say.ts
import Tool from "../tool";

export function registerSay() {
    const tool = new Tool({
        type: "function",
        function: {
            name: "say_hi",
            description: "打招呼",
            parameters: {
                type: "object",
                properties: { arg1: { type: "string", description: "说点什么" } },
                required: ["arg1"]
            }
        }
    });
    tool.solve = async (_ctx, _msg, _session, args) => `你好，${args.arg1}`;
}
```

```typescript
// src/tool/tools/init.ts
import { registerSay } from "./tool_say";
registerSay();
```

## 添加一个配置分组

1. `src/config/configs/` 新建文件，实现 `register()`（`seal.ext.registerXxxConfig`）与 `get()`（读取并返回类型化对象）。
2. 在 `src/config/config.ts` 的 `configMap` 中登记（顺序即配置页签顺序；「错误处理」固定最后）。
3. 使用处 `Config.<分组>.<字段>`（60s 缓存）。可用注册函数：`registerTemplateConfig`（多行文本/模板）、`registerStringConfig`、`registerIntConfig`、`registerFloatConfig`、`registerBoolConfig`、`registerOptionConfig`（下拉）。
4. `registerTemplateConfig` 默认值不能传空数组，至少保留一个元素；纯占位可用 `['']`。
5. 若配置需要「应用到实现」，在 `src/config/apply/` 写应用函数并在 `hooks.ts` 注册。

## 添加一个子命令

1. `src/cmd/sub_cmd/` 新建文件，导出 `registerCmdXxx()`，创建 `new SubCmd('name')`。
2. 设置 `desc`/`help`/`priv`，实现 `solve(scc: SubCmdContext)`，返回 `ret`。
3. 在 `src/cmd/bootstrap.ts` 的 `registerSubCommands()` 中调用（顺序不可调换：根命令 help 与默认权限依赖 `SubCmd.map` 已填满）。
4. 子参数权限在 `priv.args` 按命令链嵌套声明。`SubCmdContext` 提供：ctx、msg、cmdArgs、epId、uid、gid、sid、session、page、ret。
5. `.ai <子指令> help`（无更多参数）由根命令内置处理；需要处理更多参数时（如 `.ai tool help <函数名>`）在 `solve` 内自行处理。新增子命令必须填写 `cmd.help`。

## 添加一个智能体

1. `src/agent/agents/` 新建文件，导出 `init()`，用 `Agent.get(name)` 获取实例并配置 name/description/instruction/use。
2. 在 `src/agent/agents/index.ts` 的 `initAgents()` 中调用。
3. 模型用途：`Agent.use` 决定 `Model.getChatModel(use)`；压缩/摘要/judge 与 chat 共用文本/视觉候选链，需要其它模型时用 `.ai model <用途> <模型>` 绑定。

## 拆双向依赖 / 新增模块

- 双向协作：在 `src/core/ports/` 定义端口接口，A 注册「提供给 B 的能力」、B 注册「回调 A 的能力」，双方只 import 端口，不互相 import。
- 新增子系统：建 `src/<模块>/` 目录与 `index.ts` 导出；在 `scripts/lib/deps.mjs` 补 `LAYER_RULES`；跑 `npm run deps:check`。
- 拆分大模块：纯逻辑先下沉（无宿主依赖），再抽实例无关的服务类（宿主回调注入），最后保留原类同名方法委派；每步跑全量验证。

## 修改提示词

- 4.29.0 起 system prompt 由**英文段注册表**组装，不再有大模板：内置段在 `src/prompt/sections/`，文案在 `src/prompt/texts/en.ts`（唯一来源，禁止中文提示词）；协议标记/包装/`[system:<name>]` 在 `src/utils/protocol.ts`（L0 叶子）。
- 新增/调整段：在 `sections/` 实现并登记（order 槽位见 `.dev/docs-archive/18-系统提示词重构与英文化方案.md` 4.7；`channel` 选 system（稳定）或 runtime（每轮易变）；`cache.deps` 必须覆盖全部输入；`sanitize:'external'` 仅用于用户/外部数据段）；`sections/index.ts` 汇总注册。
- 段级缓存 key 形如 `sect:<name>|<deps>`；记忆/总结写入后经 `src/memory/revision.ts` 失效 `sect:core:memory|` 前缀。
- 辅助提示词（记忆抽取/观察/反思、判分、子代理、识图）不在 system 段内，位于各自模块；修改后同样必须英文（用户内容/服务器返回文本除外）。
- 记忆/知识库/工具段开关在 `src/memory/manager.ts`、`src/prompt/memory_source_impl.ts` 与对应配置分组。
- 快照对比：`npm run prompt:snapshot` 用测试宿主装配 group/private 两种会话，输出 system/runtime/段统计到 `test-reports/prompt-baseline/<时间戳>/`（不连真实海豹；改段后对比 digest 与段字符数）。

## 为其他插件提供 API（globalThis.aiplugin4）

启动时挂载（幂等，重载不重复覆盖），海豹所有 JS 插件共享同一全局环境。调用前先判空以兼容本插件未安装。

| 成员 | 说明 |
| --- | --- |
| `name` / `version` | 插件名与版本号 |
| `Agent` | `Agent` 类，可自行 `get/save` |
| `getAgent(name?)` | 获取智能体实例（默认 `*`） |
| `getSession(agentName, sessionId)` | 获取指定智能体的会话 |
| `chat(prompt, agentName?, options?)` | 单轮对话：不经会话上下文与工具，直接返回文本。**默认不解析 `[img:]`**；`options.allowImages=true` 时才把 user 文本里的图片标签转成图片块 |
| `chatMessages(messages, agentName?, options?)` | 发送 OpenAI 风格 `messages` 数组，返回文本。**默认不解析图片**；`options.allowImages=true` 时 user 文本里的 `[img:]` 才转图片块（非 user 消息里的图片块始终清洗为文本） |
| `imageToText(source, prompt?)` | 识图：图片 id 或 http(s) 地址，返回描述 |
| `embed(text)` | 嵌入向量（未配置嵌入模型返回空数组） |
| `run(ctx, msg, options?)` | 触发一次完整编排（上下文/工具/回复发送），等价收到一次触发 |
| `registerTool(info, options?)` | 注册工具；同名内置不可覆盖，成功返回 true |
| `registerPromptSection(section)` | 注册提示词扩展段（`ext:<插件>:<名>`、order ≥10000、channel system/runtime；单段 ≤2000 字符、合计 ≤4000；默认外部清洗），成功返回 true |
| `onPromptAssemble(fn)` | 注册组装 hook，可整体改写 `{system, runtime}`（按注册顺序执行） |

`run` 的 `options`：`agentName`（默认 `*`）、`reason`（默认「外部插件调用」）、`toolChoice`。`registerTool` 的 `options`：`sensitive`、`sessionType`（any/group/user）、`callBack`（结果是否写回并继续生成，默认 true）、`solve`。`registerPromptSection` 的 `section`：`{ name, order?, channel?, maxChars?, build(ctx) }`（`build` 返回空串表示不可见）。

```javascript
const api = globalThis.aiplugin4;
if (!api) return; // 本插件未安装

const reply = await api.chat('用一句话介绍你自己');
// 需要模型看 prompt 里的 [img:] 时显式开启（默认不解析）：
const visionReply = await api.chat('看看 [img:img_xxx]', undefined, { allowImages: true });
const reply2 = await api.chatMessages([
    { role: 'system', content: '你是翻译助手' },
    { role: 'user', content: '翻译：hello' }
]);
const desc = await api.imageToText('https://example.com/a.png', '画面里有什么？');
const vec = await api.embed('要检索的文本');
await api.run(ctx, msg, { agentName: 'kp_agent', reason: 'KP插件调用' });

api.registerTool({
    type: 'function',
    function: {
        name: 'my_tool',
        description: '示例工具：把传入的 text 原样回显',
        parameters: {
            type: 'object',
            properties: { text: { type: 'string', description: '要回显的内容' } },
            required: ['text']
        }
    }
}, { solve: async (_ctx, _msg, _session, args) => `回显: ${args.text}` });
```

`chat` 是无状态单轮；需要多轮上下文、工具调用或主动回复聊天窗口时用 `run`（受请求并发限制与令牌桶约束）。仓库内示例插件 [`examples/use-aiplugin4.js`](../examples/use-aiplugin4.js) 可直接加载体验；示例插件的扩展必须 `seal.ext.register(ext)` 否则指令不进海豹指令表。

## 文档维护规范

`docs/` 是**稳定知识库**，不是设计草稿区。硬性规则：

1. **方案/审查/实验/临时分析禁止放进 `docs/`**：统一放 `.dev/`（已 gitignore）、PR 描述或 issue；实现完成后只把最终行为并入既有 `02/03/04/05/06/09`，不新增“方案/计划/复盘/审查”章节。
2. **不新增插件架构之外的二级章节**：`docs/03-核心模块详解.md` 的 `##` 章节必须对应 `src/` 的实际模块；不得为某个临时功能插入额外 `##` 章节。内容优先并入对应模块章节。
3. **文档结构统一**：新增/删除 `docs/*.md` 必须同步 `docs/README.md`、`docs-site/manifest.js`、`docs-site/mkdocs.yml`，并跑 `npm run docs:manifest` / `docs:build`；不登记、不在 nav 的文档视为非法。
4. **行为变更同步**：命令/配置/工具/存储/架构改动分别同步 05/03/04/06/02；只在现有章节更新，不靠追加“补充说明”章节。
5. **排障与验收**：临时日志/实验数据放 `.dev/`；需要长期保留的排障结论并入 09 的对应条目。
6. **主模块文档保留**：01-11、13（记忆系统）对应实际插件模块，保持现有编号/章节；所有 `*-方案.md` 设计稿移至 `.dev/docs-archive/`，`docs/` 不再保留方案文件。

## 完成检查清单

发布前必须同步：

1. `src/changelog/<版本>.ts`：在版本数据文件补充 `- 描述`，再 `npm run changelog:gen` 生成聚合索引（不要手改 `src/changelog.ts`）；发布工作流读取数据文件生成 GitHub Release 正文。
2. `README.md`：同步配置手册/命令手册/可用工具函数等章节。
3. `docs/`：涉及命令/配置/工具/架构的改动同步对应文档（常用 03/04/05/09；架构改动同步 02）；方案/审查/实验一律放 `.dev/`，不进入 `docs/`。
4. 配置项更改（新增/删除/默认值/弃用）在版本数据文件「配置项更改」小节注明；模板等默认值变更在「重要」小节提醒恢复默认。
5. 版本号：`meta.ts` 的 `VERSION` 改完跑 `npm run version:sync`；`sealpack/info.toml` 由 `prepare-sealpack.js` 同步。
6. 文档清单：新增/删除 `docs/*.md` 后更新 `docs-site/manifest.js` 与 `docs-site/mkdocs.yml`，跑 `npm run docs:manifest`；不得新增插件架构之外的二级章节。

## CI 与发布

`.github/workflows/`：

- `_check.yml`：可复用质量门禁（`workflow_call`）——版本/changelog/默认值一致性、lint、`tsc --noEmit`、单测、依赖边界、`package:check`、冒烟；PR 与发版共用，避免两处漂移。
- `build-check.yml`：main push / PR 时调用 `_check.yml`。
- `docs.yml`：文档变更时构建站点并校验清单/链接；push main 时发布 GitHub Pages。
- `release.yml`：推送 `v*` 标签时——先复用 `_check.yml`，再校验标签与 `VERSION`/changelog 数据文件一致 → `scripts/build-release.js` 打包（本体 JS + 本体豹包 + 完整豹包）→ 用 `SEALPACK_TOKEN` 发布两个豹包 → 从数据文件提取版本日志作为 GitHub Release 正文。

完整包依赖插件在 `scripts/deps.cjs` 的 `dependencies` 配置（当前仅 ob11 网络连接依赖）；`sealpack-full/` 为生成目录（已 gitignore）。配套后端独立仓库 `aiplugin4-backends`（见 [08-相关后端项目](08-相关后端项目.md)）。

## 常见问题

- `tsc --noEmit` 报未使用变量/参数：`noUnusedLocals`/`noUnusedParameters` 开启，删掉或显式使用；不要在命令行加 `--strict` 覆盖 tsconfig。
- `deps:check` 报「新增跨层依赖」：低层 import 了高层，改为端口注入或把共享逻辑下沉为叶子；确属有意调整时编辑基线并在 PR 说明。
- `deps:check` 报「未分类文件」：新目录需要在 `scripts/lib/deps.mjs` 加 `LAYER_RULES`。
- 文档校验失败：`docs:manifest` 检查磁盘 ↔ `docs-site/manifest.js` ↔ `mkdocs nav` 三方一致。
- Windows 上编辑含中文的脚本/文档注意编码（UTF-8），避免 CRLF/引号转义破坏文件。
