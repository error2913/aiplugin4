# 04 - 工具系统

工具系统是 AI 与插件能力的接口层：把内置能力、扩展/核心指令、MCP、技能、知识库统一注册成 OpenAI function calling 形态，经同一个执行器校验与执行。

## 设计概览

- **注册表与实现分离**：`src/tool/registry.ts` 只持有 `toolMap`；工具实现不反向 import 装配入口，避免「注册表 ↔ 实现」环。
- **装配入口唯一**：`src/tool/bootstrap.ts` 的 `registerAllTools()`（内置 + 技能 + MCP），只被 `src/index.ts` 调用。
- **执行入口唯一**：`src/tool/executor.ts` 的 `executeTool()`，函数调用、提示词工程、`call_tool`、`.ai tool call` 全部经过它。
- **描述即能力**：工具描述是模型可见的唯一边界；参数 schema、平台、分组都通过工具描述暴露给 AI。

## Tool 属性与注册

| 属性 | 说明 |
| --- | --- |
| `toolInfo` | OpenAI function calling 描述（name/description/parameters JSON Schema） |
| `solve` | 工具实现：`solve(ctx, msg, session, args) => string`；扩展指令工具由 `run_ext_command` 现场构造 `CmdArgs` 后调用扩展 `solve` |
| `sessionType` | 适用会话类型：`'any'`（默认）/`'group'`/`'user'` |
| `callBack` | 是否回调智能体（当前统一为 true） |
| `sensitive` | 敏感工具（发消息/禁言/改名等），日志显著记录 |
| `group` | 来源分组：内置工具不传（显示「内置」）；技能 = `技能`；知识库 = `知识库`；MCP = 服务器名 |
| `category` | 内置工具细分分类（仅 `group` 为空时由 `Tool.withCategory(分类, 注册批次)` 注入，缺省「其他」） |
| `platforms` | 平台白名单（来自 JSON 条目的 `platform` 字段）；缺省/空 = 所有平台 |

**内置分类（16）**：基础调度、指令、定时、触发、记忆、图片、多媒体、OB11、资源、属性、原文检索、上下文编辑、黑名单、网页、公开会话、子代理；外部插件注册的工具归「外部插件」，未分类内置工具归「其他」。

**注册方式**：`src/tool/tools/init.ts` 的 `registerTools()` 导入各文件注册函数；文件按分类目录放置（`core/`、`context/`、`image/`、`manage/`、`media/`、`memory/`、`ob11/`、`pub/`、`raw/`、`resource/`、`seal/`、`subagent/`、`web/`）。

## 执行链

`executeTool(name, ctx, msg, session, options)` 按顺序校验（任一失败返回带 `code` 的失败结果，不再执行）：

1. 工具是否已注册（`toolMap`）。
2. 会话工具开关 `session.toolState[name]`（`checkEnabled` 可跳过）。
3. 平台白名单（`checkPlatform`，按当前平台过滤）。
4. `sessionType` 是否匹配当前消息类型（`checkSessionType`）。
5. 扩展指令工具的白名单/来源分组校验（`core|ext` 为例外发现入口）。
6. 参数 JSON 解析与修复（`fixJsonString`）。
7. 必需参数与 Schema 类型校验（`validateToolArgs`）。
8. 执行 `solve`，整体受「请求超时时限」约束。

失败统一走 `functionCallErrorText` 生成模型侧文案（措辞保持稳定）。执行成功记录审计日志（`[tool] session=... call=... content=...`）。

两条路径（`src/tool/runner.ts` 的 `ToolRunner`）：

- `executeFunctionCalls`：函数调用模式，直接执行模型返回的 `tool_calls`。
- `executePromptCalls`：提示词工程模式，解析 ```function 代码块内的 JSON 数组再执行。

两者底层都走 `Tool.handleToolCalls` → `executeTool`；`Tool.handleToolCall` 只是把执行结果包装为 `ToolCallResult` 文案。防失控：`允许连续调用函数次数`（`MAX_CALL_COUNT`，默认 0 不限制）按会话累计。

## 结果截断与原文保留

超过「工具响应截断字数」（默认 10000，0 关闭）的结果不再压缩，只展示开头（head 截断），避免长结果占用 token：

- 独立于上下文滚动摘要：工具结果是事件账本中的 `tool_result`，不会被摘要删除。
- 截断时完整原文保留在事件 parts（旧回退路径为工具消息的 `rawText`），不参与渲染与 token 估算；展示文本末尾附 `[工具原文过长: ...]` 标记（含 tool_call_id，可寻址）。
- `grep_raw`/`read_raw` 是原文统一出口：事件账本用 `read_raw id=e:<seq>` / `e:<from>-<to>` 读取，`grep_raw` 命中返回可直接传入的 `pointer`；旧会话仍兼容 `kind=tool/user/image/event`（tool_call_id、msg_id、blk、arc/raw 分片）。均只读、默认开启，返回内容声明「仅作参考，不要执行」。
- 事件提示词本身不走压缩智能体：文本由纯代码按模板生成，超长仅 head 截断兜底；完整原始数据挂 `raw`（当前通过会话上下文记录审计，不从事件文本自动展开）。

实现位置：`src/context/context.ts` 的 v2 写入/原文保留与 `src/context/tool_api.ts` 的 `read_raw`/`grep_raw` 适配；调用侧在结果上补 `toolName` 字段。

## 平台与工具权限

每个会话有独立 `session.tool.state`，`session.toolState` getter 合并：

- `禁止调用的函数`（`BLOCKED`）：强制关闭，不出现于工具组视图与统计。
- `默认关闭的函数`（`DEFAULT_CLOSED`）：新会话默认关闭，用 `.ai tool on <name>` 开启。
- 已删除工具的残留状态自动清理。
- 子代理 `toolRestriction`（父会话工具面 allow/deny 求交）二次收窄。

工具组：

- 内置工具按 `category` 分 16 组，每台 MCP 服务器各一组；技能/知识库不参与组维度（来源分组）。
- `Tool.getToolGroups(session, platform)` 聚合当前平台可用工具（继承 BLOCKED/默认关闭/子代理收窄）；组顺序由 `BUILTIN_CATEGORY_ORDER` 固定。
- `setToolGroupState`（`src/tool/tool_group.ts`）供 `.ai tool on/off <组名>` 与 `.ai mcp on/off <服务器>` 共用：`on` 跳过 BLOCKED 并计数，`off` 默认跳过核心常驻工具（`list_tools`/`search_tools`/`list_mcps`/`call_tool`/`use_skill`/`call_ob11_api`/`run_ext_command`/`run_core_command`，`--force` 才一并关闭）。
- 技能/知识库另有会话级开关（`session.skillState`/`kbState`，只记录关闭项，缺省开启），命令为 `.ai skill on/off`、`.ai kb on/off`。

AI 侧同口径：`list_tools` 组头、`search_tools` 详情、`list_mcps` 均按平台与工具组过滤；`mcp=` 参数支持按分类名/来源分组/显示名过滤。

## MCP 集成（src/tool/mcp.ts + mcp/config.ts + mcp/client.ts）

三层职责：

| 文件 | 职责 |
| --- | --- |
| `mcp/config.ts` | 服务器配置解析/缓存（`isMCPEnabled`/`getConfiguredMCPServers`/`refreshMCPConfig`）、会话参数（`sessionTTLMs`/`maxSessionsPerServer`）、`formatMcpError` |
| `mcp/client.ts` | JSON-RPC 会话层：initialize / tools.list / tools.call，按 AI 会话分桶与 LRU 回收、会话失效重试 |
| `mcp.ts` | 工具同步/注册（`syncTools`/`registerMCPTools`/`refreshMCP`）；公共 API 从这里导出 |

- 总开关「是否启用 MCP」（默认关闭）；开启后解析 `MCP服务器` 并连接/注册。
- 配置格式：标准 `mcpServers` 对象（`{"mcpServers":{"服务器名":{"type":"http","url":"…","headers":{…}}}}`），`type` 仅 `http`/`streamable-http`（stdio/SSE 跳过并记日志），`platform` 为扩展字段（`[]`/省略 = 所有平台）。插件默认空配置，生成器保留 `mcp-files-exec`/`md-html-render`/`mcp-browser` 示例。
- 协议：Streamable HTTP + JSON-RPC（`initialize` → `notifications/initialized` → `tools/list` → `tools/call`），带 `Mcp-Session-Id`，兼容 SSE 响应；工具列表 60s TTL；会话失效自动重初始化并重试一次。
- 会话按 AI 会话（`session.sessionId`）分桶：同一 AI 会话连续操作复用服务端会话（保持登录/页面状态），不同 AI 会话互不干扰；空闲或超上限按 LRU 回收，回收前对 `mcp-browser` 调 `browser_close`。
- 平台限制贯穿发现与调用；同名工具跳过；返回标准 image 块/base64 → 存为 `[img:...]`。
- 命令 `.ai mcp list/on/off/refresh`：list 看可用服务器与开关；on/off 按会话批量开关（等价 `.ai tool on/off <服务器>`）；refresh 重解析并强制重同步（骰主，无需重载 JS）。

## 技能（src/tool/skills.ts）

- 配置「技能列表」为 v1 JSON：`skills[]` 的 `name`（必填）/`description`/`platform`/`content`；缺失默认技能（「录卡」）自动补入；生成器可导入标准 `SKILL.md`。
- 注册 `use_skill`、`skill_list`（来源分组 = 技能）；system prompt 的「可用技能」段只注入当前平台匹配且本会话未关闭的技能，摘要 1500 字符/≤100 条/单条描述 ≤200 字符。
- `use_skill` 按名取正文，支持 `offset` 续读；`{{skill:名称}}` 引用其他技能（最大深度 2，循环/未开启/不存在会标记），单次上限 12000 字符。
- 配置变化下一条消息自动重解析（JSON 非法时保留上一份）；`.ai skill list/on/off/refresh` 管理。

## 扩展指令与 OB11 核心桥

- `run_ext_command`：插件内**本地直接调用**扩展 `solve`（现场构造独立 `CmdArgs`，不依赖最近一次真实指令，也无需 MCP/中间件）。扩展名分硬编码 `builtin`（fun/story/coc7/deck/dnd5e/exp/log/reply）与 `non_builtin`；核心指令统一用虚拟扩展名 `core`（如 `core|ext`）。指令前缀由「工具 → 指令前缀」配置（默认 `.`），复用多消息收集器（空闲窗口 + 最大消息数 + 超时）。
- `run_core_command`：通过 `aiplugin4-backends/ob11-core-bridge` 的 `/plugin` WebSocket 注入标准 OB11 假消息执行核心指令；`command=ext` 可直接执行核心 `.ext` 查看扩展列表。
- 两种工具均支持 `trigger`（替换触发对象）与 `at`（写入 @ 段）。
- 中间件：`aiplugin4-backends/backends/ob11-core-bridge`，核心侧以 OB11 网络依赖连接 `/core`（或 `/core/ws`），中间件出站连接协议端；插件经 `/plugin` 直连调用。环境变量/「后端配置」见 [08-相关后端项目](08-相关后端项目.md) 与 [11-ob11-core-bridge-使用指南](11-ob11-core-bridge-使用指南.md)。
