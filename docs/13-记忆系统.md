# 13 - 记忆系统（v3）

> 状态：已实现（2026-10-26）。本文是记忆系统的**实现总览**，面向需要理解、排查或修改记忆行为的开发者。
> 实现复核与审计记录：`.dev/memory-audit/`（内部资料，不随仓库分发）；命令与配置细节见 [05-命令与配置](05-命令与配置.md)，存储键细节见 [06-数据存储](06-数据存储.md)。
> 一句话：**事实 append-only → 观察带证据 → 心智模型负责推理**；写入/巩固/刷新全部在后台调度，注入与 reflect 只读。

## 1. 设计目标与边界

### 1.1 目标

| 目标 | 实现方式 |
| --- | --- |
| 三层记忆 | `user_<sid>` / `group_<gid>` / `global_<agent>` 三个 bank 独立存储、独立注入 |
| 不阻塞会话 | AI 轮结束只入队；抽取/巩固/MM 刷新在后台执行；只有命令/工具的手动操作同步等待 |
| 不干烧 token | 无 AI 触发不跑自动任务；空工作不调 LLM；队列去重/合批/预算/熔断 |
| 隐私边界 | `owner` 仅本人私聊；`origin` 仅来源会话；只有 `public` 可跨群 |
| 认知层可演化 | 观察有证据与历史；心智模型有 AST、watermark、失败冷却、full/delta |
| 上下文解耦 | `src/context/**` 不 import memory、不访问 `session.memory` |

### 1.2 非目标

- 不做向量数据库；向量只作为 recall 的语义通路，失败自动降级关键词。
- 不物理删除过期观察；过期只是注入/状态上的派生判断。
- 不保留旧 v1 归档路径的同步记忆写入；legacy 路径已不写记忆。

## 2. 数据模型

### 2.1 三层 bank

| bank | ID | 归属 | 默认可见性 |
| --- | --- | --- | --- |
| 个人 | `user_<sessionId>` | 某个用户 | `owner`（仅本人私聊） |
| 群聊 | `group_<sessionId>` | 某个群 | `public`（仅本群） |
| 本体 | `global_<agentName>` | 某个智能体 | `public`（所有会话） |

`agentName` 为 `*`/空时归一为 `main`（bank `global_main`）；旧 `global__` 在首次读取时惰性改名为 `global_main`。

### 2.2 原始事实（MemoryUnit）

原始事实**只新增，不合并文本**；相同内容按 `contentHash` 去重。字段：

| 字段 | 说明 |
| --- | --- |
| `id` / `bankId` | 事实 ID / 所属 bank |
| `text` | 原子事实文本 |
| `factType` | `world`（世界/属性事实）或 `experience`（经历/事件） |
| `createdAt` / `createdAtSeq` | 创建时间（秒）/ 单调序号（水印与 delta 窗口） |
| `occurredStart/End` | 事件发生时间（可选） |
| `tags` | `user:`/`group:`/`global:` + `vis:` + `src:` + `kw:` |
| `metadata` | `type`、`contentHash`、`supersedes` 等 |
| `importance` | 0–1；淘汰与排序参考 |
| `embedding` | 语义通路向量；可为空 |
| `entityIds` | 实体链接 |
| `state` | `valid` / `invalidated`；纠错用失效，不物理改历史 |
| `consolidationState` | `pending` / `done` |
| `supersedes` | 被本条取代的旧事实 ID |

### 2.3 观察（Observation）

观察是**独立一等公民**，不是 `factType=observation` 的伪事实（v2 的双份存储已删除）。

| 字段 | 说明 |
| --- | --- |
| `text` / `tags` | 观察文本 / 范围 + 可见性标签 |
| `evidence[]` | `{memoryId, quote, addedAt}`；来源事实证据 |
| `proofCount` | 当前有效（valid）来源事实的**去重数**；每次折入证据后重算 |
| `history[]` | `created` / `reinforced` / `refined` / `contradicted` / `merged` 等 |
| `lastSupportedAt` | 最近一次新增/验证证据时间；过期判断依据 |
| `status` | `active` / `invalidated` |

- 过期（默认 90 天无新证据）只影响注入/状态，**不删除观察**。
- `obs clr` 会删除观察并把源事实重置为 `pending`，以便重新巩固。

### 2.4 心智模型（MentalModel）

| 字段 | 说明 |
| --- | --- |
| `sourceQuery` | 写死的模板问题 / 用户自定义问题；刷新时重新推理 |
| `content` | 当前答案（Markdown 文本） |
| `structuredContent` | AST：`sections[].blocks[]`；delta 编辑用 |
| `trigger` | `mode: full\|delta`、`refreshAfterConsolidation`、`factTypes`、`tagsMatch` |
| `tags` / `maxTokens` | 作用域标签 / 单次输出上限（默认 2048） |
| `status` | `ready` / `pending` / `failed` |
| `lastRefreshedAt` / `lastFullRefreshAt` | 时间门控 |
| `lastMemorySeenSeq` | 已见过的最大 fact seq（watermark） |
| `lastRefreshedSourceQuery` | delta 基线校验 |
| `reflectResponse` | 最近一次刷新的 basedOn / skipped 原因 |
| `history[]` | 旧内容快照（最多 10 条） |
| `templateId` | `persona` / `preference` / `rules` / `self_rules` / `self_experience` |

固定模板：个人 `persona + preference`，群聊 `persona + rules`，本体 `self_rules + self_experience`。模板按 `seededMentalModelVersion` 版本化播种；**删除后不会自动复活**，只有模板版本升级才补新条目。

### 2.5 标签与可见性

保留前缀：`user:`、`group:`、`global:`、`vis:`、`src:`、`kw:`。外部/LLM 输入不允许伪造保留前缀；关键词统一加 `kw:`。

| 可见性 | 个人 bank | 群 bank | 全局 bank |
| --- | --- | --- | --- |
| `owner` | 仅本人私聊 | 本群（bank 隔离已限制） | 不允许 |
| `origin:<scope>` | 来源群 + 本人私聊 | 本群 | 不允许 |
| `public` | 本人私聊 + 该用户发言的群 | 本群 | 所有会话 |

默认写入：

| 来源 | 目标 | 默认可见性 |
| --- | --- | --- |
| 私聊抽取 | 个人 bank | `owner` |
| 群聊抽取（`memory_type=private`，个人抽取开启） | 个人 bank | `origin:<群>` |
| 群聊抽取（个人抽取关闭，默认） | 群 bank | `origin:<群>` |
| 群聊抽取（`memory_type=group`） | 群 bank | `public` |
| 手动 `--shared` | 目标 bank | `public` |
| 全局手动/抽取 | 全局 bank | `public` |
| 旧 user bank 迁移 | 个人 bank | 统一收紧 `owner` |

## 3. 写入链路

### 3.1 自动链路时序

```
AI run
  ├─ run 开始：MemoryScheduler.onRunStart（activeAiRuns++）
  ├─ 请求前：agent.settleBacklog -> collectContextBacklog
  │    只读事件账本 -> mem_cursor.pending；0 LLM
  └─ finally（acquired 且非 headless/subagent）
       MemoryScheduler.onRunEnd
         activeAiRuns--
         collectContextBacklog（幂等）
         lastAiActivityAt = now
         无 MEMORY/EXTRACT -> 不入队
         pending 达水位 -> enqueue extract
         meta.pendingFactCount > 0 -> enqueue consolidate（崩溃恢复兜底）

后台 MemoryScheduler（mem_sched_v1）
  extract -> MemoryService.extractFromChunk
       LLM 只输出 facts
       服务层校验/路由/写 bank（不信任模型给的 bank）
       成功后 commitExtraction（清除 pending 前缀、推进 consumed）
       失败不 commit；退避重试/降级
  consolidate -> doConsolidate（事实 -> 观察）
  mm_refresh -> 读取 sourceQuery + 相关记忆 -> full/delta
```

要点：

- **job 只存引用**：`sessionId`、`throughSeq`、`textLength`、`bankId`、`modelId`；原文只在 `mem_cursor.pending`。
- **抽取失败不丢原文**：LLM 无效 JSON/网络错误会抛错，调度器不 commit，pending 保留重试。
- **抽取水位**：`min(Config.context.SUMMARY_WATERMARK, 6000)` token；不足水位不触发自动抽取（`force` 手动路径除外）。
- **手动路径**：命令/工具可直接调服务同步执行；只有这些路径会等 LLM。

### 3.2 抽取与路由

`MemoryService.extractFromChunk` 分两步：

1. **抽取**（`extractFacts`）：只负责调 LLM，要求返回 `{"facts":[...]}`；不写存储。
2. **应用**（`applyFact`）：校验 `text/op/memory_type/visibility/confidence`，按类型路由：

| `memory_type` | 目标 | 备注 |
| --- | --- | --- |
| `private` | 目标用户 bank；群聊默认关闭个人抽取时回退群 bank | 私聊默认 owner；群来源 origin |
| `group` | 目标群 bank；只允许当前群 | 跨群丢弃 |
| `global` | 全局 bank；默认自动关闭；过滤用户引用/低置信/敏感 | 私聊不写 global |

`op=update/delete` 通过 `existing_id` 失效旧事实；`update` 再写新事实并保留 `supersedes`。无效/敏感/跨目标事实记为 dropped，不写库。

## 4. 巩固：事实 → 观察

入口：`doConsolidate`（`v2/consolidation.ts`），每次最多 50 条 pending facts。

1. 按实体/文本相似度聚类（不按 scope 标签硬合并）。
2. 查相关 active 观察（证据交集、文本相似、scope 标签重叠）。
3. 观察决策：`create / reinforce / refine / contradict / merge / noop`；LLM 不可用时回退合成/拼接。
4. 更新证据并重算 `proofCount`（distinct live source facts）；写 `history`。
5. 全部处理完才 `markConsolidated`；失败不推进 pending。

观察不删除；过期只由 `OBSERVATION_STALE_DAYS`（默认 90）在注入/状态中派生。

## 5. 心智模型刷新

`MentalModelService.refreshMentalModels` 的门控顺序：

```
failed 冷却（默认 30min）
  → watermark（scope 内最新 fact seq <= lastMemorySeenSeq 跳过）
  → 最小刷新间隔（默认 0）
  → delta 条件（mode=delta && AST 非空 && sourceQuery 未变 && deltaOps 可用）
  → delta 超过 48h 或条件不满足 → full
  → 空输出/空 delta/无效 delta → skipped/failed，不推进 watermark
```

- **full**：把 scope 内相关心智模型（默认排除其它模型）/观察/事实交给 LLM，重新生成完整答案。
- **delta**：只喂新增事实，LLM 返回类型化操作（`add_section/append_bullet/replace_block/remove_stale_paragraph/replace_section_blocks`）；未命中的 block 逐字节保留；空操作视为失败，不推进。
- **模板 seed**：固定模板创建为 `pending`；首次有来源事实时由调度器排一次 seed 刷新；ready 后不再自动 seed。
- **自动刷新**：默认关闭；开启后只在巩固产生 `touchedTags` 且模型标签重叠/模型无标签时排队；按 watermark/间隔/冷却收敛。
- **失败**：标记 `failed`，30min 冷却；不覆盖旧内容；不推进 watermark。

## 6. 读取链路

### 6.1 recall

`MemoryEngine.recall` 四路召回 + RRF：

| 通路 | 说明 |
| --- | --- |
| semantic | embedding cosine，低于阈值丢弃；无 embedding 自动跳过 |
| keyword | 文本 token/字符 n-gram |
| graph | 实体/语义链接 ≤2 跳，只从候选出发 |
| temporal | 今天/昨天/上月/今年/`YYYY年M月` 等窗口 |

RRF 融合后可选用 LLM rerank；再按新近度加分，按 token 预算截断；`collapseObservations` 时用覆盖该事实的观察替换事实并去重。访问计数只更新实际返回的事实。

### 6.2 reflect

`reflection.reflect`：

1. 找 ready 心智模型并打分；命中「分数≥0.5 且不 stale」→ 直接返回模型内容（**0 合成 LLM**）。
2. 否则收集 scope 内观察 + recall 事实；交给合成器；strict 模式下无证据不 dump。
3. 返回 `text / basedOn / answeredBy`；basedOn 会写入 MM 的 `reflectResponse`。

### 6.3 注入

`MemoryService.buildMemoryPrompt` 的 section 顺序：

1. 当前会话 bank（群或私聊）。
2. 群聊最近发言者 personal bank（≤3 人）。
3. 全局 bank（最后，段预算 300）。

统一由 `v2/prompt.ts` 单渲染器输出：模型 → 观察 → 事实；全局预算（默认 3000 token）、文本去重、过期观察剔除。个人 bank 在群聊中**不注入心智模型**（避免 owner 内容经模型泄露），只注入可见事实/观察。

## 9. 存储与迁移

### 9.1 存储键

| 键 | 内容 |
| --- | --- |
| `memv2:banks` | bank ID 索引（存储无遍历能力，需索引枚举） |
| `memv2:<bankId>:meta` | bank 元信息：kind/agentName/sessionId/schemaVersion/settings |
| `memv2:<bankId>:units` | 原始事实分片 |
| `memv2:<bankId>:links` | 实体/语义/相关链接分片 |
| `memv2:<bankId>:obs` | 观察 + 实体 + 心智模型分片 |
| `mem_cursor:<sid>` | 记忆桥进度：epochStart/consumed/readSeq/offset/pending |
| `mem_sched_v1` | 调度器持久状态：jobs/running/hourly/failureStreak/pausedUntil |
| `memv2:<bankId>:backup:legacy\|v2` | 迁移前备份（幂等，不覆盖） |

`meta.settings` 还维护 `nextFactSeq`、`pendingFactCount`、`lastExtractAt`、`lastConsolidateAt`、`lastAutoRefreshAt`、`seededMentalModelVersion`。

### 9.2 v2 → v3 迁移

`migrate_v3.ts` 在 `repository.getBank` 首次读取时惰性执行（`schemaVersion` 缺失视为 2）：

1. `factType=observation` 的旧 unit 转为观察表，删除同步 unit。
2. 旧 user bank 的事实/观察可见性统一收紧 `owner`；旧 group private 因群 bank 本身已隔离，迁移后仍为本群可见（`public`）。
3. 心智模型：`question→sourceQuery`、`answer→content`、结构化 AST、`trigger` 默认 `full/false`、`maxTokens=2048`、watermark=0；旧 persona 问题改模板。
4. `global__ → global_main` 改名并迁移单元/观察/模型归属。
5. 写 units/links/obs 后最后写 meta（schemaVersion=3）；迁移前备份。

## 10. 调度器与预算

`MemoryScheduler` 的状态机：

```
queued → running → 删除（成功）
queued/backoff → dead（attempts>=3）
queued/backoff → degraded（无效 JSON 等不可重试）
queued → 删除（purge/clear）
重载：running → queued；lastAiActivityAt=0
```

门控：

- **无 AI 不跑**：自动 job 要求 `lastAiActivityAt` 存在且在 30 分钟内；seed/ai 均受此限制。
- **AI 轮内让路**：`activeAiRuns > 0` 时自动 job 推迟；manual 不受限。
- **在线让路**：探测 `requestLimiter.getQueueInfo().active/queued`，不 `acquire` 排队；推迟最多 10 分钟，之后强跑。
- **预算**：后台每小时 LLM 上限（默认 20）；队列上限 200；同 key 合并；manual 提升优先级。
- **熔断**：连续 3 个 job 失败 → 暂停 30 分钟。
- **重试**：1s → 2s 退避，最多 3 次；失败不 commit pending。

调度器空队列即停止；`enqueue` 唤醒；重载由 `MemoryScheduler.init()` 加载并清理 dirty running。

### 12.2 常见现象

| 现象 | 排查 |
| --- | --- |
| `.ai memo status` 一直 pending | 是否有 AI 活动（自动 job 需要 30min 内 lastAi）；`mem_sched_v1` 是否 dead/暂停；LLM 配置 |
| 群聊看不到个人事实 | 检查 `vis:`：owner 不进群；public 才跨群；origin 只来源群 |
| 心智模型一直 pending | 模板无来源事实时不会 seed；先产生事实，或 `mm refresh` 手动；`seededMentalModelVersion` 防复活 |
| 观察不更新 | 事实是否 pending；观察开关；巩固是否被熔断/预算挡住 |
| 注入为空 | 记忆总开关、token 预算、查询是否命中；个人 model 在群聊不注入 |
| 抽取失败 | 看 `mem_sched_v1` job 状态与 pending 是否保留；无效 JSON 会 degraded，不丢原文 |

### 12.3 调试入口

- `MemoryScheduler.status()` / `snapshot()`：队列、running、小时预算、暂停、lastAi。
- `MemoryService.status(bankId)`：事实/观察/模型/backlog/下一次刷新。
- `.ai memo obs view <ID>`：证据、proofCount、历史。
- `.ai memo mm view <ID>`：模型状态/内容/触发方式。
- `mem_cursor:<sid>`：pending 原文与消费水位。
