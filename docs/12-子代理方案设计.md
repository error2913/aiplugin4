# 12 - 子代理（Subagent）方案（定稿 · DSH 对齐）

> 状态：已随 4.22.0 发布实施（`src/agent/subagent/` 11 个文件、`src/tool/tools/subagent/init.ts` 的委派/控制/job 工具、`.ai subagent` 命令、「子代理」配置分组）；下文 §1-§9 为设计正文，与实现的差异见顶部「实施备注」。
> 依据：DeepSeek Harness（DSH）子代理框架（`@deepseek-ai/dsh-subagent*`、`dsh-tool-subagent`、`dsh-tool-subagent-control`、`dsh-jobs-local`/`dsh-tool-jobs`）+ aiplugin4 现有代码（`src/agent/agent.ts`、`src/session/session.ts`、`src/utils/message.ts`、`src/prompt/builder.ts`、`src/tool/tool.ts`、`src/utils/seal.ts`、`src/timer.ts`）。
> 决策基线（已拍板）：工具**全量继承**；完成后**主动续一轮、空回复不发言**；child **落盘持久化**；进程外 provider 本期不做（接缝预留）；全局总开关**默认开**；基础「请求并发上限」默认 **1→10**。
> 关联：`04-工具系统`、`05-命令与配置`、`07-开发指南`、`10-TODO`。
>
> 实施备注（以代码为准，核对于 4.22.0）：
> - 配置实际只有三键（是否启用子代理 / 最大委派深度 / 子代理禁止调用工具，见 `src/config/configs/subagent.ts`）；「记录保留上限 100」是 `store.ts` 硬编码默认，无配置键。
> - 当前实际最多委派 1 层：子代理再委派会被深度限制拒绝（`limits.ts`），「最大委派深度」>0 等价于允许主会话委派。
> - child system 只注入 persona/默认指令 + 工具引导句（`wiring.ts`/`child_system.ts`），不含父记忆/知识库/时间节。
> - `run_in_background` 后台 job（`job_*`）完成后**不**投 notice，结果由 `job_output` 收取；结算通知（[system:子代理] 入父 noticeQueue、可唤醒空闲父会话）只发生在可续跑/前台结算路径。
> - `.ai stop` 与 `.ai subagent stop <ID>`/`interrupt_agent` 只中断当前轮（记录回可续）；`.ai subagent stop all` 才终止全部；`.ai subagent` 默认普通用户权限。
> - 决策基线「完成后主动续一轮、空回复不发言」中的唤醒由 `wake.ts` 判定（父空闲且未待机），「空回复不发言」尚未在主线实现。
> - 子代理模型请求不占用全局请求并发槽（`child.ts`），与「基础 → 请求并发上限（多会话与子代理并行共用）」的描述并存。

## 1. 目标与边界

目标：主智能体在对话中通过工具把独立任务委派给**拥有独立上下文、独立工具开关、可持久化、可续跑**的子代理，子代理只回最终结论，中间过程不进父上下文。

- 本期实现：进程内 `spawn` / `fork` 两个 provider（对应 DSH 两个 in-process 后端），委派/控制/发现/jobs 全工具，前台与后台（one-shot / continuable）双策略，notice 结算与父侧唤醒，child 持久化。
- 不实现（接缝预留）：进程外 provider（ACP/Codex/Claude Code 类，需独立进程承载）。
- 运行时硬边界（goja）：无 AbortController（在途请求不可硬断，停止靠 stopEvent 检查点）、无子进程、单线程（并行=异步交叠）。

## 2. 总体架构

```
                     ┌────────────────────────────────────────────┐
                     │ SubAgentService（≈ ctx.subagents）          │
  工具层              │  registerProvider / getProvider            │
  subagent ──────────►│  start / startContinuable / dispose        │
  subagent_fork ─────►│  sendMessage / interrupt / listAgents      │
  send_message        │  settle / abortByParent                    │
  interrupt_agent ───►└───────┬────────────────────────┬───────────┘
  list_agents                 │ spawn                  │ fork
  list_subagent_models        ▼                        ▼
  job_output / job_list / ── SpawnProvider        ForkProvider
  job_kill                    └─────────┬──────────────┘
                                        ▼
                         ChildRunner（headless child Session 激活循环）
                          ├─ 前台：等 run.result → stopReason 映射 → 工具结果回父
                          ├─ one-shot 后台：SubAgentJobs → job_* 收集/终止
                          └─ continuable：settle → 父 noticeQueue → 父下一轮/唤醒
```

## 3. 接口与数据模型

### 3.1 Provider 接缝（`src/agent/subagent/service.ts`）

```ts
// —— 对外类型 ——
type StopReason = 'completed' | 'aborted' | 'error' | 'max-tokens' | 'refusal' | 'timeout';
interface SubAgentResult {
  stopReason: StopReason;
  output: string;            // completed 时的最终文本（可能截断）
  diagnostic?: string;       // 非 completed 时的 provider 诊断
}
interface SubAgentRun { id: string; result: Promise<SubAgentResult>; dispose(): Promise<void>; }

interface StartRequest {
  label: string;                                        // 3-5 词展示名
  prompt: string;                                       // 任务文本
  parent: { sessionId: string; epId: string; isPrivate: boolean; depth: number; };
  agentOptions?: { provider?: string; model?: string; reasoningEffort?: string; maxTokens?: number };
  persona?: string;                                     // 覆盖 child 人设
  toolFilter?: { allow?: string[]; deny?: string[] };   // 覆盖继承工具面
  maxDepth?: number;
}

interface SubAgentProvider {
  name: string;
  inheritsParentContext: boolean;   // fork=true, spawn=false；决定工具文案
  start(req: StartRequest): Promise<SubAgentRun>;                       // 前台
  prepareContinuable?(req: StartRequest): Promise<{ seed?: unknown }>;  // continuable 能力位
}

class SubAgentService {
  registerProvider(p: SubAgentProvider): void;
  getProvider(name: string): SubAgentProvider | undefined;
  start(provider: string, req: StartRequest, signal): Promise<SubAgentRun>;
  startContinuable(provider: string, req: StartRequest): Promise<{ childId: string }>;
  sendMessage(sender: ParentRef, childId: string, message: string): Promise<{ messageId: string }>;
  interrupt(childId: string, by: ParentRef): void;      // 授权：仅 ancestor
  listAgents(sessionId: string): ChildSummary[];        // 树状盘点
  abortByParent(sessionId: string): void;               // .ai stop 全灭
  settle(childId: string, result: SubAgentResult): void; // → 父 noticeQueue
}
```

### 3.2 ChildRecord 与 Session 扩展

```ts
interface ChildRecord {
  childId: string;                 // "sub:<父sessionId>:<序号>"
  parentSessionId: string;
  parentAgentName: string;
  provider: string;                // 'spawn' | 'fork'
  label: string;                   // description
  depth: number;
  status: 'running' | 'idle' | 'done' | 'stopped';   // 持久化
  childSessionId: string;
  agentName: string;               // persona 对应 Agent 名
  meta: { epId: string; isPrivate: boolean };
  lastResult?: SubAgentResult;     // 持久化（completed/非 completed）
  createdAt: number;
}
```

`Session` 新增运行时字段（全部加入 `SESSION_RUNTIME_KEYS`，不落盘）：

| 字段 | 用途 |
| --- | --- |
| `headless: boolean` | `reply()` 不发送，文本进 `headlessTranscript`；`addAssistantMessage` 照常（合成 msgId） |
| `toolRestriction: {allow?: string[]; deny?: string[]} \| null` | toolState getter 求交（≈ toolFilter） |
| `parentSessionId?: string` | control / settle 归属 |
| `subagentDepth: number` | 深度链（主会话=0，逐层+1） |
| `noticeQueue: Notice[]` | 仅父 Session 使用 |

### 3.3 模型可见工具 schema

`subagent`（spawn）与 `subagent_fork`（fork）共用参数（工具 description 按 `inheritsParentContext` 换措辞）：

```jsonc
{
  "description": { "type": "string", "required": true },   // 3-5 词
  "prompt":      { "type": "string", "required": true },   // 任务（spawn：自包含；fork：只写新增目标）
  "run_in_background": { "type": "boolean" },              // 默认按实例 backgroundMode
  // 以下仅在「模型选择」开启时出现：
  "provider": { "type": "string" },
  "model": { "type": "string" },
  "reasoning_effort": { "type": "string" }
}
```

控制/发现/jobs 工具 schema 与 DSH 相同：

- `send_message { agent_id, message } → { messageId }`
- `interrupt_agent { agent_id } → { accepted }`
- `list_agents {} → 文本快照（本会话子树）`
- `list_subagent_models { provider?, model? } → 文本`
- `job_output { job_id, wait? }`、`job_list {}`、`job_kill { job_id, reason? }`

所有工具注册前做 `toolMap` 重名断言；未来撞名通过实例配置 `toolName` 改名（DSH 同款机制）。

### 3.4 停止原因 → 结果映射（结算的唯一口径）

```ts
switch (stopReason) {
  case 'completed': return { kind:'foreground', output: result.output };
  case 'aborted':   throw 'subagent run was cancelled';
  case 'error':     throw 'subagent run failed';
  case 'max-tokens':throw 'subagent run hit its token limit before finishing';
  case 'refusal':   throw 'subagent declined the task';
  case 'timeout':   throw 'subagent run timed out';
}
// 错误文本统一追加：\nDiagnostic: <diagnostic>（若有）\nPartial output:\n<部分文本>（若有）
```

前台路径：`Promise.allSettled([run.result])` 后**必执行** `run.dispose()`；两个都失败时以 AggregateError 保留双错。

## 4. 运行机制（细化）

### 4.1 child 会话创建（spawn / fork 共用）

1. 生成 `childId`，建 child `Session`：`sessionId="sub:<parentSessionId>:<childId>"`、`agentName`= persona 模板 Agent（默认 `researcher`，或实例 `persona` 覆盖）、`headless=true`、`subagentDepth=parent.depth+1`、`parentSessionId` 回填。
2. **工具面初始化**（全量继承口径）：
   - `child.tool.state = { ...父会话当前 toolState }`（快照：父关掉的保持关）；
   - 应用实例 `toolFilter` → 写 `child.toolRestriction`（allow 求交、deny 优先）；
   - 执行唯一防线 = `Tool.handleToolCall` 对 `child.toolState` 的既有校验（getter 合并 restriction 后天然拒绝）；两种工具模式（原生 function calling / 提示词工程 ```function 块）最终都汇聚到 `handleToolCall`，白名单单点生效。
3. **持久化**：写 `session_sub:<parentSessionId>:<childId>`；索引 `subagent_index:<parentSessionId>` 追加 `ChildRecord` 元数据（含 `status`）。
4. `runHeadless` 激活循环与主链 `runInternal` 同构：`resetState()`（清 callCount）→ 每轮前 `flushNotices()`/`flushPending()` → `handleMessages(...)` → `streamService.sendChatRequest(...)` → 工具批执行 → 续轮；差异仅：无 `requestLimiter.acquire`（父 run 已持槽，重复取会自锁）、headless 回复收集、终止判定含 agentOptions.maxTokens / 检查点。

### 4.2 fork seed

取父 `context.messages` 中**最近一条含 toolCalls 的 assistant 消息之前**的连续消息（深拷贝 `cloneContextMessage`，tool_calls/tool 成对保留）；无则全量。当前在飞的委派工具链必在切点之后，不参与回放——等价 DSH“最近 turn/end 前缀”。

### 4.3 child system（`buildChildSystemMessage`）

组成：persona/instruction（child Agent 的 instruction）+ 「当前时间」+ 工具能力说明 + 一行语义引导："你拥有与会话相同的工具能力，仅当任务本身需要时才使用对外发送/管理类工具"。**不注入**父记忆/知识库/事件动态段——子代理按需经工具读取（fork 只额外带消息历史 seed）。输出复用模板与 `stripInternalTags` 防注入。

### 4.4 前台 / one-shot 后台 / continuable

- **前台（one-shot 缺省）**：`start()` → 按 §3.4 映射 → 工具结果回父（`addToolCallbackMessage`，超长走既有 head 截断 + `rawText`/`read_raw` 原文保留）。
- **one-shot 后台**（`run_in_background:true`）：`SubAgentJobs.start({kind:'subagent', label, owner, run})` → 返回 `job_output/job_list/job_kill`；job 结束同样 `settle`。
- **continuable（实例 backgroundMode='continuable' 时缺省后台）**：`prepareContinuable` 预取 seed → `startContinuable()` 返回 `started subagent <childId>`，不等结果；child 独立跑完本次激活 → `settle`；可 `send_message` 续派（idle→新激活；running→steer 下一检查点）、`interrupt_agent`（只停当前轮，状态回 idle）、`list_agents` 盘点。重载后经存储恢复为 idle/done/stopped，可查可续。

### 4.5 notice 与父侧唤醒

1. `settle(childId, result)`：前台不投递（已随工具结果回父）；后台/continuable 把 `{childId, label, stopReason, output/error}` 格式化为 system-user 消息（`[system:子代理]…[/system]` 成对边界 + 内部标签剥离），push 父 `noticeQueue`。
2. 父运行中：主链每轮请求前 `flushNotices()` 逐条 `context.addSystemUserMessage`（顺序入队）。
3. 父空闲（无 run 在跑）且 notice 到达：唤醒策略——
   - 若该会话 `setting.standby` 或全局待机开启 → **不唤醒**，notice 留存待下次触发；
   - 否则用 `meta{epId,isPrivate}` 经 `getSessionCtxAndMsg` 重建 ctx/msg，调 `session.chat(ctx, msg, '子代理完成通知')`（走正常令牌桶；桶空则本次不跑、notice 留存）；
   - 该轮允许空回复：主链在最终发送前检查——若最终文本为空则**不发送、不入上下文**，仅记日志（作为主链小行为项单独回归，见 §8）。
4. 持久化边界：flush 后 notice 已成为父 context 消息，随 `session.save()` 落盘；未 flush 的队列在重载时丢弃（运行中子代理同时丢失，状态记录为 stopped，见 §8）。

### 4.6 深度 / 中断 / 清理

- **深度**：每次 `start/startContinuable` 前按调用链 `subagentDepth` 校验 `maxDepth`（默认 3；0=禁委派）。超限返回错误工具结果，委派工具保持可见——同 DSH。
- **中断**：`.ai stop`（`Session.stopConversation`）→ `abortByParent`：对子会话逐一 `fireStopEvent(child.stopEvent)` + `stopVersion++`；在途请求结果丢弃（goja 不可硬断，费用仍计，与主链 changelog 口径一致）；记录置 `stopped`。
- **清理**：`subagent_index` 记录保留上限（默认最近 100 条，超出清理最旧**已结束**记录）；用户命令 `.ai subagent clean` 手动清理。内存 job 记录同理。

### 4.7 模型选择（agentOptions / modelSelectionSettings）

- 每实例 `agentOptions{provider,model,reasoningEffort,maxTokens}`：显式配 → child 用它；未配 → **继承父当前路由**（fork 与 spawn 同规则；插件无 KV 前缀复用，DSH 的 fork 改路由限制在本项目不产生实际代价，故不另设限制）。
- `modelSelectionSettings:true`：Session 记录管理员允许的精确路由列表（policy），并**随 child Session 继承**（policy 传播链同 DSH）；工具暴露 `provider/model/reasoning_effort`；注册 `list_subagent_models`（读 `Model` 注册表/provider 分类）；执行期按 policy 二次校验，非法路由 → 错误工具结果。
- `reasoningEffort`：仅当目标 adapter/模型声明支持时下发；否则工具返回明确错误（不静默丢参）。
- `maxTokens`：child 单轮请求 max_tokens；触顶按 `max-tokens` 结算。

## 5. 工具清单与命令

### 5.1 AI 侧（§3.3 schema）

`subagent`（spawn）· `subagent_fork`（fork）· `send_message` · `interrupt_agent` · `list_agents` · `list_subagent_models`（仅启用时）· `job_output/job_list/job_kill`。
委派指引（system prompt 节，按开关注入）：独立任务可委派；**相互独立的任务在一条消息里一起发起**，能继续干的活先干，结果以 notice 到达；只有下一步依赖它才前台等待；spawn 任务自包含、fork 只写新增目标；子代理只回最终结论；简单问题直接答。

### 5.2 用户侧 `.ai subagent`

```text
.ai subagent              查看本会话子代理运行情况（任务 + job 计数）
.ai subagent list         列出子代理：ID / 用途 / 状态 / 进度
.ai subagent stop <ID>    停止指定子代理（当前轮中止）
.ai subagent stop all     停止本会话全部子代理
.ai subagent clean        清理已结束/已停止的记录
```

开启/关闭工具仍走 `.ai tool`；全局开关与实例配置在「子代理」分组。权限：list 与 `.ai tool` 同级；stop/clean 为管理操作（默认群管理/骰主）。

## 7. 不变量（实现时必须保持）

1. 工具消息顺序与 `tool_call_id` 配对：同批并发执行（fan-out）时按原 `tool_calls` 顺序回填，`callCount` 汇总一致。
2. 停止原因单次结算：`settle` 仅在激活结束转移时触发一次；同一 child 不重复投递 notice（前台除外）。
3. 白名单单点：`Tool.handleToolCall` 的 `child.toolState` 是唯一执行闸门；不得绕过（含 call_tool 内层、提示词工程路径）。
4. `.ai stop` 必须中断全部子代理（ancestor 授权）。
5. 前台路径 `dispose()` 必执行；错误结果携带 diagnostic + 部分输出，不半成功。
6. child 请求不得二次 acquire `requestLimiter`（自锁）；恢复使用 `getSessionCtxAndMsg` 重建现场。
7. notice/上下文标签防注入（`[system:]…[/system]` + 剥离）与主链一致。
