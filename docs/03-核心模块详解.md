# 03 - 核心模块详解

本章按 `src/` 目录顺序逐个说明模块的职责、文件布局、关键类型、主要流程与不变量。代码路径均相对仓库根目录。分层与依赖规则见 [02-架构设计](02-架构设计.md)，工具系统详见 [04-工具系统](04-工具系统.md)，命令与配置项详见 [05-命令与配置](05-命令与配置.md)。

## 1. 入口与装配（src/index.ts）

**职责**：进程入口。装配宿主端口、配置、注册表与事件，不承载业务逻辑。

**装配顺序（契约，不可随意调整）**：

1. `setHost(createSealHost())` —— 宿主端口必须先装，后续存储/时钟/网络全走它。
2. `registerConfigAppliers()` —— 配置应用钩子先注册（`Config.warmup()` 会触发）。
3. `installAuxLlm()` / `installPromptMemorySource()` —— 端口实现先于配置预热安装，预热钩子可用端口。
4. Handlebars Helper：`index`（从 1 开始）、`json_stringify`、`time`。
5. `Config.registerConfig()` —— 注册 20 个配置分组并 `warmup()`（触发模型配置应用等钩子）。
6. `initAgents()` / `registerAgentApi()` / `checkUpdate()`。
7. `registerAllTools()` —— 内置工具 + 技能 + MCP。
8. `TimerManager.init()` / `MemoryScheduler.init()` / `MediaTaskManager.init()` / `ImageGC.init()` / `knowledgeService.init()` / `BlockManager.initBlockList()`。
9. `registerAllCmds()` / `PrivilegeManager.reviveCmdPriv()`。
10. `MessagePipeline.subscribeOb11Receive()` —— ob11 依赖存在时订阅其事件分发。
11. 写 `storage_version`（结构升级时）。
12. 绑定 `ext` 事件：`onNotCommandReceived` / `onCommandReceived` / `onMessageSend` / `onPoke` / `onGroupMemberJoined` / `onGroupLeave` / `onMessageDeleted` / `onBecomeFriend` / `onGroupJoined`。消息类委托 `MessagePipeline`；通知类先归一 UNI-ID（`normalizeUserId` / `normalizeGroupId`）再交 `handleNativeNoticeEvent`，与 ob11 依赖路径共用事件去重。

**注意事项**：入口只做装配；新增注册表必须提供 `xxx/bootstrap.ts`（或等价装配函数）且只被 `index.ts` 调用，避免「注册表 ↔ 实现」环。

## 2. 宿主端口与跨层端口（src/core/）

**职责**：隔离 SealDice 环境与业务代码，提供可注入的内存实现，供单测/模拟器替换。

| 文件 | 职责 |
| --- | --- |
| `host.ts` | 端口接口 `HostStorage` / `HostClock` / `HostFetcher` / `HostExt` 与 `setHost/getHost` |
| `seal_host.ts` | SealDice 适配器：唯一直接读 `seal` / `ext` 的模块；`getStorage/getClock/getFetcher` 实现 |
| `ports/agent_registry.ts` | 按名取 Agent 的端口（默认委派 `Agent.get`，保住测试桩） |
| `ports/aux_llm.ts` | 内部推理端口（压缩/摘要/评分/抽取等），实现由组合根注入 |
| `ports/session_lookup.ts` | 按 id 取会话，供 timer/media 等消费，不反向 import `session_service` |
| `ports/judge_wait.ts` | 评分轮末等待 ↔ 定时器双向登记，拆掉 judge ⇄ timer 环 |
| `ports/media_notice.ts` | 媒体完成通知「已送达」回置，session 侧消费，不反向 import media |

**约定**：业务代码统一 `getHost()` 访问宿主能力；双向协作用端口各注册一半，实现为动态委派（不要缓存函数引用，否则测试桩失效）。

**职责**：集中注册/读取 SealDice 配置项，并把解析结果应用到实现。

**配置分组（20）**：基础、模型、角色设定、上下文、消息接收、事件接收、消息触发、回复、工具、联网、MCP、技能、子代理、记忆、知识库、图片、后端、论坛、资源、错误处理。

**不变量**：`Config.registerConfig()` 的预热必须走 `getCache`（`warmup()`），否则分区钩子（如模型配置应用）不执行；解析失败的分组保留默认/上次结果并记日志，不整机崩溃。

### 配置读取禁令（重要）

**禁止读取未注册的配置键，禁止为旧键保留 `oldInt/oldBool` 兼容读取。**

SealDice 的 `getIntConfig/getBoolConfig/...` 在键不存在时不会抛普通 JS 异常，而是 Go 侧 `nil pointer dereference`：

```go
// sealdice-core/dice/dice_jsvm.go
if ei.dice == nil || d.ConfigManager.getConfig(ei.Name, key).Type != "int" {
```

`getConfig` 返回 `nil` 时取 `.Type` 直接 panic；这个 panic **无法被 JS 的 `try/catch` 接住**，会表现为“扩展处理非指令消息异常”，并且日志打不出来。

因此：

1. 读配置前必须确认该键已在对应 `configs/*.ts` 的 `register()` 中注册为**相同类型**；
2. 删除配置键时，必须同时删除所有读取点，**不要保留**“旧键读不到就 try/catch 回 0”的兼容代码；
3. 生产事故记录：`ContextConfig` 曾读取已不再注册的 `对话保存轮数`，通过 `getIntConfig` 触发 nil panic，第一条普通消息即崩溃；根因是旧键读取，不是配置类型变更。

排查方法：`grep -rn "getIntConfig\|getBoolConfig" src/config/configs` 的每个 key 都必须能在同文件 `register()` 中找到注册项。

## 4. 消息管线（src/pipeline.ts + src/pipeline/）

**职责**：所有消息/事件的唯一分发入口；负责过滤、触发判定、会话获取与模式分流。

| 文件 | 职责 |
| --- | --- |
| `pipeline.ts` | `MessagePipeline` 编排：非指令/指令/机器人消息/戳一戳/ob11 补充接收；`resolveEndpointId` 兼容 re-export |
| `pipeline/dedup.ts` | 核心/依赖配对状态机：配对表（TTL/容量淘汰）、依赖整条兜底墓碑、事件「后到覆盖先到」引用表、`filterOb11SupplementSegments` |
| `pipeline/events.ts` | 事件分发与事件提示词入库：ob11 通知/请求、原生通知 → 黑名单 → 待机 → 去重 → 录入上下文 |
| `pipeline/inbound.ts` | ob11 入站段渲染：卡片/语音/文件/视频/音乐/商城表情/XML/Markdown/消息节点/合并转发 → `MessageSegment[]`，含嵌套深度上限 |
| `pipeline/endpoint.ts` | 按机器人自身 ID 反查通信端点（优先已连接端点），事件分发与管线共用 |

**主要流程**：

- `handleNonCommand`：忽略私聊/忽略条件/忽略正则 → CQ 白名单 → 触发判定（正则/条件/计数器/计时器/概率/活跃时间/待机）→ `chat()` 或仅入库。
- `handleCommand`：`.ai` 根命令分发（默认不入上下文，开启后在待机模式入库）。
- `handleBotMessage`：先交 `session.tool.listen`，再按配置入库；跳过刚发出的回复。
- 事件三兄弟：仅待机/全局待机时录入，纯背景不触发；机器人自身事件由原生回调覆盖、ob11 侧跳过。

**不变量**：核心优先、依赖补充（避免同一条消息双录）；事件去重 key 含整包内容指纹，连续但内容不同的事件不会互吞；重复/双路径到达「后到覆盖先到」就地替换（位置不变）；事件原始 JSON 挂 `raw`，不渲染、由 `read_raw kind=event` 读取。

## 5. 会话（src/session/）

**职责**：会话状态、触发判断、收信/发信、保存节流。

| 文件 | 职责 |
| --- | --- |
| `session.ts` | `Session` 主体：字段/工具状态、`chat()`/`chatStream()` 编排、`stopConversation()`；其余方法委派叶子 |
| `setting.ts` | `Setting`：priv、standby、regexTrigger、counter、timer、prob、judge、activeTimeInfo、overrides |
| `rhythm.ts` | 纯函数：`computeSessionState`（冷/余温/热状态机）、`activeTimeSegmentIndex`、`nextActiveTimePoint`；`COLD_AFTER_MS` / `COOL_DOWN_MS` / `HOT_HOLD_MS` |
| `persistence.ts` | 序列化与保存节流：`SESSION_RUNTIME_KEYS`、`serializeSession`/`serializePendingQueue`、`writeSessionRecord`/`writePendingRecord`（5 秒或 20 次合并一次） |
| `inbox.ts` | 收信与排空：`handleReceipt`/`deferReceipt`/`drainPending`/`flushPending`（挂起消息入库）/`flushNotices`（子代理/媒体通知） |
| `outbox.ts` | 发送：`deliverReply`（分段延时 → `replyToSender` → 上下文回填 → 落盘；headless 只收集不发送） |
| `session_service.ts` | `getSession(sid)` 从存储复活会话；`SessionService` 持有 `sessionMap` 与全局记忆 |
| `tool_listen.ts` | 工具「等待消息返回」监听（`ToolListen`/`ToolWaitHandle`） |
| `group.ts` / `user.ts` | 群档案（角色/群主/管理员/成员/忽略名单）与用户档案（名称） |
| `types.ts` | `SessionType('group'|'user')`、`State`、`GroupInfo`、`UserInfo` |

**关键字段**：`agentName`、`sessionId`、`sessionType`、`state`、`context`、`memory`、`setting`、`stream`、`bucket`、`tool`（state/callCount/listen）；运行时字段 `running`/`starting`/`stopVersion`/`stopEvent`/`pendingQueue`/`activeRuns` 不持久化。

**主要流程**：

- `chat()`：令牌桶检查 → 重置 BLOCKED 工具 → 模型流式判定 → `chatStream` 或 `Agent.run()`。
- 收信：运行中收到新消息 → `deferReceipt` 入 `pendingQueue`；每轮模型请求前 `flushPending` 统一入库；触发类在链结束后由 `resumePending` 串行再起一轮。
- 发送：`deliverReply` 分段发送并回填上下文；回复/命令/摘要等关键路径立即 `save`，待机消息/事件用 `coalesce` 节流。
- 工具开关：`toolState` getter 合并 `BLOCKED`、`DEFAULT_CLOSED`、已删除工具清理与子代理 `toolRestriction`（allow/deny 求交）。
- 技能/知识库会话开关 `skillState`/`kbState` 只记录被关闭项，缺省开启，参与 prompt 静态段缓存 key。

**不变量**：`.ai stop` 通过 `stopVersion`/`StopEvent` 中止，检查点后丢弃结果；`chat()` 不做静默丢弃——忙时由调用方 `deferReceipt`/`decideWake` 决定，媒体/子代理结果必须进队列（见 [02-架构设计](02-架构设计.md) 异步章节）。

## 6. 上下文（src/context/）

**职责**：会话的只追加事件账本、内容 AST、请求编译、滚动摘要、完整召回与管理命令。
旧版 `messages` 数据模型仅作迁移/回退兼容；生产会话由 `ContextService` 接管。

| 文件 | 职责 |
| --- | --- |
| `events.ts` / `head.ts` / `keys.ts` | 事件/记录/Part 类型、ContextHead 水位、`ctx_head/evt/rec` 键 |
| `log/page_store.ts` / `log/record_store.ts` | 连续页号只写一次；缺失/读失败区分；崩溃恢复 |
| `store.ts` | 同步 append、eventId 去重、增量 flush、head、snapshot、commitSummary |
| `content/*` | 标签描述符、宽松入站解析、规范文本/平台段/LLM 内容块、MCP 工具结果、防注入 |
| `view/units.ts` / `view/records.ts` / `view/compile.ts` | 单元切分（工具组原子）、记录可见性/编辑、纯函数 `compileRequest`（最新必留/摘要缺口/PE/多模态） |
| `recall.ts` / `tool_api.ts` | `e:<seq>`/区间/msg_id/grep 检索、legacy arc/raw；`read_raw`/`grep_raw` 适配 |
| `compact/compactor.ts` / `compact/runtime.ts` | 每 epoch 单条 rolling summary、单元边界、失败不推进、节流/小时上限/退避 |
| `migrate/*` | 旧 `messages` → 事件/记录（rawText/rawItems 保留原文）+ 幂等落盘 |
| `projection.ts` | 旧 `MessageType` 只读投影，供 judge/prompt/pub/status 等过渡读取 |
| `service.ts` | `ContextService`：写入、compile、召回、压缩、flush、记忆桥通知 |
| `admin.ts` / `commands.ts` | purge/hide/stats/repair；`.ai ctx` 逻辑 |
| `mutations.ts` | 编辑/覆盖/遗忘/epoch 记录与事件定位 |
| `roster.ts` / `types.ts` | 名册/图片查询、旧 `MessageType` 兼容类型 |
| `context.ts` | 兼容门面：接入事件账本后写入走 append、`messages` 由 projection 派生；旧路径仅回退 |
| `window_policy.ts` / `archiver.ts` / `archive_store.ts` | 旧窗口/归档/分片；新实现下 `settle/trim/archive` 短路，仅迁移与回退使用 |

**主要流程/不变量**：

- 写入：单写者同步 append，flush 只写新页 + 常量 head；旧 `messages` 数组在新实现启用后不再落盘。
- 请求：`handleMessages` 在 `session.contextV2` 存在时返回 `compileRequest`；最新单元必留，超预算截断并带 `read_raw` 指针，工具组不拆。
- 摘要：run 结束由 `agent/context_bridge` 触发；摘要只追加 `SummaryRecord`，不删原文；失败/空不推进，节流 + 小时上限 + 退避。
- 召回：`read_raw e:<seq>` / `grep_raw` 可穷尽检索；摘要文本带可解析指针。
- 管理：`.ai ctx`（status/archive/hide/purge/set/name/repair）；`hide` 逻辑遗忘、`purge` 物理清除且默认不动记忆。
- 解耦：上下文不写记忆；`agent/context_bridge` 从事件账本消费并维护自己的水位。

## 7. 智能体（src/agent/）

**职责**：模型请求编排（工具循环、流式、错误恢复）、对外 API、子代理框架。

| 文件 | 职责 |
| --- | --- |
| `agent.ts` | `Agent`：字段（name/description/instruction/use/sessionService/tools/subAgents）、`get`/`save`、`chat()`、`run()`/`runStream()`、错误自动处理、`.ai stop`、挂起队列续跑 |
| `run_context.ts` | `AgentRunContext`：单次 run 的 runId/轮次/工具事件/耗时 |
| `stream.ts` | `sendChatRequest()`（非流式，注入 tools/tool_choice、统计用量）、`startStream/pollStream/endStream`（后端中转流式） |
| `api.ts` | `globalThis.aiplugin4` 对外 API：`chat`/`run`/`getAgent`/`registerTool` |
| `aux_llm_impl.ts` | `aux_llm` 端口实现：压缩/摘要/评分等内部推理（委派 `Agent.get` / `chat`） |
| `agents/` | `compress_agent`（压缩）、`summarize_agent`（摘要）、`judge_agent`（评分）；`index.ts` 统一 `initAgents()` |
| `subagent/`（独立模块 `src/subagent/`，公共入口 `index.ts`） | DSH 对齐子代理框架：`child.ts` 子会话编排、`context.ts` 独立上下文（消息叠加 + 上限压缩，不接主 ContextStore）、`child_system.ts` 子 system、`providers.ts` spawn/fork、`service.ts` 生命周期、`jobs.ts` 后台 job、`store.ts` KV、`wake.ts` 父会话空闲唤醒、`rules.ts`/`limits.ts`/`wiring.ts`；配套工具 `subagent/subagent_fork/send_message/interrupt_agent/list_agents/job_*` |

**主要流程**：

- `run()`：组装消息 → `requestModel` → 工具轮（function calling 或提示词工程）→ 复读检测重试 → 最终回复；单轮最多 3 次尝试。
- 错误分类处理：上下文超长按模型窗口重算预算后重发一次（编译层已按预算裁剪）；余额不足等按「跨厂商优先/配置顺序」切备用模型并持久化覆盖；单 run 各至多一次。
- 停止：检查点检测 `stopVersion`/`StopEvent`，命中即中止（goja 无 AbortController，结果丢弃）；排队项由 `requestLimiter.cancelBySession` 丢弃。
- 子代理：headless 子会话（spawn 无 seed / fork 继承父上下文），原生模式只注入 list_tools/search_tools/call_tool；完成后写父 `noticeQueue` 或 job 结果。

## 8. 模型层（src/model/）

| `adapter.ts` | 按协议方言转换请求/响应（对话 anthropic-messages 走 Messages；媒体请求体原样透传） |

## 9. 记忆（src/memory/）

**职责**：三层记忆（事实 / 观察 / 心智模型）、本体全局记忆、知识库；`MemoryService` 是唯一门面。

**数据模型**：

| 层 | 存储 | 关键字段 / 语义 |
| --- | --- | --- |
| 原始事实 | `MemoryUnit` | append-only；`factType=world/experience`；`createdAtSeq`；`state=valid/invalidated`；纠错用 `supersedes`，不合并文本 |
| 观察 | `Observation` | `evidence[]`、`proofCount=distinct live source`、`history[]`、`lastSupportedAt`；过期只派生，不删除 |
| 心智模型 | `MentalModel` | `sourceQuery/content/structuredContent/trigger/tags/maxTokens/watermark/reflectResponse/history`；full/delta、失败冷却、48h full 重建 |

**可见性**：

| 标签 | 个人 bank | 群 bank | 全局 bank |
| --- | --- | --- | --- |
| `vis:owner` | 仅本人私聊 | 本群 | 不允许 |
| `vis:origin:<scope>` | 来源群 + 本人私聊 | 本群 | 不允许 |
| `vis:public` | 本人私聊 + 该用户发言的群 | 本群 | 所有会话 |

默认：私聊事实 `owner`；群来源个人事实 `origin:<群>`；群 bank `public`；global `public`；旧 user bank 迁移统一收紧 `owner`。

| 文件 | 职责 |
| --- | --- |
| `service.ts` | `MemoryService`：抽取路由、bank/可见性、注入、巩固、reflect、状态、管理命令 API；命令/工具/调度器只经过这里 |
| `manager.ts` | 兼容门面（旧 import/测试）；生产路径已改用 `MemoryService` |
| `session_state.ts` | `SessionMemoryState`：会话持久化字段（`observationEnabled` 等）与旧调用薄适配；实际读写走服务 |
| `revision.ts` | 记忆/观察 revision 自增并失效 prompt 缓存 |
| `v2/engine.ts` | Hindsight-like 引擎：retain（append-only）、recall（语义/关键词/图/时序 + RRF + 预算 + 观察折叠）、consolidate/MM/reflect 编排、prune |
| `v2/repository.ts` / `v2/storage.ts` | 分片存储（meta/units/links/obs）+ bank 索引；旧单 key 与 v2 数据惰性迁移 |
| `v2/consolidation.ts` | 事实→观察：证据去重、`proofCount` 重算、create/reinforce/refine/contradict/merge/noop、历史 reason；不删过期观察 |
| `v2/mental_models.ts` | 心智模型：模板播种、full/delta、watermark、空内容保护、失败冷却、48h delta 重建 |

| `v2/prompt.ts` / `v2/access.ts` | 单渲染器（预算/去重/分组）+ 可见性矩阵（owner/origin/public）与 scope 工具 |
| `v2/structured.ts` / `v2/migrate_v3.ts` | 心智模型 AST 与类型化 delta；幂等迁移 |
| `v2/templates.ts` / `v2/bank_resolver.ts` / `v2/types.ts` / `v2/index.ts` | 模板目录、bank 解析、类型、导出与默认回调装配 |

**核心流程**：

- 注入：`MemoryService.buildMemoryPrompt` 当前 bank + 群内最近发言者个人 bank + global；单渲染器统一预算/去重；`owner` 事实永不进群，`public` 才可跨群。
- 抽取：只由 AI 触发；`agent/memory_scheduler` 从 `context_bridge` 的 pending 取原文，后台抽取 → 路由到目标 bank → 入队巩固；无 AI 活动不跑自动任务。
- 巩固：pending facts ≤50/批 → 聚类 → 观察决策 → evidence/proofCount/history 更新；失败不推进。
- 心智模型：固定模板版本化播种；刷新逐条 staleness/interval/失败冷却门控，成功后推进 watermark；delta 只做类型化编辑，未命中 block 原样保留。
- 知识库：`search` 关键词过滤 → 候选块懒向量重排（失败降级）；只注入索引。

**调度与预算**：`agent/memory_scheduler.ts` 持久队列 `mem_sched_v1`；AI 轮结束只入队，抽取/巩固/MM 刷新后台执行。自动任务要求 30min 内有 AI 活动、主 AI 轮内让路、探测 `requestLimiter` 在线让路（不排队）、每小时 LLM 上限（默认 20）、单并发、连续失败熔断；手动命令/工具是唯一同步等待路径。job 只存会话/游标引用，原文只在 `mem_cursor:<sid>.pending`。

**配置**：启用长期/观察记忆、自动抽取、群聊自动写个人记忆、本体自动抽取、启用全局记忆、固定模板维护、巩固后自动刷新、刷新模式/最小间隔/失败冷却/输出上限/增量重建、召回新近度/语义阈值、条数上限、注入预算、观察过期、后台小时上限、三个 LLM 回调开关；默认值对齐 Hindsight（MM 自动刷新关闭、full、2048 token、后台 20 次/小时）。完整面板见 [05-命令与配置](05-命令与配置.md)。

**存储**：`memv2:banks` 索引 + `memv2:<bank>:meta/units/links/obs` 四分片；`mem_cursor:<sid>` 抽取进度；`mem_sched_v1` 调度队列。v2→v3 惰性迁移：schemaVersion、迁移前备份、observation unit 去除、可见性收紧、旧 persona 迁入模型、`global__→global_main`；迁移先写数据分片、最后写 meta。详见 [06-数据存储](06-数据存储.md)。

**命令与工具**：`.ai memo` 支持 `--u/--g/--self`、`clear/obs clr --yes`、`#N` ID；工具为 `memory_recall/add/update/delete/consolidate/reflect/mental_model`（7 个）。完整语法见 [05-命令与配置](05-命令与配置.md) 与 [04-工具系统](04-工具系统.md)。

## 12. 媒体生成（src/media/）

**职责**：tts/tti 异步任务队列：提交即返回、后台执行、按来源投递、逐会话限流与恢复。

| 文件 | 职责 |
| --- | --- |
| `task_queue.ts` | `MediaTask`（含 `validKeys`）+ `MediaTaskManager`：`submit`/`pump`/`run`/`waitForSettle`/`cancel`/`markNotifiedByNotice`/`wakePendingNotices`/持久化与恢复 |

**主要流程/不变量**（详见 [02-架构设计](02-架构设计.md) 异步章节）：

- `submit()` 建任务、落盘、立即返回任务号；`pump()` 在并发上限（默认 3）内启动。
- 结算：命令来源直接 `replyToSender`；工具来源先入会话 `noticeQueue`（带 taskId、不置 notified），再按 `decideWake` 决定立刻起一轮或 defer，轮末 `wakePendingNotices` 补触发。**结果要么已呈现、要么仍在队列**。
- 工具同步等待窗口（默认 5 秒）：窗口内完成当场返回，不进唤醒链路。
- 只存句柄/短摘要，不落 base64；每会话最多保留 50 条已结束任务；重载 `running` → 失败。

## 20. 日志（src/logger.ts）

- 输出格式：`【AI骰娘4】[级别短标签] [模块标签] 内容`；级别 ERROR/WARN/INFO/DEBUG 与海豹面板对应。
- 通过 `logger.withTag('模块名')` 生成带标签日志；级别由「日志级别」配置控制。
- 单条截断 2000 字符；「日志简短打印」首尾各 500 字符；`logLong()` 分片打印并标注段号。
- 密钥脱敏：`api_key`/`token`/`authorization`/`secret`/`password` 等字段、URL query、`Bearer`、`sk-` 前缀、access/refresh token。
- `exception()` 错误进 error、堆栈进 debug；`printRequestMessages()` 默认只打摘要，正文受「日志记录消息内容」开关与截断控制。
