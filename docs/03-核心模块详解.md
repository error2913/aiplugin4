# 03 - 核心模块详解

> 本章按目录逐模块说明职责与关键类型。代码路径均相对仓库根目录 `src/`。

## 入口与装配(src/index.ts)

- 注册 Handlebars Helper:`index`(从 1 开始)、`json_stringify`、`time`。
- 依次初始化:`Config.registerConfig()`、`initAgents()`、`checkUpdate()`、`Tool.registerTool()`、`TimerManager.init()`、`knowledgeService.init()`、`registerCmd()`、`PrivilegeManager.reviveCmdPriv()`。
- 写入存储版本标记 `storage_version`(当前 `STORAGE_VERSION = 2`,结构变更时递增)。
- 绑定九个 SealDice 事件:`onPoke`、`onNotCommandReceived`、`onCommandReceived`、`onMessageSend`、`onGroupMemberJoined`、`onGroupLeave`、`onMessageDeleted`、`onBecomeFriend`、`onGroupJoined`,消息与戳一戳委托给 `MessagePipeline`,原生通知事件统一交给 `MessagePipeline.handleNativeNoticeEvent`(与 ob11 依赖通知共用白名单/去重,避免双录)。

## 消息管线(src/pipeline.ts)

`MessagePipeline` 是唯一的事件处理入口:

- `handleNonCommand(ctx, msg)`:执行忽略/触发判定,见 [02-架构设计](02-架构设计.md)。
- `handleCommand(ctx, msg, cmdArgs)`:处理收到的指令消息;可选录入上下文。扩展指令工具所需 `CmdArgs` 不从这里缓存，而是在 `run_ext_command` 调用现场构造。
- `handleBotMessage(ctx, msg)`:转发给工具监听;可选录入上下文。
- 通知/请求事件(`handleOb11NoticeEvent`/`handleOb11RequestEvent`/`handleNativeNoticeEvent`):转文本提示词,仅当会话待机或全局待机开启时录入上下文（仅背景、不触发 AI）,原生与 ob11 依赖共用白名单/去重避免双录。事件原始数据随条目挂载（上限 20 条、单条 4000 字符），不渲染给模型，AI 经 `read_raw kind=event` 读取完整 JSON 字段（原 `get_event_detail` 工具已删除）。
- 会话统一通过 `getSession(sid)` 获取;`sid` 私聊为用户 ID、群聊为群 ID。
- CQ 码白名单 `CQ_TYPES_ALLOW = ["at","image","reply","face","poke"]`,含白名单之外 CQ 类型的消息不处理。

## 配置(src/config/)

### config.ts

- 通过 `seal.ext.find/new/register` 创建扩展实例 `ext`(插件名 `aiplugin4`)。
- `configMap` 集中登记 16 个配置分组(按注册顺序):base、model、role、context、received、trigger、reply、tool、mcp、skills、memory、knowledgeBase、image、backend、event、resource。
- 每个分组由 `register()`(向 SealDice 注册配置项)与 `get()`(读取并返回类型化对象)构成。
- 读取带缓存:`CONFIG_CACHE_TTL = 60000` 毫秒,`Object.defineProperty` 把 `Config.<分组>` 变为缓存 getter;`ModelConfig.get()` 在注册时预热并同步模型静态列表。
- `getRegexConfig()`:把模板配置的多行正则拼接为单个 `RegExp`,失败时返回永不匹配的 `/(?!)/`。

### static_config/(静态常量)

- `VERSION`(当前 4.21.0)、`AUTHOR`、`NAME`、`STORAGE_VERSION`(当前 2)、`CONFIG_CACHE_TTL`、`CQ_TYPES_ALLOW`。
- `PRIVILEGE_LEVEL_MAP`:master=100 / whitelist=70 / owner=60 / admin=50 / inviter=40 / user=0 / blacklist=-30。
- `HELP_MAP`、`ALIAS_MAP`(命令别名表)、`FACE_MAP`(QQ 表情编号 → 名称)。
- `PROVIDER_MAP`:10 家厂商的 OpenAI 兼容 base_url。
- `CHAT_MODEL_MAP` / `MULTIMODAL_MODEL_MAP` / `EMBEDDING_MODEL_MAP` 及反向映射:模型名 → 提供商自动识别。
- `DEFAULT_CHAT_MODEL_BODY` / `DEFAULT_MULTIMODAL_MODEL_BODY` / `DEFAULT_EMBEDDING_MODEL_BODY`:默认请求体兜底。
- 按类别拆分为 `meta.ts`(版本/作者/插件名/缓存 TTL/存储版本)、`cq.ts`、`permission.ts`、`help.ts`、`alias.ts`、`face.ts`、`providers.ts`(厂商与模型映射)、`model_defaults.ts`、`memory.ts`(记忆检索内置常量),由 `index.ts` 统一 re-export,历史导入路径 `../config/static_config` 保持不变。

### prompt 模板(src/prompt/templates.ts)

模板在代码中以 `TEMPLATES` 常量内置(不再注册为配置项,避免误改导致渲染损坏),读取时 `compileTemplate` 编译,仅在编译失败时回退空函数;渲染期异常不兜底,由调用方处理。模板清单:

- `system prompt模板`
- `长期记忆prompt模板`
- `观察记忆prompt模板`
- `工具函数prompt模板`
- `图片识别prompt模板`
- `记忆观察prompt模板`

## 模型层(src/model/)

- `model.ts`:`Model` 静态注册表(chatModels/multimodalModels/embeddingModels)与全局分用途覆盖 `purposeModelOverrides`(use → 模型唯一标识 `来源[序号]:模型名`,由 `.ai model` 写入 `modelPurposeOverrides` 存储键)。`getChatModel(use)`/`getMultimodalModel(use)`/`getEmbeddingModel(use)` 先按用途查覆盖(覆盖失效自动回退),再按 use 精确匹配取默认(chat 类用途:纯文本列表优先,其次多模态列表;use=chat 的多模态模型可作多模态对话模型);`findModelByRef` 按完整标识反查;`reset()` 供测试/热重载。
- `chat.ts`:`ChatModel` 请求 `{baseUrl}/chat/completions`(anthropic 走 `/messages`,由 `adapter.ts` 转换),解析 `choices[0].message`、`tool_calls`、`reasoning_content`。
- `multimodal.ts`:`MultimodalModel` 用于图片理解(`callITT`,图片 + prompt)与多模态对话(`callChat`)。
- `embedding.ts`:`EmbeddingModel` 请求 `{baseUrl}/embeddings`,带单条文本向量缓存。
- `provider.ts`:`requestModel()` 统一请求入口:超时(`TIMEOUT`)、失败重试(最多 2 次,4xx 不重试,指数退避)、成功时上报 token 用量;`adapter.ts` 按提供商转换请求/响应格式(当前支持 anthropic)。
- `types.ts`:用途类型 `ChatModelUse('chat'|'compression'|'summarization'|'judge')`、`MultimodalModelUse('image-understanding'|上述对话用途)`、`EmbeddingModelUse('text-embedding')`。

## 请求服务(src/agent/stream.ts)

- `sendChatRequest()`:非流式对话,函数调用模式(`STATUS && !PROMPT_ENGINEERING`)下注入 `tools`/`tool_choice`,统计用量。
- `startStream()/pollStream()/endStream()`:把模型配置(URL/Key/body)发给后端流式输出服务中转,按 `id` 轮询增量结果。
- token 估算与校准:`src/token_calibration.ts` 按模型记录实际 prompt token 与估算的比值(校准系数),`utils/message.ts` 裁剪时用系数预测结果;流式请求结束按真实 usage 回写校准,避免长上下文估算偏差。

## 会话(src/session/)

- `session.ts`:
  - `Setting`:priv、standby、regexTrigger、counter、timer、prob、judge、activeTimeInfo(start/end/segs)。
  - `Session`:agentName、sessionId、sessionType、state、context、memory、setting、stream、bucket、tool(state/callCount/listen)、lastCtx(不持久化);运行时字段 `running`(是否有 run/runStream 在跑)、`starting`(是否正在启动 run/runStream,置位期间同会话新消息一律挂起)、`stopVersion`(.ai stop 自增的中止版本号)、`stopEvent`(停止信号,fireStopEvent 唤醒等待者)、`pendingQueue`(会话忙时挂起的待入库消息队列)、`activeRuns`(本会话当前在跑的请求数)均不持久化。
  - `toolState` getter:按 `BLOCKED` 与 `DEFAULT_CLOSED` 同步每会话工具开关,并清理已删除工具的残留状态。
  - `chat()`:配额检查 → 重置 → 流式判断 → `Agent.run/runStream` → `save()`。
  - `reply()`:逐段发送并写入上下文。
  - 活跃时间:把时间段切分为 `segs` 段,`checkActiveTimer` 用 `TimerManager` 安排下一次触发。
- `session_service.ts`:`getSession(sid)` 从存储复活会话(经 `revive`),`SessionService` 持有 `sessionMap` 与全局 `memory`。
- `group.ts` / `user.ts`:群档案(角色/群主/管理员/成员/忽略名单)与用户档案(名称)。
- `types.ts`:`SessionType('group'|'user')`、`State`、`GroupInfo`、`UserInfo`。

## 上下文(src/context/)

- `types.ts`:消息类型定义:`UserMessageItem`、`SystemUserMessageItem`、`AssistantMessageItem`、`ToolCallsMessage`、`ToolCallbackMessage`、`RequestMessage`。
- `message.ts`:`Message` 静态方法判断消息类型;`handleMessages` 把内部消息转为 API 请求格式,元数据(时间/用户/消息ID/系统来源)存在消息项字段中,多模态模式下把 `[img:...]` 等图片标签转成 `image_url` 内容块直接传给模型。系统名义消息（群事件/触发原因/定时器等）与工具返回分别以 `[system:名称]…[/system]`、`[tool_result]…[/tool_result]` 成对边界渲染,配合 system prompt 声明防注入;`stripInternalTags` 统一剥离内部标签及其闭合形式（`[/system]` 等）,防止标签逃逸。
- `pipeline.ts` 的接收适配遵循核心优先、依赖补充原则:核心 `msg.message`/Milky `msg.segments` 直接进入统一转换器;ob11 依赖只补充核心不接收的 file/video/record/json/music/node 等段,并通过唯一消息 ID 去重。转换器输出统一的 `[from:...]`、`[time:...]`、`[msg_id:...]`、`[img:...]`、`[at:...]`、`[reply:...]`、`[face:...]`、`[poke:...]` 标签。
- `handleMessages` 在组装 system、预设上下文、历史和工具定义后进行整包 token 估算;system 与预设上下文不裁剪,历史从最早消息开始裁剪。长对话中按 `INSERT_COUNT` 插入短提醒,不会重复复制完整 system prompt。
- `context.ts`:`Context` 类:
  - 添加用户消息(自动改名、超长消息交给 `compress_agent` 压缩)、助手消息(写入后触发持久化 token 超限归档检查)、系统用户消息、工具调用/回调消息。
  - 持久化 token 超限归档:`archiveByTokenIfNeeded()` 在新增消息后按需执行——超过 `MAX_CONTEXT_TOKENS` 时保留最近 `MAX_ROUNDS` 个真实 user 轮(出现一次真实 user 视作一轮),更早消息按 `ARCHIVE_CHUNK_TOKENS`(50000 token)切块,逐块经 `MemoryManager.summarizeChunkWithRetry`(最多重试 3 次)沉淀为观察/长期记忆,成功一块删一块;归档失败降级丢弃最早一轮;极端单条超限时兜底截断最旧消息文本。`handleMessages` 另有请求级 token 预算裁剪(整条优先丢弃、仅剩单条保护消息时兜底截断)。
  - 事件提示词条目支持 `eventType`/`raw` 字段（`addSystemUserMessage` 第三参传入）:`eventType` 供事件过滤,`raw` 为事件原始数据、不参与渲染、仅由 read_raw kind=event 读取,随所在消息清理/归档失效,不设条数与长度上限。
  - 工具回调消息支持 `rawText`（`addToolCallbackMessage` 在超长截断时保留截断前完整原文）;用户消息条目在压缩替换时保留 `rawText`（单条）/`rawItems`（连续多条合并压缩块）;均不参与渲染与 token 估算,随所在消息清理/归档失效;由 `grep_raw`/`read_raw` 按 kind 只读检索。
  - `getUserById` / `getGroupById`:仅按用户ID或群ID获取目标，不执行名称搜索。
  - `findImage`:支持 `user_avatar`、`group_avatar`、图片 ID、本地图片路径、记忆内图片。
  - `setName`/`updateName`:按 `autoNameMod`(0/1/2)自动把名字改为昵称或群名片。

## 记忆(src/memory/)

- `session_memory.ts`:`SessionMemoryService` 会话记忆门面:只包装 Hindsight-like 新引擎(不再使用旧 MemoryService/MemoryItem),提供 `retainMemory`/`recallMemory`/`deleteMemory`/`clearMemory`/`buildObservationPrompt` 等,保留 `validKeysMap` 与兼容方法以平滑读旧存档。
- `revision.ts`:记忆/观察缓存失效:`bumpMemoryRevision()` / `bumpSummaryRevision()` 自增全局版本号并主动失效对应 prompt 缓存(一次总结可能写入多个会话,统一全量失效)。
- `session_target.ts`:`resolveTargetSession()` 按「当前会话所属 agent」的 sessionService 定位私聊/群聊目标会话,避免写入与检索落到不同 agent 的会话空间。
- `knowledge_chunk.ts`:`splitMarkdownIntoChunks()` 按 `#`/`##`/`###` 标题与段落把 Markdown 文档切块(单块约 800 字符、块间保留重叠),生成稳定 ID(`kb_xxxxxxxx`)。
- `knowledge_base.ts`:`KnowledgeBaseService` 单例,配置驱动(Markdown 模板,每条一份完整文档),解析时不出向量(懒向量);`search()` 先关键词过滤,嵌入可用时仅对命中候选(≤20 块)做惰性向量重排,失败自动降级关键词;`buildKnowledgePrompt()` 只展示条目索引:ID + 标题,1500 字符预算内尽可能多列(≤100 条),不注入正文,详情由模型用 `knowledge_read` 按 ID 读取;`formatIndex(limit)` 支持索引条数上限。
- `knowledge.ts`:兼容导出层,`knowledgeService = knowledgeBase`(旧 `KnowledgeService` 已移除)。
- `manager.ts`:`MemoryManager` 统一入口:`buildLongTermPrompt`(心智模型 + 长期记忆混合注入,群聊按「群聊 / 最近发言者」分组)、`buildObservationPrompt` / `buildKnowledgePrompt`、`retainMemory` / `recallMemory` / `consolidateMemory` / `reflectMemory`、`summarizeChunk` / `summarizeChunkWithRetry`(上下文 token 超限归档:把将删除的消息块交给 `summarize_agent` 抽取 facts → 写入长期记忆 → consolidate 为观察记忆,最多重试 3 次)、`migrateLegacyPersona`(旧 persona 懒迁移为心智模型并清空)。
- `v2/`(4.17.0 起):Hindsight-like 纯 TS 记忆引擎。`engine.ts` 实现 Retain(抽取原子事实/观察记忆,可选 LLM 结构化抽取 occurred_at/entities)、Recall(RRF 混合检索 + Hindsight 式新近度加权(按 lastAccessedAt 指数衰减,权重/半衰期可配)+ 可选 LLM 重排)、Consolidation(LLM 合成观察记忆、合并重复、清理 90 天过期观察)、MentalModel(心智模型:question/answer/scopeTags/status/lastRefreshedAt/history/trigger,支持 refresh/delete、persona 懒迁移)、固定模板(`templates.ts` 按场景写死「设定/偏好/规则」问题,`ensureDefaultMentalModels` 按 `seededMentalModelVersion` 版本化播种:升级只增量补新、删除不复活;固定模板优先注入、语义召回补余)、遗忘机制(长期记忆条数上限,默认 100,0=不限制;retain/consolidate 后超限时按「已被观察覆盖 → 普通按衰减分 → observation 沉淀 → 保护项(importance≥0.9 或 pinned)」优先级物理删除多余记忆,上限为硬约束);`repository.ts` 统一存取长期/观察记忆与心智模型,`bank_resolver.ts` 按会话解析记忆库(私聊 `user_<id>` / 群聊 `group_<gid>`),`migrate.ts` 负责旧格式(memoryMap/summaries/persona)自动迁移,`llm.ts` 提供可选的 LLM 抽取/重排/合成/推理回调,`prompt.ts` 负责注入裁剪(scopeTags 任一命中过滤、心智模型只注入 ready、观察按 lastVerifiedAt 剔除 90 天过期)与分组渲染(`buildGroupedMemoryPrompt`:每组段头标注会话身份与证据范围——群聊/个人 + 群号/ID(含名称),reflect 提示词开头注入会话范围行)。`manager.ts buildLongTermPrompt` 在群聊时除群记忆库外,还会并入最近发言者(最多 3 人)的个人记忆库并分组渲染:群回忆 ≤20、群心智模型 ≤3(固定优先),每个发言者个人回忆 ≤20 条且单用户 2048 字符预算、个人心智模型 ≤2(固定模板 ≤1),观察记忆由 `buildObservationPrompt` 独立注入(≤20 条、90 天过期剔除),私有记忆仅创建者本人可见;查询向量每轮只算一次,复用于群聊与各发言者个人库。配套记忆工具为 `memory_*` 系列(增删改查/巩固/推理/心智模型,含 `memory_mm_list/view` 查看心智模型、`memory_mm_delete` 可按 model_id 或 question 删除),`.ai memo` 子命令重构为 status/add/list/update/delete/clear/obs/consolidate/reflect/mm,范围参数改用 `--u`/`--g`。

## 智能体(src/agent/)

- `agent.ts`:
  - `Agent` 字段:name、description、instruction(可为函数)、use、sessionService、tools、subAgents。
  - `Agent.get(name)` / `Agent.save(agent)`:从 `agent_<name>` 存储复活/保存。
  - `chat(prompt)`:直接发起一次单轮对话(压缩/摘要智能体使用)。
  - `run()`:完整编排循环——组装消息 → 请求 → 工具执行(函数调用或提示词工程)→ 复读检测重试 → 最终回复。
  - `runStream()`:流式编排,轮询后端流,检测 ```function 代码块截断,执行工具后递归续流。
  - `.ai stop` 中止机制:run/runStream 启动时捕获 `session.stopVersion` 并通过代际检查;stop 时 `fireStopEvent` 置位会话级 `stopEvent`(StopEvent)并同步唤醒所有 `withTimeout`/`requestModel` 等待者(以 StopError reject),同时归零 `activeRuns`/`running`、清空挂起队列与待触发计时器;StopError 不算工具失败回填,消息组装/请求返回/工具执行后/最终回复前均设检查点,检测到版本变化或 StopEvent 即中止;goja 无 AbortController,底层 fetch 无法硬中断,但返回结果会被丢弃。并发队列中该会话的等待项由 `requestLimiter.cancelBySession` 丢弃。
  - 挂起队列机制:会话运行(或正在启动)时收到的新消息经 `session.deferReceipt` 进入 `pendingQueue` 挂起,`run/runStream` 每轮模型请求前 `flushPending` 统一入库(此时上一轮工具回调已写入上下文,插入位置合法);记录类只入库不续跑,触发类在链结束后由 `resumePending` 用第一条触发消息串行再起一轮;`.ai stop` 清空挂起队列并自增 `stopVersion`,停止后不复活。
- `run_context.ts`:`AgentRunContext` 记录单次 run 的观测信息(runId/轮次/工具调用事件/耗时)。
- `api.ts`:对外 API,启动时挂载 `globalThis.aiplugin4`(智能体调用 `chat`/`run`/`getAgent` 与工具注册 `registerTool`),供其他海豹插件使用。
- `agents/`:包含 `compress_agent`(压缩)、`summarize_agent`(摘要/上下文归档总结);`samples.ts` 的 `sample_agent` 仅作参考,不在 `initAgents` 中初始化。

## 命令系统(src/cmd/)

- `root_cmd.ts`:注册根命令 `.ai`(注册到 `cmdMap['ai']` 与 `cmdMap['AI']`),别名经 `aliasToCmd` 归一;子命令统一分发,兜住异步异常并回复错误;支持 `--page`/`--p` 翻页。
- `privilege.ts`:命令权限系统,`CmdPrivInfo { priv: [会话权限, 用户权限, 强触权限] }`,预置 `U`(user)/`M`(master)/`I`(inviter)/`S`(会话需 inviter,否则骰主);`PrivilegeManager` 管理 `cmdPriv` 存储与校验,支持 `*` 通配。
- `sub_cmd/`:21 个文件,其中 20 个注册到根命令,`sample.ts` 未注册(仅开发参考),详见 [05-命令与配置](05-命令与配置.md)。

## 定时器(src/timer.ts)

- `TimerInfo`:sid/isPrivate/epId/set/target/interval/count/type/content;type 分 `target`(目标时间)、`interval`(间隔)、`activeTime`(活跃时间)。
- `TimerManager`:队列持久化到 `timerQueue`;`executeTask()` 每 5 秒扫一轮,每个定时器执行间隔 2 秒;超过目标时间 1 小时未执行则忽略;触发时注入系统用户消息并调用 `session.chat`。

## 用量统计(src/usage.ts)

- `UsageManager`:按模型按天(`Y-M-D`)累计 prompt/completion token,持久化到 `usageMap`;过期数据归并(30 天前 → `Y-M-0`,11 个月前 → `0-0-0`)。
- `get_chart_url()`:把用量数据 POST 给用量图表后端 `/chart`,返回图片 URL。

## 日志(src/logger.ts)

- 输出格式:`【AI骰娘4】[级别短标签] [模块标签] 内容`。级别短标签为 ERROR/WARN/INFO/DEBUG,与海豹面板日志级别/颜色对应,便于按级别过滤。
- 模块标签:通过 `logger.withTag('模块名')` 得到带标签的日志对象,已覆盖 agent/model/pipeline/timer/send/ob11/context/image 等核心链路;全局 `logger` 仍可用。
- 级别:从不/错误/警告/信息/调试,由 `日志级别` 配置控制。
- 单条截断 2000 字符;`日志简短打印` 时首尾各保留 500 字符;`logLong()` 超长文本按片打印并标注 `[第x段/总段数]`。
- 密钥脱敏:`api_key`/`token`/`authorization`/`secret`/`password`/`app_secret`/`appkey` 字段、URL query 中的同名参数、`Bearer xxx`、`sk-` 前缀密钥、access/refresh token。
- `exception()` 错误进 error、堆栈进 debug;`printRequestMessages()` 默认只打 `[请求上下文] run=... 共N条` 摘要,逐条 role/长度/toolCalls 与正文进 debug(正文受 `日志记录消息内容` 开关控制,截断 300 字符,默认不打印 system)。
