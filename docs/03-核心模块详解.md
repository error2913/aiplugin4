# 03 - 核心模块详解

> 本章按目录逐模块说明职责与关键类型。代码路径均相对仓库根目录 `src/`。

## 入口与装配(src/index.ts)

- 注册 Handlebars Helper:`index`(从 1 开始)、`json_stringify`、`time`。
- 依次初始化:`Config.registerConfig()`、`initAgents()`、`checkUpdate()`、`Tool.registerTool()`、`TimerManager.init()`、`knowledgeService.init()`、`registerCmd()`、`PrivilegeManager.reviveCmdPriv()`。
- 写入存储版本标记 `storage_version`(当前 `STORAGE_VERSION = 1`,结构变更时递增)。
- 绑定四个 SealDice 事件:`onPoke`、`onNotCommandReceived`、`onCommandReceived`、`onMessageSend`,全部委托给 `MessagePipeline`。

## 消息管线(src/pipeline.ts)

`MessagePipeline` 是唯一的事件处理入口:

- `handleNonCommand(ctx, msg)`:执行忽略/触发判定,见 [02-架构设计](02-架构设计.md)。
- `handleCommand(ctx, msg, cmdArgs)`:记录 `Tool.cmdArgs`;可选录入上下文。
- `handleBotMessage(ctx, msg)`:转发给工具监听;可选录入上下文。
- 会话统一通过 `getSession(sid)` 获取;`sid` 私聊为用户 ID、群聊为群 ID。
- CQ 码白名单 `CQ_TYPES_ALLOW = ["at","image","reply","face","poke"]`,含白名单之外 CQ 类型的消息不处理。

## 配置(src/config/)

### config.ts

- 通过 `seal.ext.find/new/register` 创建扩展实例 `ext`(插件名 `aiplugin4`)。
- `configMap` 集中登记 11 个配置分组:base、model、message、received、trigger、reply、tool、memory、image、backend、resource。
- 每个分组由 `register()`(向 SealDice 注册配置项)与 `get()`(读取并返回类型化对象)构成。
- 读取带缓存:`CONFIG_CACHE_TTL = 60000` 毫秒,`Object.defineProperty` 把 `Config.<分组>` 变为缓存 getter;`ModelConfig.get()` 在注册时预热并同步模型静态列表。
- `getRegexConfig()`:把模板配置的多行正则拼接为单个 `RegExp`,失败时返回永不匹配的 `/(?!)/`。

### static_config/(静态常量)

- `VERSION`(当前 4.15.0)、`AUTHOR`、`NAME`、`STORAGE_VERSION`、`CONFIG_CACHE_TTL`、`CQ_TYPES_ALLOW`。
- `PRIVILEGE_LEVEL_MAP`:master=100 / whitelist=70 / owner=60 / admin=50 / inviter=40 / user=0 / blacklist=-30。
- `HELP_MAP`、`ALIAS_MAP`(命令别名表)、`FACE_MAP`(QQ 表情编号 → 名称)。
- `PROVIDER_MAP`:10 家厂商的 OpenAI 兼容 base_url。
- `CHAT_MODEL_MAP` / `IMAGE_MODEL_MAP` / `EMBEDDING_MODEL_MAP` 及反向映射:模型名 → 提供商自动识别。
- `DEFAULT_CHAT_MODEL_BODY` / `DEFAULT_IMAGE_MODEL_BODY` / `DEFAULT_EMBEDDING_MODEL_BODY`:默认请求体兜底。
- 按类别拆分为 `meta.ts`(版本/作者/插件名/缓存 TTL/存储版本)、`cq.ts`、`permission.ts`、`help.ts`、`alias.ts`、`face.ts`、`providers.ts`(厂商与模型映射)、`model_defaults.ts`、`memory.ts`(记忆检索内置常量),由 `index.ts` 统一 re-export,历史导入路径 `../config/static_config` 保持不变。

### configs/(11 个分组)

| 文件 | 分组 | 主要配置项 |
| --- | --- | --- |
| `base.ts` | 基础 | 日志级别/简短打印/记录消息内容、请求超时、请求并发/队列限制、海豹核心路径、全局待机 |
| `model.ts` | 模型 | 对话/图片/嵌入模型(TOML),解析后同步 `Model` 静态列表 |
| `backend.ts` | 后端 | 流式输出、图片转 base64、联网搜索、用量图表、论坛 URL/token；网页读取与 md/html 渲染（MCP）已移入「工具 → MCP服务器配置」 |
| `received.ts` | 消息接收 | 接收图片/指令/骰子消息、忽略私聊、忽略豹语条件、忽略正则 |
| `trigger.ts` | 消息触发 | 默认计数器/计时器/概率/活跃时间、向量相似度、触发正则、触发条件、令牌桶 |
| `image.ts` | 图片 | 图片识别条件、URL 转 base64、识别 prompt |
| `tool.ts` | 工具 | 函数调用开关、提示词工程、连续调用次数(0=不限制)、禁止/默认关闭函数、牌堆、MCP(仅 JSON)、技能(仅标准 SKILL.md)、音色 |
| `memory.ts` | 记忆 | 长期/总结/知识库开关、总结上限/间隔/参与轮数、短期记忆上限、知识库注入阈值、知识库(Markdown 模板) |
| `reply.ts` | 回复 | 引用(含戳戳跳过)、最大字数、去空白、禁止复读与相似度、过滤正则与模板 |
| `message.ts` | 对话 | 角色扮演设定(每条第一行为名称,以 `.` 开头隐藏)、示例对话、轮数、token 上限、system 插入间隔、压缩阈值 |
| `resource.ts` | 资源 | 本地图片路径、本地语音路径(`语音名=路径`,供 system prompt 列出资源) |

注意:本地图片/语音路径由资源分组统一注册;图片发送与 system prompt 资源列表读取同一份配置(本地语音路径支持 `语音名=路径`,省略语音名时用文件名)。

### prompt 模板(src/prompt/templates.ts)

模板在代码中以 `TEMPLATES` 常量内置(不再注册为配置项,避免误改导致渲染损坏),读取时 `compileTemplate` 编译,仅在编译失败时回退空函数;渲染期异常不兜底,由调用方处理。模板清单:

- `system prompt模板`
- `长期记忆prompt模板`
- `总结记忆prompt模板`
- `工具函数prompt模板`
- `图片识别prompt模板`
- `记忆总结prompt模板`

## 模型层(src/model/)

- `model.ts`:`Model` 静态注册表(chatModels/imageModels/embeddingModels),`getChatModel(use, name)` 按"会话指定名称 → 用途 → 任意用途"确定性选择(按名称解析时也会在图片模型列表中查找,use=chat 的图片模型可作多模态对话模型),图片/嵌入模型按用途随机选择;`reset()` 供测试/热重载。
- `chat.ts`:`ChatModel` 请求 `{baseUrl}/chat/completions`(anthropic 走 `/messages`,由 `adapter.ts` 转换),解析 `choices[0].message`、`tool_calls`、`reasoning_content`。
- `image.ts`:`ImageModel` 用于图片理解(`callITT`,图片 + prompt)与图片对话(`callChat`)。
- `embedding.ts`:`EmbeddingModel` 请求 `{baseUrl}/embeddings`,带单条文本向量缓存。
- `provider.ts`:`requestModel()` 统一请求入口:超时(`TIMEOUT`)、失败重试(最多 2 次,4xx 不重试,指数退避)、成功时上报 token 用量;`adapter.ts` 按提供商转换请求/响应格式(当前支持 anthropic)。
- `types.ts`:用途类型 `ChatModelUse('chat'|'compression'|'summarization')`、`ImageModelUse`、`EmbeddingModelUse('text-embedding')`。

## 请求服务(src/agent/stream.ts)

- `sendChatRequest()`:非流式对话,函数调用模式(`STATUS && !PROMPT_ENGINEERING`)下注入 `tools`/`tool_choice`,统计用量。
- `startStream()/pollStream()/endStream()`:把模型配置(URL/Key/body)发给后端流式输出服务中转,按 `id` 轮询增量结果。

## 会话(src/session/)

- `session.ts`:
  - `Setting`:priv、standby、regexTrigger、counter、timer、prob、modelName、activeTimeInfo(start/end/segs)。
  - `Session`:agentName、sessionId、sessionType、state、context、memory、setting、stream、bucket、tool(state/callCount/listen)、lastCtx(不持久化)。
  - `toolState` getter:按 `BLOCKED` 与 `DEFAULT_CLOSED` 同步每会话工具开关,并清理已删除工具的残留状态。
  - `chat()`:配额检查 → 重置 → 流式判断 → `Agent.run/runStream` → `save()`。
  - `reply()`:逐段发送并写入上下文。
  - 活跃时间:把时间段切分为 `segs` 段,`checkActiveTimer` 用 `TimerManager` 安排下一次触发。
- `session_service.ts`:`getSession(sid)` 从存储复活会话(经 `revive`),`SessionService` 持有 `sessionMap` 与全局 `memory`。
- `group.ts` / `user.ts`:群档案(角色/群主/管理员/成员/忽略名单)与用户档案(名称)。
- `types.ts`:`SessionType('group'|'user')`、`State`、`GroupInfo`、`UserInfo`。

## 上下文(src/context/)

- `types.ts`:消息类型定义:`UserMessageItem`、`SystemUserMessageItem`、`AssistantMessageItem`、`ToolCallsMessage`、`ToolCallbackMessage`、`RequestMessage`。
- `message.ts`:`Message` 静态方法判断消息类型;`handleMessages` 把内部消息转为 API 请求格式,元数据(时间/用户/消息ID/系统来源)存在消息项字段中,多模态模式下把 `[img:...]` 等图片标签转成 `image_url` 内容块直接传给模型。
- `context.ts`:`Context` 类:
  - 添加用户消息(自动改名、超长消息交给 `compress_agent` 压缩)、助手消息(触发记忆访问与总结检查)、系统用户消息、工具调用/回调消息。
  - `limitMessages()` 按 `MAX_ROUNDS`(出现一次 user 视作一轮)裁剪;`handleMessages` 另有 token 预算裁剪。
  - `findUserId` / `findGroupId`:按 ID、名字(编辑距离容错)、上下文/记忆、群成员/好友列表解析用户与群。
  - `findImage`:支持 `user_avatar`、`group_avatar`、图片 ID、本地图片路径、记忆内图片。
  - `setName`/`updateName`:按 `autoNameMod`(0/1/2)自动把名字改为昵称或群名片。

## 记忆(src/memory/)

- `memory_item.ts`:`MemoryItem` 包含内容、向量、标签、关联记忆、用户、群组与权重。评分模型:
  - `decay`:新鲜度衰减(年龄半衰期 7 天占 0.7,活跃半衰期 4 小时占 0.3)。
  - `calculateSimilarity`:向量 0.4 + 用户 0.2 + 群组 0.2 + 标签 0.2,按参与维度加权归一。
  - `calculateScore`:重要性 0.2 + 访问分 0.2 + 相似度 0.6。
  - `updateVector()`:调用嵌入模型生成向量,维度取自嵌入模型配置 `[body] dimensions`(默认 1024),未配置时自动降级为关键词/分数检索。
- `memory.ts`:`MemoryService` 提供 `memoryMap` 增删改查、`search()`(方法:importance/similarity/score/early/late/recent)、去重合并、按分数淘汰;内含旧格式迁移逻辑(兼容早期 `src/AI/memory.ts` 存档)。
- `session_memory.ts`:`SessionMemoryService` 提供会话级记忆与短期记忆:`summarize()` 把最近 `SUMMARY_SIZE` 轮对话交给 `summarize_agent`,解析 JSON 摘要与记忆列表,写入 `shortMemoryList`/`summaries` 并落库。
- `knowledge_chunk.ts`:`splitMarkdownIntoChunks()` 按 `#`/`##`/`###` 标题与段落把 Markdown 文档切块(单块约 800 字符、块间保留重叠),生成稳定 ID(`kb_xxxxxxxx`)。
- `knowledge_base.ts`:`KnowledgeBaseService` 单例,配置驱动(Markdown 模板,每条一份完整文档),解析时不出向量(懒向量);`search()` 先关键词过滤,嵌入可用时仅对命中候选(≤20 块)做惰性向量重排,失败自动降级关键词;`buildKnowledgePrompt()` 总内容 ≤ 注入阈值(默认 5000)时全量注入,否则只注入条目索引。
- `knowledge.ts`:兼容导出层,`knowledgeService = knowledgeBase`(旧 `KnowledgeService` 已移除)。
- `manager.ts`:`MemoryManager` 统一入口:`buildLongTermPrompt` / `buildSummaryPrompt` / `buildKnowledgePrompt` / `addMemory` / `search` / `summarize`。

## 智能体(src/agent/)

- `agent.ts`:
  - `Agent` 字段:name、description、instruction(可为函数)、use、sessionService、tools、subAgents。
  - `Agent.get(name)` / `Agent.save(agent)`:从 `agent_<name>` 存储复活/保存。
  - `chat(prompt)`:直接发起一次单轮对话(压缩/摘要智能体使用)。
  - `run()`:完整编排循环——组装消息 → 请求 → 工具执行(函数调用或提示词工程)→ 复读检测重试 → 最终回复。
  - `runStream()`:流式编排,轮询后端流,检测 ```function 代码块截断,执行工具后递归续流。
- `run_context.ts`:`AgentRunContext` 记录单次 run 的观测信息(runId/轮次/工具调用事件/耗时)。
- `api.ts`:对外 API,启动时挂载 `globalThis.aiplugin4`(智能体调用 `chat`/`run`/`getAgent` 与工具注册 `registerTool`),供其他海豹插件使用。
- `agents/`:包含 `compress_agent`(压缩)、`summarize_agent`(摘要);`samples.ts` 的 `sample_agent` 仅作参考,不在 `initAgents` 中初始化。

## 命令系统(src/cmd/)

- `root_cmd.ts`:注册根命令 `.ai`(注册到 `cmdMap['ai']` 与 `cmdMap['AI']`),别名经 `aliasToCmd` 归一;子命令统一分发,兜住异步异常并回复错误;支持 `--page`/`--p` 翻页。
- `privilege.ts`:命令权限系统,`CmdPrivInfo { priv: [会话权限, 用户权限, 强触权限] }`,预置 `U`(user)/`M`(master)/`I`(inviter)/`S`(会话需 inviter,否则骰主);`PrivilegeManager` 管理 `cmdPriv` 存储与校验,支持 `*` 通配。
- `sub_cmd/`:17 个文件,其中 16 个注册到根命令,`sample.ts` 未注册(仅开发参考),详见 [05-命令与配置](05-命令与配置.md)。

## 定时器(src/timer.ts)

- `TimerInfo`:sid/isPrivate/epId/set/target/interval/count/type/content;type 分 `target`(目标时间)、`interval`(间隔)、`activeTime`(活跃时间)。
- `TimerManager`:队列持久化到 `timerQueue`;`executeTask()` 每 5 秒扫一轮,每个定时器执行间隔 2 秒;超过目标时间 1 小时未执行则忽略;触发时注入系统用户消息并调用 `session.chat`。

## 用量统计(src/usage.ts)

- `UsageManager`:按模型按天(`Y-M-D`)累计 prompt/completion token,持久化到 `usageMap`;过期数据归并(30 天前 → `Y-M-0`,11 个月前 → `0-0-0`)。
- `get_chart_url()`:把用量数据 POST 给用量图表后端 `/chart`,返回图片 URL。

## 日志(src/logger.ts)

- 级别:从不/错误/警告/信息/调试,由 `日志级别` 配置控制。
- 单条截断 2000 字符;`日志简短打印` 时首尾各保留 500 字符。
- 密钥脱敏:`api_key`/`token`/`authorization`/`secret`/`password`/`Bearer xxx`。
- `exception()` 错误进 error、堆栈进 debug;`printRequestMessages()` 受 `日志记录消息内容` 控制,正文截断 300 字符,默认不打印 system。

- `Image`:图片对象(url/local/base64 三种来源),提供 `CQCode`、`urlToBase64`、`imageToText`;全局 `imageMap` 缓存与 `save`。
- 头像:`getUserAvatar` / `getGroupAvatar`(经 ob11 获取头像 URL)。
